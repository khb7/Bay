> 조사 기간: 2026-09-04 ~
> 엔진: Unreal Engine 5

## 목표

언리얼에서 파도가 치는 모래사장을 만든다. **주력은 모래성 쌓기**이고,
물과 모래가 만났을 때의 그 특유의 흐르는 거동을 표현하는 것이 핵심이다.

## 조사 결론 요약

### 정확도 ↔ 속도의 스펙트럼

```
정확 ─────────────────────────────────────────────── 빠름
  MPM 2상 (Tampubolon 2017)   PBD 입자 (Macklin 2014)   하이트필드 침식 (Mei 2007)
  프레임당 수십 초~분          실시간, 수십만 입자        실시간, 4K 격자 여유
  물리적으로 옳음              그럴듯함                   2D, 오버행 불가
```

**결정: 하이브리드.** MPM 논문(1·2번)은 직접 구현하지 않고 **물리적 근거와 파라미터 곡선의 출처**로만 사용한다.

### 핵심 통찰

**모든 것을 수분량 `W` 하나가 구동한다.**

```
              ┌─→ talusAngle       (하이트필드 붕괴각)
              ├─→ cohesion         (입자 응집력)
   W (수분) ──┼─→ albedo/roughness (렌더링: 젖으면 어둡고 반질)
              ├─→ 붕괴 임계값       (게임플레이)
              └─→ 침식 저항         (파도에 깎이는 속도)
```

- **연속체 논문의 "포화도 → 항복면 이동"** 과
- **하이트필드의 "젖음 → 안식각 상승"** 은 **같은 아이디어**이고, 후자가 1/1000 비용.
- 강도 곡선의 형태는 Pakpour 2012 + Scheel 2008 참조. **왼쪽(건조) 절벽이 가파르고 중간은 넓은 고원.**
  → 마르는 모래성은 서서히 약해지는 게 아니라 **버티다 갑자기 무너진다.**

### 논문 공백

**증발/건조를 다루는 그래픽스 논문은 없다.** 토양물리학의 2단계 증발 모델을 직접 이식해야 한다.
이 부분이 이 프로젝트의 고유 메커니즘이 될 가능성이 크다.

## ★★ 이 프로젝트의 목적과 설계 원칙

> **목적: 실제 해변에서 모래성을 쌓는 것 자체의 구현.**
> 최대한 시뮬레이션으로 가고, **안 되는 부분만 명시적으로 타협한다.**

### 판단 기준 하나

```
`if (조건) then 결과` 를 쓸 때마다 충실도가 깎인다.
국소 물리 규칙에서 나오면 충실도가 쌓인다.
```

**창발을 최대화하고 규칙을 최소화한다.** 새 기능을 넣을 때마다 이걸로 점검한다.

| 거동 | 창발인가 | 비고 |
|---|---|---|
| 모래성이 무너짐 | ✓ | 입자 + cohesion |
| 연쇄 붕괴 | ✓ | 입자면 자동 / 하이트필드는 하중 전파(J-10) |
| 전도 | ✓ | 입자면 자동 (동역학) |
| 아치가 버팀 | ✓ | 압축 전달이 저절로 |
| 크기 효과 | ✓ | 자기 무게가 실제로 작용하므로 |
| 마르면 약해짐 | ✓ | `W → cohesion` |
| 파도가 깎음 | △ | 운반 공식은 경험식 (타협 5) |
| 지하수면 | △ | 해석식. 단 물리적으로 유도된 식 |
| **소리 (반응층)** | ✓ | 절차적. 시뮬 상태가 그대로 구동 (M절) |
| 소리 (기반층) | ✗ | 샘플 루프. **분위기라 물리와 무관해도 무해** |
| **안전율 경고** | ✗ | **UI 전용이면 무해** — 물리에 되먹임 금지 |

### 무엇이 진실이고 무엇이 지표인가

```
진실 = 시뮬레이션 ([B] 입자 동역학, [A]의 하중 전파)
지표 = 그걸 읽어서 만드는 예측.  판정을 대신하면 안 된다

지표 = 계기판. 엔진이 아니다. 계기판이 틀려도 차는 정상 동작한다.
```
실제 해변엔 안전율 표시가 없다 — **안 보여주는 선택지도 있다.**
예고는 지어내지 말고 **실제 전조**(균열, 작은 흘러내림, 마름 색변화)를 드러낸다.
근거는 [papers.md J-9](papers.md).

## 시스템 설계 (초안)

### 3계층 구조

```
[A] 해변 전체 — 하이트필드 GPU 시뮬  (수십~수백 m)
     상태: b(지형) d(물깊이) s(뜬모래) f(4방향 유량) v(속도) W(수분)
     구현: Niagara Grid2D + Simulation Stages, 결과를 Render Target으로 export
     지형: 테셀레이션 평면 + WPO, 또는 Virtual Heightfield Mesh

[B] 모래성 — XPBD 입자  ★ 조건부가 아니라 상시
     입자 + 접촉 마찰 + cohesion(W로 구동)
     플레이어가 쌓는 것은 처음부터 끝까지 입자. 하이트필드로 되돌리지 않는다
     → 붕괴 판정이 100% 물리 안에 있음
     → [A]↔[B] 강도 불일치 문제가 아예 없음 (전환이 없으므로)
     비용: 반지름 2.5cm(지름 5cm), 성 한 채 3천~2만, 총 예산 30만 → 성 10채 누적 여유
     (이전 5mm 안은 폐기 — 해상도를 낮추면 8배라 "성이 여러 채 남는다"가 깨진다.
      확정값은 design/system-design.md §2)

[C] 물 표면 렌더링
     원해: Gerstner / FFT (UE5 Water)
     근안: [A]의 d, v, s 로 합성 (탁도, 플로우맵, 포말)

[D] 소리 — 하이브리드 (papers.md M절)
     기반층 = 샘플 루프    먼 파도, 분위기        ← 사실성
     반응층 = 절차적       쇄파, 모래, 붕괴, 물   ← 시뮬 연동
     구현: UE5 MetaSounds
     ★ 쇄파 유형 ξ가 소리를 가른다 (spilling/plunging/surging) — 이미 계산 중인 값
     ★ 모래 소리는 W가 구동 (젖으면 둔탁) — granular synthesis
```

### [A] 패스 순서 (한 스텝)

```
1. 파도 주입      바다쪽 경계 셀의 수면 높이를 파형 함수로 강제
2. 가상 파이프    f += dt·A·g·Δh/l  →  K로 클램프  →  d 갱신  →  v 산출
3. 침식/퇴적      C = Kc · max(sinα, minSlope) · |v|
                  C > s → 깎음(b↓ s↑) / C < s → 쌓음(b↑ s↓)
4. 모래 이류      s를 v 따라 반라그랑주 이동
5. 수분 W         침투 ← d / 배수(>field capacity) / 증발(2단계) / 모세관 확산
6. 지하수면       waterTable(x,t) 아래 셀은 W=1 강제
7. 열침식         이웃 경사 > talus(W) 이면 아래로 이동
8. 하중 전파      load 누적 → capacity 초과 시 항복 + 이웃으로 재분배  ← 연쇄 붕괴 (J-10)
9. rainsplash    b += D·∇²b − 경사편향.  D ∝ rainRate·exp(−d/2mm)·(1−점착)
                 ← 빗방울 충격의 연속체 극한 = 확산. 비 안 오면 스킵 (params §4a)
```

> 8은 지표가 아니라 **물리**다. 국소 상호작용이라 연쇄가 창발한다.
> 이게 있어야 [A]에서도 "버티다가 갑자기" 무너진다.

### 증발은 2단계

```
1단계 (등속): 모세관이 표면까지 공급 가능 → 속도는 햇빛·바람이 결정
2단계 (감속): 건조 전선이 후퇴 → 마른 껍질을 통한 수증기 확산 → rate ∝ 1/두께

전환 조건: 건조 전선 깊이 > 특성 길이 L_C   (모래는 L_C가 짧음, 수 cm)
```

이 모델에서 **저절로 나오는 것들**:
- 양지쪽 벽이 먼저 무너짐 (증발률이 법선·그림자 의존)
- 첨탑이 기단보다 먼저 감 (표면적/부피 비 → 얇은 건 껍질이 관통)
- 겉은 뽀얗고 속은 짙은 모래성 (건조 전선이 안으로 자람)

### 지하수면(water table)

```
                     ┌── 상부: 불포화. 물이 스며듦(influent)
                     │    → 백워시 약함 → 모래 쌓임 (accretion)
   ─ ─ ─ exit point ─┤
                     └── 하부: 포화. 물이 배어나옴(effluent)
                          → 백워시 강함 → 모래 깎임 (erosion)
```

- **시뮬레이션이 필요 없다.** 감쇠 진행파의 닫힌 해로 충분 (papers.md F1):
  `h(x,t) = h_mean + A·exp(−x/L)·sin(ωt − x/L)`, `L = √(2KD/nω)`
- **감쇠 길이 L ≈ 5~30 m.** 조석 영향 도달 범위 = 플레이 영역의 자연스러운 스케일.
  `x = L`에서 지하수면 최고점이 만조보다 **약 2시간 늦게** 온다.
- 지하수면은 평균 해수면보다 **높다**(super-elevation). 밀물에 빠르게 차고 썰물에 천천히 빠지는 비대칭 때문.
  선형해는 대칭이라 이걸 못 내므로 **오프셋 항으로 더한다.**
- 지하수면 위 수십 cm는 **모세관 상승대(capillary fringe)** 로 여전히 젖어 있다.
- **입도 결정: 중립~조립사, `d = 0.4 ~ 0.6 mm`** (일반적인 모래사장은 세립~중립 0.2~0.4mm이므로
  약간 굵은 쪽). 근거는 아래 "입도" 절.
- **게임 함의**: 조석에 따라 exit point가 이동 → 모래성을 어디에 짓느냐가 안정성을 결정.
  낮은 곳 = 항상 최적 수분이지만 파도에 깎임 / 높은 곳 = 안전하지만 마름.
  E절(마름 압박)과 정확히 **반대 방향으로 당기는 힘**이라 균형이 잡힌다.

### 입도 (grain size)

**결정: `d = 0.4 ~ 0.6 mm` (중립~조립사).**

| 등급 | 지름 | K (m/s) | 감각 |
|---|---|---|---|
| 극조립사 | 1 – 2 mm | 10⁻³ ~ 10⁻² | 굵은 설탕. 서걱거림 |
| 조립사 | 0.5 – 1 mm | 5×10⁻⁴ ~ 10⁻³ | 알갱이가 하나씩 보임 |
| **중립사** ← 여기 | **0.25 – 0.5 mm** | **10⁻⁴ ~ 10⁻³** | 고운 설탕 / 굵은 소금 |
| 세립사 | 0.125 – 0.25 mm | 10⁻⁵ ~ 10⁻⁴ | 알갱이 구분 어려움. 매끈 |
| 극세립사 | 0.0625 – 0.125 mm | 10⁻⁶ ~ 10⁻⁵ | 밀가루 직전 |
| 실트 | < 0.0625 mm | 10⁻⁷ ~ | 밀가루. 갯벌 |

**입도가 모든 물성을 서로 반대 방향으로 당긴다**

```
              고움 ←────────────────────→ 굵음
 모래성 강도    강함  (σ ∝ 1/d)            약함
 풍성 이동      잘 날림 (u*t ∝ √d)          거의 안 날림
 배수/건조      느림  (K ∝ d²)             빠름
 침투 침식효과  없음                       강함
 지하수면 폭 L  2 m   (L ∝ √K)             10 m
 해변 경사      완만 (dissipative)          가파름 (reflective)
```
**모래성 강도와 풍성 이동이 고운 쪽, 나머지가 굵은 쪽을 원한다.**
→ 해결책은 **구역별 입도**(papers.md H-6). 실제 해변도 그렇다 —
스텝이 가장 굵고 후빈이 가장 곱다. `grainSize`를 상수가 아니라 **필드**로 둘 것.

> 인장 강도가 `1/d`인 이유: 모세관 다리 하나의 힘 ∝ R, 단위면적당 접촉 개수 ∝ 1/R²
> → σ ∝ (1/R²)·R = 1/R. **입도 절반이면 강도 2배.**
> 모래성 대회 선수들이 해변 모래 대신 고운 강모래·석산 모래를 쓰는 이유.

**0.4~0.6mm를 고른 이유**
1. 실제 해변으로 자연스러움 (조금 굵은 편의 흔한 모래사장)
2. `K ≈ 3×10⁻⁴ ~ 10⁻³` → swash 한 주기(5s)에 **1.5~5 mm 침투**.
   swash 수막 10~50mm 대비 **부피의 3~15% 손실** → 메커니즘 ①이 확실히 살아남
3. `L ≈ 5~10 m` → 플레이 영역 스케일로 적정.
   세립사(L=2m)는 전이가 너무 좁아 플레이어가 못 읽고, 자갈(20m+)은 변화가 안 느껴짐
4. 모래성 강도는 여전히 충분 (실제로 중립사 해변에서 다들 잘 쌓음)
5. 경사가 적당히 가팔라져 **exit point 위아래 대비가 화면 안에 들어옴**

**세립사(0.2mm)로 가면 안 되는 이유** — 물이 없어서가 아니다.
세립사 해변은 **오히려 더 젖어 있다** (배수도 느림 + 모세관 상승대 35cm + 지하수면이
조석을 못 따라가 높이 머묾). 문제는 **동역학이 없다**는 것 —
지하수면도 exit point도 있지만 파도 한 번이 아무것도 안 바꾸고 조석에도 상태가 잘 안 변한다.
→ 시스템을 넣어놔도 **화면에서 아무것도 안 움직인다.**
중립~조립사를 고르는 건 물을 만들기 위해서가 아니라 **물의 움직임을 보이게 하기 위해서.**

> ⚠️ **오해 주의 — "굵은 모래를 골랐으니 침식이 약하다"가 아니다.**
> ①②③(침투/유출)은 침식의 **엔진이 아니라 변속기**다.
>
> - **엔진**: 파도 에너지 → 바닥 전단응력 → 알갱이가 들림. **입도가 고울수록 잘 들림**
> - **변속기**: 침투/유출이 uprush/backwash 비대칭을 조절 → 순 이동의 **방향**(육지/바다)을 정함.
>   굵은 모래에서만 유의미
>
> **Hjulström 곡선: 0.1~0.5mm가 지구상에서 가장 깎기 쉬운 물질이다.** (양쪽 끝이 올라간 U자 —
> 굵은 쪽은 무게가, 실트·점토 쪽은 점착력이 붙잡는다.) 즉 **세립사 해변이 훨씬 잘 깎인다.**
> 침강속도도 낮아(0.2mm ≈ 2cm/s vs 1mm ≈ 10cm/s) 한 번 뜨면 먼바다까지 간다.
>
> | | 세립사 (dissipative) | 조립사 (reflective) |
> |---|---|---|
> | 표면 단단함 | 단단 (σ ∝ 1/d + 넓은 쇄파대에서 에너지 소산) | 푸석 |
> | 국소적으로 패임 | 잘 안 됨 | 잘 됨 |
> | **총 이동량 / 계절 변화** | **큼 (폭풍에 사주 형성)** | 작음 |
>
> 자갈 해변이 해안 방어 구조물로 쓰이고, 양빈 공사에서 원래보다 **굵은 모래**를 넣는 이유가 이것.
>
> **우리 선택(0.4~0.6mm)은 Hjulström 최소 구간의 오른쪽 끝자락 — 여전히 잘 깎인다.**
> 그리고 모래성은 평형 프로파일 위로 솟은 인공 구조물이라 어떤 입도에서든 파도가 먹는다.
> 입도가 좌우하는 건 "모래성이 깎이느냐"가 아니라 **"주변 지형이 어떻게 반응하느냐"** 다.

**구현 노트**: `grainSize`를 상수가 아니라 **필드로** 두고
`K`, `cohesionMax`, `capillaryFringe`, `talusAngle`을 전부 여기서 파생시킬 것.
나중에 구역별 입도 차이 / 플레이어가 모래를 골라 옮기는 행동으로 확장 가능.

## 게임 동사 후보 — 지어낼 필요가 없다

실제 모래조각 기법이 **전부 우리가 이미 모델링한 물리 위에서 돈다.** (papers.md K-9)

| 동사 | 물리 | 이미 있나 |
|---|---|---|
| **우물 파기 / 물 나르기** | 지하수면, `W` | ✓ F절 |
| **다지기 (두드리기)** | 다짐 → φ↓ → 강도↑. 물이 표면으로 배어나옴 | ✓ 팽창/다져짐 |
| **거푸집 쌓기** | 형틀 안에서 다져 블록 제작 | ✓ |
| **팬케이크** (묽은 모래 얹고 흔들기) | 순간 액상화 → 재배치 → 배수 | ✓ |
| **위에서 아래로 조각** | 아래를 건드리면 위가 무너짐 | ✓ 입자 동역학 |
| **터널·아치 뚫기** | 압축 구조, 수평 추력, 버트레스 | ✓ K절 |
| **물 뿌려 유지보수** | 증발 대응 | ✓ E절 |
| **비 온 직후를 노려 짓기** | 과포화 → 배수 → **최적 강도 골든타임** | ✓ params §4a |
| 밟기 (실수/파괴) | 팽창 → 약해짐. 표면이 뽀얘짐 | ✓ |

**플레이어가 배우게 되는 것도 진짜 지식이다** — 현수선이 반원보다 강하고,
아치엔 버트레스가 필요하고, 높이보다 세장비가 위험하고, 물때를 읽어야 한다는 것.
목적이 "실제로 쌓는 것의 구현"이라면 이게 자연스러운 결과다.

## ★★ 게임플레이 — 완전 샌드박스 모래성 시뮬레이션 (2026-09-05 결정)

**게임이 목표를 주지 않는다.** 점수·미션·타이머 없음. 플레이어가 스스로 만든다.

### 설계 원칙과 철학이 같다
```
설계 원칙:  창발을 최대화하고 규칙을 최소화한다
샌드박스:   게임이 목표를 주지 않고 플레이어가 만든다
```
목적을 "실제 해변의 구현"으로 잡은 순간부터 예정된 결론.

### ⚠ 샌드박스라고 압박이 없는 게 아니다
```
게임이 주는 압박:  없음
자연이 주는 압박:  마름 / 파도 / 조석 / 비 / 바람   ← 규칙이 아니라 물리
```
**실제 해변에서도 아무도 목표를 주지 않지만 파도는 온다.**

### ★ 정서적 핵심
> **모래성은 없어질 걸 알면서 만드는 것이다.**

파도가 결국 가져간다. 그게 이 소재의 매력이고 샌드박스와 정확히 맞는다.
목표를 달성해 보존하는 게 아니라 **만드는 동안이 전부인** 구조.

→ **"파도가 모래성을 먹는 장면"이 실패가 아니라 이 게임의 클라이맥스다.**
그 장면을 잘 만드는 것이 렌더링(L절)·소리(M절) 작업의 우선순위를 정한다.

### 스케일 (이 결정으로 정해짐)
```
모래성 작업 영역   2 ~ 5 m      [B] 입자
물가까지          10 ~ 30 m    조차에 따라
시뮬 영역         50 × 50 m    [A] 하이트필드
배경             100 m+       메시. 시뮬 안 함

50m × 50m @ 256² → 19.5 cm/cell
25m × 25m @ 256² →  9.8 cm/cell   ← 프로토타입은 이쪽
```
beach cusp(10~50m)는 잡히고 리플(5~15cm)은 안 잡힌다 → **리플은 머티리얼 노멀로.**

### ★ 시간 — 전부 1×. 압축하지 않는다

**균일 배속은 물리를 안 바꾼다 — 단위 변환일 뿐이다.**
모든 rate를 S배 하면 시간이 1/S가 되고 **길이 스케일은 보존된다**
(`L = √(2KD/nω)` 에서 K와 ω를 둘 다 S배 → 약분).
**균일 = 타임랩스 영상. 비균일은 어떤 실제 상황의 타임랩스도 아니다.**

**비균일 25×(이전 안)가 깨뜨리던 것**
```
ω만 25× 되고 K는 1× 이면   L : 6.9 m → 1.4 m   (1/5로 압축)
→ exit point 전이를 플레이어가 못 읽는다
→ 세립사를 배제했던 이유(L=2m라 전이가 안 보임)를 배속으로 다시 만드는 셈
```

**그리고 압축이 필요 없다 — 1×에서 다 보인다**
```
중조(1.8m) 반일주조, 경사 1:10 →  물가가 4.5 m/시간 이동
```
| 프리셋 | 조차 | 물가 이동 |
|---|---|---|
| 극대조(서해) | 9 m | **22 m/시간** |
| 중조 | 1.8 m | 4.5 m/시간 |
| 미소조(동해) | 0.3 m | 0.8 m/시간 |

> **★ 25×면 미소조도 19 m/시간이 되어 모든 프리셋이 극적으로 변한다 — 압축이 지역 차이를 지운다.**

**건조도 마찬가지** — 실제 표면 건조는 **15~30분**이라 1시간 세션에 2~4번 마른다.
25×면 표면 1분·붕괴 2~7분이라 **물 나르기만 하는 아케이드**가 된다.
실제 사람들의 행동은 "가끔 물 뿌리기"다.

**세션보다 긴 것은 압축이 아니라 선택으로**
```
대조소조 14.8일 / 계절 / 폭풍 사이클  →  세션 시작 시 뽑는다
기다림                              →  균일 고배속(×100) 건너뛰기 + 진행바
                                       (건너뛰기도 균일이면 여전히 타임랩스)
timeScale                           →  설정값으로 남기되 기본 1×. 디버그·트레일러용
```

### 샌드박스라서 새로 생긴 결정 사항 (미결)
- [ ] **시간 제어** — 연속 배속보다 **"기다리기"**("물이 빠질 때까지"/"마를 때까지")가 깔끔해 보임.
      연속 배속은 파도만 실시간이라 조석이 이상하게 빨라 보인다
- [ ] **날씨 조작 권한** — (a) 관찰 샌드박스: 자연대로 돌고 플레이어가 적응 ← "실제 구현"에 충실
      / (b) 도구 샌드박스: 폭풍을 부르고 조수를 조절 ← 실험 가능.
      **절충: 기본 (a) + 별도 "실험 모드"에서 조건 설정** (비행 시뮬레이터 방식)
- [ ] **조작 방식** — [게임 동사 9개](#게임-동사-후보--지어낼-필요가-없다)가 전부 손과 도구인데,
      입자 시뮬을 손으로 만지는 구현이 만만치 않다 (입자 추가/제거 + 하이트필드 왕복)
- [ ] **저장 / 사진** — 저장하려면 입자 수만 개 위치 + 하이트필드 + W·d·s 필드.
      용량이 크다. **사진 모드가 더 현실적일 수 있다** (샌드박스의 핵심 보상)
