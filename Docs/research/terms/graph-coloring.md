# ★ 그래프 컬러링 — 현대적 답

> [← 용어집](../glossary.md) › [6. 수치해석 / 시뮬레이션 기법](../glossary.md#6-수치해석--시뮬레이션-기법)

**아이디어: 서로 영향을 안 주는 것끼리 묶으면 동시에 처리해도 된다.**

## 가장 쉬운 사례 — 레드-블랙 (유체 압력 풀이의 고전)
```
┌─┬─┬─┬─┬─┐
│R│B│R│B│R│   각 셀은 상하좌우 이웃만 참조
├─┼─┼─┼─┼─┤   → 빨강의 이웃은 전부 검정
│B│R│B│R│B│   → 빨강끼리는 서로 절대 안 건드림
├─┼─┼─┼─┼─┤
│R│B│R│B│R│   1패스: 빨강 전부 동시 갱신 (병렬)
└─┴─┴─┴─┴─┘   2패스: 검정 전부 동시 갱신 (갱신된 빨강을 읽음)
```
**2패스 결과가 순차 Gauss-Seidel과 정확히 같다.** 병렬인데 수렴은 GS 그대로.

## 일반화 — 제약 그래프 채색
```
노드 = 제약 하나
간선 = "이 두 제약이 같은 입자를 공유한다"
→ 인접 노드끼리 다른 색 (그래프 채색 문제)
```
**같은 색 = 어떤 입자도 공유 안 함 = 동시 처리해도 쓰기 충돌 없음.**
필요한 색 개수 ≈ 최대 차수 + 1.

## Vivace (Fratarcangeli, Tibaldo, Pellacini 2016, SIGGRAPH Asia)
*"Vivace: a Practical Gauss-Seidel Method for Stable Soft Body Dynamics"*
> ⚠ 두 번째 저자명 확인 필요. 이하 내용도 기억 기반이라 원문 대조 권장.

레드-블랙 아이디어 자체는 오래됐다. 이 논문의 기여는 **임의의 비정형 [제약](constraint.md) 그래프를
실시간으로 채색해 쓸 수 있게 만든 것.**

**① 랜덤 그리디 병렬 채색** (정확한 채색은 NP-hard)
```
1. 각 노드에 랜덤 수 부여
2. 색 없는 이웃들 중 내 랜덤 수가 최대면 → 지금 색칠 (이웃이 안 쓴 최소 색)
3. 반복
```
모든 단계가 병렬. 보통 `O(log n)` 라운드. 색이 최적보다 조금 많아도 빠른 게 낫다.

**② GPU 부하 균형** — 색마다 제약 개수가 들쭉날쭉하면 제약이 적은 색에서
점유율이 낮아 시간이 통째로 낭비된다. 색 개수를 줄이고 균형 맞추는 데 신경 씀.

**③ 결과**
| | Jacobi + 평균화 + SOR | Vivace (컬러링 GS) |
|---|---|---|
| 병렬성 | 완전 | 색 단위 |
| 과보정 | 나눠서 억제 (느려짐) | **애초에 불가능** |
| 수렴 | 느림 | **Gauss-Seidel 그대로** |
| 전처리 | 없음 | **채색 필요** ← 우리에겐 이게 문제 |

## ★ 우리 케이스는 격자 기반 기하 컬러링이 낫다
Vivace의 전제는 **위상이 고정**(천·연체)이라 한 번 칠하면 계속 쓴다는 것.
우리 [B] 입자 계층은 **매 프레임 입자가 생기고 사라지고 이웃이 바뀐다** → 매번 다시 칠해야 함.

그런데 **모든 입자의 반지름이 같으므로**(Macklin 2014의 결정이 여기서 또 보상) 공간으로 나누면 된다.
```
셀 크기 = 상호작용 반경 이상, 2칸 간격으로 색 배치

┌─┬─┬─┬─┬─┐
│1│2│1│2│1│   같은 색 셀은 항상 한 칸 이상 떨어짐
├─┼─┼─┼─┼─┤   → 그 안의 입자들은 절대 안 닿음 → 동시 처리 안전
│3│4│3│4│3│
├─┼─┼─┼─┼─┤   2D: 4색  /  3D: 8색 (2×2×2)
│1│2│1│2│1│
└─┴─┴─┴─┴─┘
```
- **채색 알고리즘 불필요.** 색 = 셀 좌표를 2로 나눈 나머지. 산술 두 줄
- 입자가 생기고 사라져도 무관. 위치만 알면 색이 정해짐
- **이미 이웃 탐색용 균일 격자(Niagara `Neighbor Grid3D`)를 쓸 예정이라 격자가 이미 있다**
- 3D면 커널 [디스패치](dispatch.md) 8번 고정

**Vivace의 이득(진짜 Gauss-Seidel)을 얻으면서 채색 비용은 0.**
대신 색이 8개로 고정되고 셀에 입자가 몰리면 부하가 불균등해진다.

## 정리 — 언제 무엇을
| | 언제 |
|---|---|
| **레드-블랙** | 격자 위 문제 (유체 압력 풀이). 가장 단순 |
| **Vivace (그래프 채색)** | **위상 고정** 비정형 제약. 천, 연체 |
| **★ 격자 기반 기하 컬러링** | **위상이 매 프레임 바뀌는** 접촉 제약. **우리 케이스** |
| Jacobi + 평균화 + SOR | 채색조차 부담일 때. 단순하지만 수렴이 느림 |

> **진행 순서**: 프로토타입은 마지막(제약 평균화)으로 시작해 돌아가는 걸 먼저 보고,
> 성능이 부족하면 격자 기반 컬러링으로 올린다.
