# 컴퓨트 셰이더 (compute shader)

> [← 구현 용어집](../glossary-impl.md) › [2. GPU 실행 모델](../glossary-impl.md#2-gpu-실행-모델)

렌더링과 무관하게 **GPU에서 임의 계산**을 돌리는 셰이더. 픽셀을 그리지 않고 버퍼/텍스처를 읽고 쓴다.
격자 시뮬의 [패스](pass.md) 하나하나가 컴퓨트 셰이더 한 번이다.

## 왜 이게 가능한가

**2006년에 GPU 코어가 렌더링 전용이기를 그만뒀기 때문이다.**

그 전까지 정점 셰이더 유닛과 픽셀 셰이더 유닛은 **물리적으로 따로** 있었다.
G80 / DirectX 10이 이를 **통합 셰이더 아키텍처**로 바꿔, 범용 ALU 코어 무더기에
스케줄러가 일을 배정하는 구조가 됐다. **코어가 범용이 된 순간 "그래픽"은 그 코어가 하는
여러 일 중 하나가 됐다.**

### 그 전에도 했다 — 위장해서

```
데이터를 텍스처에 인코딩 → 화면 전체를 덮는 사각형 하나를 그림
                       → 픽셀 셰이더가 픽셀마다 = 데이터 원소마다 실행
                       → 렌더 타겟에서 결과 회수
```

계산을 **렌더링인 척** 시킨 것이다(GPGPU). 우리 격자 패스도 원리적으로는 이렇게 짤 수 있다 —
셀당 독립 계산이라 픽셀 셰이더와 모양이 같다. **컴퓨트 셰이더는 이 위장을 걷어낸 것뿐이고,
새 하드웨어가 생긴 게 아니라 원래 있던 ALU 배열에 직접 접근하는 API가 열린 것이다.**

## 무엇을 건너뛰는가

```
정점 입력 → 정점 셰이더 → [래스터라이저] → 픽셀 셰이더 → [깊이 테스트·블렌딩]
                            ↑ 고정 기능                    ↑ 고정 기능
```

대괄호가 **고정 기능(fixed-function) 전용 회로** — 삼각형을 픽셀로 쪼개고 깊이를 비교하고
색을 섞는다. **이것들이 "그래픽"인 부분이고, 프로그래밍 가능한 셰이더 단계는
원래부터 그냥 계산이었다.** 컴퓨트는 고정 기능을 전부 건너뛰고
[스레드 개수를 직접 지정해](dispatch.md) ALU 배열과 메모리에 곧바로 접근한다.

## 왜 빠른가 — 트랜지스터를 어디에 썼는가

| | CPU | GPU |
|---|---|---|
| 트랜지스터 | 분기 예측 · 비순차 실행 · 큰 캐시 | **ALU** |
| 지연 대응 | 캐시로 **피한다** | 스레드를 **초과 배정해 숨긴다** |
| 잘하는 것 | 하나를 빨리 | 수천 개를 동시에 |

메모리 대기가 생기면 그 스레드를 재우고 **1사이클 만에** 다른 스레드로 갈아탄다.
수천 개가 상주해 있으니 항상 돌릴 게 있다. **미스를 없애는 대신 미스를 신경 안 써도 되게** 만든 것.

실행 단위는 32(NVIDIA warp) 또는 64(AMD wavefront) 스레드가 **하나의 명령 포인터를 공유**하는
SIMT다. Burst의 AVX2가 8레인 SIMD라면 GPU는 32레인 SIMD가 수백 개 있는 셈.

## "임의"의 진짜 한계

| 제약 | 내용 |
|---|---|
| **분기 발산** | 같은 warp 안에서 `if`가 갈리면 **양쪽을 다 실행**하고 마스킹한다. 최악 32배 손해 |
| **데이터 병렬이어야** | 원소끼리 독립적이어야 한다. 앞 결과가 다음 입력인 순차 계산은 최악 |
| **재귀 · 동적 할당 없음** | 스택이 사실상 없다. 트리 순회는 명시적 스택 배열로 푼다 |
| **[리드백 지연](gpu-readback.md)** | GPU→CPU는 몇 프레임 걸린다 |

**도구 11종 분기가 GPU에 안 맞는 이유가 첫 줄이다.**
반대로 격자 셀 100만 개가 전부 같은 식을 도는 건 최적 형태다.

## 이 프로젝트의 숫자

```
1024² 셀 × 9패스 = 스텝당 940만 스레드
CPU  16코어 × AVX2 8레인 = 128 레인
GPU  수천 레인 + 지연 은닉
```

**세 자릿수 차이다.** 격자 시뮬이 GPU가 아니면 성립하지 않는 이유이고,
"격자 = Niagara, 구조물 = 커스텀 컴퓨트"도 결국 **같은 ALU 배열에 일을 태우는 두 가지 방법**이다.
