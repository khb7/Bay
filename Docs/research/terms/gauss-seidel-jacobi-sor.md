# Gauss-Seidel / Jacobi / SOR ★

> 물리 관점(glossary)과 구현 관점(glossary-impl)을 합친 문서.

[제약](constraint.md)이 여러 개인데 서로 얽혀 있어 한 번에 다 만족시킬 수 없다 → 반복해서 오차를 줄인다.
**두 방식의 차이는 하나: 같은 반복 안에서 이미 갱신된 값을 쓰느냐.**

```
Jacobi (동시)
  옛 위치 → 제약1 보정량 계산 ┐
  옛 위치 → 제약2 보정량 계산 ├→ 계산 다 끝나고 한꺼번에 적용
  옛 위치 → 제약3 보정량 계산 ┘

Gauss-Seidel (순차)
  제약1 계산 → 즉시 적용 → 제약2가 갱신된 값을 읽음 → 즉시 적용 → 제약3 ...
```

- **Gauss-Seidel**: 정보가 **한 반복 안에서 끝까지 전파**된다 → 훨씬 빨리 수렴.
  대신 제약2가 제약1을 기다려야 함 → **순차적 → GPU 불가**
- **Jacobi**: 정보가 **반복당 한 칸씩만** 감 → 느림. 대신 완전 병렬

**왜 Jacobi가 과보정하나** — 입자 P가 벽 3개에 파묻혀 각 접촉이 "위로 1cm"라고 할 때:
```
Gauss-Seidel: 접촉1 처리 → 1cm 올라감 → 접촉2·3은 이미 해결됨 → 총 1cm ✓
Jacobi:       셋 다 옛 위치를 보고 "+1cm" → 한꺼번에 적용 → 총 3cm ✗ → 튕겨 날아감
```
제약 20개면 20배. 다음 프레임에 반대로 튕기고 진동하다 폭발.

**제약 평균화**: 그 입자에 걸린 제약 개수로 나눔 → 과보정 소멸.
단, 제약들이 진짜 독립적이면 그만큼 **느려짐**.

**SOR (Successive Over-Relaxation)**: 그래서 다시 밟아준다.
```
x_new = x_old + ω · (계산된 보정)

ω = 1       그대로            ω < 1      덜 적용 (진동 억제)
1 < ω < 2   더 적용 ← 여기     ω ≥ 2      발산
```
보통 **ω = 1.5~1.9**. 다음 반복에도 같은 방향으로 보정할 게 뻔하니 미리 더 가는 것.
격자 문제 기준 Jacobi/GS의 `O(N²)` 반복을 **최적 ω의 SOR은 `O(N)`** 으로 줄인다.

**어디서 또 쓰이나 — 이미 쓰고 있다**

| 분야 | 용도 |
|---|---|
| **게임 물리 엔진의 접촉 해결** | **sequential impulse = Gauss-Seidel.** Box2D, Bullet, PhysX 전부 |
| Unity | `Physics.defaultSolverIterations` 가 **정확히 이 반복 횟수** |
| 유체 시뮬 | 압력 투영(푸아송) 풀이 |
| 멀티그리드 | Gauss-Seidel을 "스무더"로 |

원래 맥락은 선형방정식 `Ax = b`를 반복으로 푸는 방법.
Gauss가 1823년 편지에 쓴 것을 Seidel이 1874년 출판.

## 구현 관점 (UE5 / Niagara)

- **Gauss-Seidel**: 제약을 순차로 풀고 즉시 반영. 빨리 수렴하지만 **병렬화 불가**
- **Jacobi**: 전부 동시에 계산해 나중에 합침. 병렬 가능하지만 과보정이 생김
  → **제약 평균화**(보정량을 관여 제약 개수로 나눔) + **SOR**(1보다 큰 계수로 수렴 회복)로 보완

GPU는 Jacobi + 위 두 보정을 쓴다.
