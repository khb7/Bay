# 크리프 (creep)

> [← 용어집](../glossary.md) › [6. 수치해석 / 시뮬레이션 기법](../glossary.md#6-수치해석--시뮬레이션-기법)

**부서지지 않는 하중인데도 시간이 지나며 변형이 조금씩 쌓이는 것.**
"기어간다"는 뜻이고, 핵심은 **당장은 안전한데 시간이 범인**이라는 점이다.

```
무너짐(사태)   한계를 넘었다      →  힘의 문제.   즉시 일어난다
크리프         한계 아래에 있다   →  시간의 문제. 기다리면 쌓인다
```

일상의 예 — 책장 선반이 몇 년 뒤 휘어 있는 것, 걸어둔 코트가 어깨를 늘려놓는 것,
산비탈의 나무가 아래로 휘어 자라는 것(soil creep). 공학에서는 터빈 날개 수명과
콘크리트 처짐이 전부 이것이다.

## ⚠ 이 문서에서 구분하는 세 가지

| | 무엇 | 어디 |
|---|---|---|
| **물리 크리프** | 실제 재료가 항복 아래에서 시간에 따라 변형 | 아래 |
| **수치 크리프** | 솔버 잔차가 매 스텝 누적된 것. **물리가 아니다** | 아래 · [M0](../../design/m0-log.md) |
| **포행 (surface creep)** | 바람에 튄 모래가 굵은 알갱이를 밀어 굴리는 것 | [papers.md §H](../papers.md) — **완전히 다른 현상** |

영어로는 셋 다 `creep`이지만 한국어 이름이 갈려 있다.
**"포행"은 풍성 이동, "크리프"는 변형 누적**으로 굳힌다.

## ★ 물리 크리프 vs 수치 크리프 — 판별법은 잦아드느냐

실제 모래에도 크리프는 있다. [안식각](angle-of-repose.md) 아래에서도 알갱이가
미세하게 자리를 고쳐 잡는다. **다만 시간이 지날수록 느려져 사실상 멈춘다.**

```
물리   0.36 → 0.20 → 0.11 → 0.05 ...   점점 느려진다. 결국 멈춘다
수치   0.36 → 0.14 → 0.035 → 0.035 ... 어느 지점부터 일정하다. 안 멈춘다
```

**"일정하다"가 수치 오차라는 증거다.** 겉모습은 둘 다 "천천히 흘러내림"이라 구분이 안 되지만,
시간에 따른 감쇠 여부가 갈라준다.

## 수치 크리프는 어디서 나오나

```
매 서브스텝   제약을 완전히 못 푼다 ([반복](iteration-relaxation.md)이 유한하니까)
              → 아주 조금 미끄러진다
              → 다음 서브스텝은 그 위치를 새 기준으로 삼는다
              → 미끄러진 만큼이 굳는다. 되돌릴 방법이 없다
```

**매 스텝 조금씩 손해 보는데 기억을 못 해서 회수를 못 하는 구조**다.
[XPBD](xpbd.md)의 `λ`가 서브스텝마다 리셋되는 것과 같은 뿌리이고,
[하중이 바닥까지 못 가는 문제](../papers.md)·[마찰 예산 부족](coulomb-friction.md)과도
전부 "제약을 덜 풀어서 생기는 잔차"의 다른 얼굴이다.

## M0 실측 (2026-09-06)

`W=0`, 경사 5°(임계의 약 1/3)에서:

```
평균 속력   0.361 → 0.144 cm/s   지터 성분. 죽어간다
초당 변위   0.016 → 0.035 cm/s   드리프트 성분. 6초 이후 일정  ← 안 죽는다
                                 = 스텝당 5.8 μm
```

**두 양이 반대로 움직이는 것이 핵심이다.** 평균 속력은 방향을 안 보므로 제자리 떨림도
세어지고, 그 떨림이 잦아들며 값이 내려간다. 변위는 방향을 보므로 **한쪽으로 흐른 것만 남는다.**

### 게임에 직접 걸린다

```
0.035 cm/s  =  시간당 126 cm      ※ timeScale 1× 실시간이므로 그대로 게임 시간
```

게임 정의가 "성이 여러 채 남아 각자 마르고 무너진다, 보러 가는 것 자체가 콘텐츠"인데
**보러 갔더니 다 녹아 있으면 그 콘텐츠가 죽는다.**

> ⚠ 조건이 다르다 — 위 값은 **마른 모래를 5°로 기울인** 것이다.
> 젖은 모래는 [점착](cohesion.md)이 마찰 예산에 더해져 덜할 수 있고,
> 반대로 수직 벽은 5° 사면보다 응력이 크다. **성 조건에서 다시 재야 자릿수를 안다.**

## ★ 계기로 쓴다 — 크리프 속도 = 수렴도

```
반복 수를 올린다  →  크리프가 줄어든다     →  수렴 부족. 반복·모멘텀·워밍 스타트로 해결
                 →  크리프가 안 줄어든다  →  구조 문제. 서브스텝 리셋 자체를 손봐야
```

`λn(깊이)` 프로파일보다 훨씬 재기 쉽다 — **5°에 놓고 16초 돌린 뒤 초당 변위 하나**면 된다.
그리고 목표선을 지어낼 필요가 없다: **일정하면 안 되고 잦아들어야 한다.**

## 측정 판정과의 관계

M0의 [경사판](../../design/m0-spike.md) 붕괴 판정이 크리프 때문에 두 번 깨졌다.

| 판정 | 결과 |
|---|---|
| 누적 변위 > 0.5r | ✗ 크리프도 시간만 주면 임계를 넘는다 → **유지 시간이 답을 바꿈** |
| [§2-2](../../design/m0-spike.md) 60프레임 연속 | ✗ 스파이크 한 번에 카운터가 부러짐 → **μ 순서 역전** |
| **뒤 절반 평균 < 앞 절반 평균** | 검증 중 |

**세 번째가 곧 위의 판별법이다** — "잦아드느냐"를 그대로 판정식으로 쓴 것.
자를 고치면 크리프 계기가 딸려 나오는 셈이다.

> ⚠ **판정이 크리프를 안 걸러낸다고 크리프가 사라진 건 아니다.** 자를 고치는 것은
> 크리프가 *측정을 오염시키는 것*을 막을 뿐이고, 크리프 자체는 별도 항목으로 남는다.
