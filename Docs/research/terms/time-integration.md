# 시간 적분 (time integration) — 적분기의 종류

> [← 용어집](../glossary.md) › [6. 수치해석 / 시뮬레이션 기법](../glossary.md#6-수치해석--시뮬레이션-기법)

물리 시뮬은 `a = F/m`으로 **가속도**를 얻는다. 그런데 화면에 그려야 하는 건 **위치**다.
그 사이를 `dt`씩 끊어 메우는 것이 시간 적분이고, 방법이 여러 개다.

```
a  ──∫dt──▶  v  ──∫dt──▶  x
```

각 스텝이 [리만 합](spectral-band.md)의 직사각형 하나다 — `dt`가 폭, 미분값이 높이.

## 한 줄 차이가 안정성을 가른다

```csharp
// 전진 오일러 (forward / explicit Euler)  ✗
x += v * dt;        // ← 옛날 v 를 쓴다
v += a * dt;

// 준암시적 오일러 (semi-implicit / symplectic Euler)  ✓
v += a * dt;        // ← v 를 먼저 갱신하고
x += v * dt;        //    새 v 로 위치를 옮긴다
```

**두 줄의 순서만 바꾼 것인데 결과가 근본적으로 다르다.** 스프링에 매달린 추를 돌려 보면
전진 오일러는 진폭이 매 주기 커져 나선형으로 발산하고, 준암시적 오일러는 진폭이
살짝 흔들릴 뿐 **유계로 남는다**(심플렉틱 = 위상공간 부피를 보존).

> **유계(有界, bounded)** — "경계가 있다". 어떤 `M`이 있어 항상 `|x| ≤ M`.
> **수렴과 다르다** — 한 값에 안착하지 않고 영원히 흔들려도 범위 안이면 유계다.
> ```
> 발산  |x| → ∞        전진 오일러      에너지가 는다
> 유계  |x| ≤ M        준암시적 오일러   참값 주변에서 진동     ← 게임에 필요한 건 여기까지
> 수렴  x → 특정 값      후진 오일러       수치 감쇠로 깎여 멈춘다
> ```
> 주기당 1%만 늘어도 `1.01^1000 ≈ 21,000배`다. **"조금씩 는다"에 안전한 크기는 없고,
> 상한이 있느냐 없느냐만 있다.** 정확도가 같은 두 적분기를 굳이 가르는 이유.

## 적분기 비교

| 적분기 | 정확도 | 평가 횟수 | 안정성 | 쓰이는 곳 |
|---|---|---|---|---|
| 전진 오일러 | `O(dt)` | 1 | **에너지가 는다. 발산** | 쓰지 말 것 |
| **준암시적 오일러** | `O(dt)` | 1 | 유계 진동 | **게임 물리의 표준.** PhysX · Box2D · Chaos |
| Verlet / velocity Verlet | `O(dt²)` | 1 | 매우 좋음 | 분자동역학 · 천체 · 구식 래그돌 |
| RK4 | `O(dt⁴)` | **4** | 좋음 | 게임엔 잘 안 씀 (아래) |
| 후진 오일러 (암시적) | `O(dt)` | 연립방정식 | **무조건 안정** | 천 시뮬 (Baraff-Witkin 1998) |

**RK4가 게임에서 안 쓰이는 이유**: 4차 정확도는 힘이 매끄러울 때 얘기다. 충돌과
[제약](constraint.md)은 불연속이라 차수의 이점이 그 자리에서 사라지는데, 비용은 4배 그대로다.
같은 예산이면 **RK4 한 번보다 준암시적 오일러 4 [서브스텝](substep.md)이 낫다.**

**후진 오일러의 대가**: 안 터지는 대신 [연립방정식을 풀어야 하고](symmetric-linear-system.md),
에너지를 계속 갉아먹어 움직임이 눅눅해진다(수치 감쇠). 그래서 천처럼 뻣뻣한 것에만 쓴다.

## ★ [PBD](pbd.md)/[XPBD](xpbd.md)는 적분기가 아니다

```csharp
v += g * dt;   p = x + v * dt;   // 1. 준암시적 오일러로 '예측'
ProjectConstraints(ref p);       // 2. 위치를 직접 밀어 제약 만족   ← 적분이 아님
v = (p - x) / dt;   x = p;       // 3. 속도를 위치 변화에서 역산
```

1단계는 그냥 준암시적 오일러다. **PBD의 정체는 2단계** — 힘을 적분하는 대신 위치를
투영한다. 큰 수를 곱하는 곳이 없어 절대 발산하지 않는 이유가 여기 있다.
즉 PBD는 적분기를 대체한 게 아니라 **적분 위에 얹은 보정 계층**이다.

## 이 프로젝트의 적분

| 계층 | 방식 | 안정 조건 |
|---|---|---|
| 입자 (구조물) | XPBD = 준암시적 예측 + 제약 투영 | 발산 없음. `substep`·반복은 [안식각](angle-of-repose.md)으로 교정 |
| 격자 (해변) | 명시적 (가상 파이프 → `d` → 이류) | [CFL](cfl-condition.md) `dt < 27 ms` |
| 수분 `W` | 지수 이완 `W = lerp(W, W_eq, rate·dt)` | `rate·dt < 1` |

모든 계층이 **1× 실시간**이다([시간 절](../../design/system-design.md) — 비균일 배속은 폐기).
프로세스마다 `dt`가 다르지 않으므로 위 안정 조건은 전부 같은 `dt` 하나로 판정한다.

> ⚠ **고배속 건너뛰기는 `dt`를 키우는 게 아니다.** "물이 빠질 때까지"의 ×100은
> **스텝을 100배 많이 도는 것**이지 `dt`를 100배로 늘리는 게 아니다.
> `dt`를 키우면 [CFL](cfl-condition.md)과 `rate·dt < 1`이 그 자리에서 깨진다.
> 균일 배속이 "물리를 보존하는 타임랩스"인 것은 **적분 단계가 그대로일 때만** 성립한다.
