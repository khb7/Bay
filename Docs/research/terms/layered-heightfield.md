# 레이어드 하이트필드 (layered heightfield)

> [← 구현 용어집](../glossary-impl.md) › [3. 격자 시뮬레이션](../glossary-impl.md#3-격자-시뮬레이션)

[하이트필드](heightfield.md)의 "한 (x,z)에 높이 하나" 제약을 푸는 값싼 방법.
컬럼마다 높이값 대신 **구간 리스트**를 저장한다.

```
하이트필드            레이어드
  h = 14              [0~8], [11~14]      ← 8~11이 빈 공간 = 터널
```

| 변종 | 데이터 | 표현 범위 |
|---|---|---|
| **상/하 높이 쌍** `h_top`·`h_bottom` | 2D × 2 | 컬럼당 빈 공간 **1개** |
| **K층 구간 리스트** | 2D × K | 빈 공간 K−1개 (Šťava 2008의 다층 확장) |
| 컬럼 RLE / 희소 복셀 | 표면 밴드만 | 자유 |

침식 알고리즘은 층별로 그대로 확장된다. 메모리는 하이트필드의 K배로 끝나
[복셀](sdf.md)의 해상도³와 비교가 안 되게 싸다.

## ★ 그런데 표현과 동역학은 다른 문제다

**"터널이 서 있다"를 그리는 건 싸다. "터널이 언제 어떻게 무너지는가"가 비싸다.**

레이어드 하이트필드에서 천장 붕괴를 계산할 수단은 **컬럼 간 질량 이동**밖에 없다.
그러면 결과는 천장이 위에서부터 스르륵 얇아지다 사라지는 그림이고,
[설계 결정 기록](../../sessions/26.09.04-design.md)에서 명시적으로 거부한 바로 그것이다.

```
표현의 문제   →  구간 리스트 하나로 값싸게 풀린다
동역학의 문제 →  물질이 연결된 덩어리로 거동해야 한다   ← 비용은 전부 여기
```

값싼 표현들이 전부 같은 지점에서 걸리는 이유다. **덩어리 붕괴가 타협 불가 요구사항인 한
표현을 바꾸는 것으로는 해결되지 않는다.**

## 예외 — Teardown 방식

복셀 + 연결 요소 분석으로 덩어리 붕괴를 싸게 해낸 사례가 있다. 매 프레임 연결성을 검사해
지지를 잃은 덩어리를 **강체로 변환**해 떨어뜨린다. 복셀도 싸고 강체도 개수가 적어 싸다.

모래에는 그대로 안 맞는다 — 떨어진 덩어리가 강체로 남으면 안 되고(닿으면서 부서져야 한다),
젖은 모래의 강도는 `W`에 따라 연속이라 붕괴가 이진 판정이 아니다.
다만 **지지 상실 판정을 제약 풀이가 아니라 연결성으로 미리 거른다**는 아이디어는
[M0](../../design/m0-spike.md)에서 "20만 입자 XPBD가 실시간인가"에 아니오가 나올 때 검토할 후보다.

## 이 프로젝트에서의 위치

채택하지 않았다. 대신 **공간으로 분업한다** — 오버행이 필요한 영역이 해변의 1%도 안 되므로
60m×60m 전체에 3D 비용을 물리는 대신 [비싼 표현을 쓸 영역을 좁혔다](heightfield.md).

> **다만 구멍이 하나 있다 — 자연 지형에는 굴을 못 뚫는다.**
> 입자는 플레이어가 만든 구조물만이고 자연 지형은 하이트필드이므로,
> 구덩이(위→아래)는 되지만 모래언덕 옆구리를 파고드는 굴(옆으로)은 원리적으로 불가능하다.

이게 아쉬운 것으로 판명되면 **`h_bottom` 채널 하나**가 가장 싼 해법이다.
자연 지형에 빈 공간 한 겹만 허용하는 것 — 굴 하나는 표현되고, 붕괴는
[열침식](thermal-erosion.md)으로 처리하면 된다(자연 지형의 굴은 덩어리로 무너질 필요가 없다).
채널 하나 + 패스 몇 줄.

**단, 지금은 하지 않는다.** M0가 "입자로 터널이 서는가"에 답하기 전에 [A] 계층을
건드릴 이유가 없고, 저 구멍이 실제로 아쉬운지는 M2에서 도구를 잡아보면 안다.
