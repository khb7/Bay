# 실물 레퍼런스 — 만들어진 게임·데모가 어디까지 갔나 (2026-09-14)

> [papers.md](papers.md) 는 논문만 다룬다. 이 문서는 **출시·공개된 것**이 우리 요구(터널 · 덩어리 붕괴 · 20만 입자 실시간)와 어디서 겹치고 어디서 못 미치는지다.
> 3-4 성능 통과선과 게임 정의의 차별점을 정할 때의 비교점.

---

## 1. 직접 경쟁작 — **Sandcastle** (Bubblebird Studio · Fabien Weibel · 룩셈부르크 1인)

같은 장르의 실물이 **2026년 8월에 데모로 나왔다.** 우리 게임 정의와 문장 단위로 겹친다.

| | |
|---|---|
| 데모 | 2026-08-06 Steam. 리뷰 **545개 · 95% 압도적 긍정** (9월 기준). 위시리스트 16.5만, 인스타 4.5M 조회 |
| 정식 | TBA (2026 내). 퍼블리셔 Future Friends Games |
| 플랫폼 | Windows / macOS / Linux / Steam Deck. **최소 사양 GTX 950 · Apple M1 내장 · RAM 3GB · 용량 400MB** |
| 엔진 | 80.lv 태그 Unity (프레스킷은 미기재) |
| 전작 | Haven Park · Trackline Express (코지 계열) |

**한다고 명시된 것** (스토어 · 위키 · 기사 종합)
- 모래가 **습도와 압력에 따라 다져지고, 부서지고, 형태를 유지**. "너무 얇게 깎으면 탑이 처지고, 젖은 모래로 보강하면 선다"
- 파도가 **흐르고, 고이고, 벽을 침식**. 모서리·바다 쪽이 침식 핫스팟. 해자 고임. 조석 리듬
- 도구: 파기 · 기초 다지기 · 조각(흉벽 · 계단 · 해자 턱). 양동이·삽
- 성벽 · 탑 · 흉벽 · 해자 · 계단. 장식(유목 · 조약돌 · 조개 · 해초). 해변 10종(석호 · 섬 · 사주 · 삼각주…). 숨은 보물
- 타이머 · 점수 없음. "조석의 느린 리듬만"
- 데모 패치: 물 시뮬 개선, **기본 붕괴 속도를 낮춤**

**언급이 없는 것** — 위키 · 프레스킷 · 기사 · 리뷰 어디에도: **터널 · 아치 · 오버행 · 다리.** "속을 판다"는 문장이 없다.

**기술 추정** (공식 자료 없음 — 사양에서 역산)
GTX 950 / M1 내장 / 3GB 에서 도는 것은 대규모 입자 PBD 가 아니다. **하이트필드(2.5D) + 습도·다짐 필드 + 열침식형 처짐**으로 보는 게 맞다 —
우리 [system-design](../design/system-design.md) 의 **[A] 격자 계층만**. 그러면 "터널이 없다"가 설명된다: 하이트필드는 오버행을 원리적으로 못 만든다.

**우리에게 뜻하는 것**
- 장르 수요는 확인됐다 (16.5만 위시리스트 · 95%). "모래를 만지는 것 자체가 재미있는가"(M2 의 질문)는 남이 답해 줬다.
- **차별점은 [B] 입자 계층이다** — 터널 · 오버행 · 덩어리 붕괴. milestones 가 "타협 불가"로 둔 그것이고, M0-a 가 통과시킨 그것. Sandcastle 이 못 하는 것이 정확히 우리가 검증한 것이다.
- 반대로 [A] 계층(M3 격자 침식 · M5 조석)은 Sandcastle 이 이미 "짜면 된다"를 증명했다 — milestones 의 판단 그대로.
- **"붕괴 속도를 낮췄다"는 패치는 설계 신호다.** 플레이어는 무너짐이 *빠른* 것을 싫어했다. 우리 3-2 의 "버티다 갑자기"는 **ΔW 가 좁다**(문턱)는 뜻이지 낙하가 빠르다는 뜻이 아니다 — 두 축을 문서에서 갈라 둘 것 (m0-spike §3-2 판정에 각주).
- M2 도구 3종(파기 · 쌓기 · 물붓기)과 M6 의 형틀 · 다지기 · 깎기는 Sandcastle 도구와 그대로 겹친다. 도구로는 차별이 안 되고 **도구가 만드는 것(터널 · 오버행)** 으로 차별한다.

## 2-b. 입자끼리 상호작용하는 것 — 제작 도구와 연구 소프트웨어

> 제작 도구 6종의 원문 기준 상세는 **[tools.md](tools.md)** — 파라미터 대응표 · Flex 실측표 · 우리 설계에 돌아오는 것 7개.

Sandcastle 은 [A] 계층 게임이라 입자 상호작용의 기준점이 못 된다. 실제로 **입자 단위 모래를 돌리는 것**은 게임이 아니라 제작 도구(오프라인·준실시간)와 연구용 DEM 에 있다.
둘 다 우리 설계의 부품(PBD 접촉·마찰 · 점착 결합 · 모세관 다리 · 교정)을 **이미 제품으로 갖고 있는** 것들이라, "우리가 처음 하는 것"과 "남이 정해둔 관행"을 가르는 기준이 된다.

### 제작 도구 — PBD 알갱이 (우리 솔버와 같은 계열)

| 도구 | 방식 | 우리와 겹치는 것 | 다른 것 |
|---|---|---|---|
| **Houdini Grains / Vellum Grains** (SideFX, POP Grains) | **PBD** 하드 스피어. 두 가지 점착이 따로 있다: ① `Clumping/Attraction` — 가까우면 달라붙는 가중(자발적 재결합 있음) ② **Explicit Constraints** — 폴리라인으로 이은 **영구 결합**, `restlength`, 변형률 `strain`(시간에 따라 감쇠), **`Break Constraints` = 강도 문턱 넘으면 삭제**, `Remove Strands`. 마찰: 겹침 비례 · `Static Threshold`(속도/침투 비) · **`Accurate Friction` = 매 반복마다 마찰**. **`Mass-Shock Scaling`** = 위 입자를 가볍게 해 스택 안정화 | **우리 설계가 통째로 여기 있다.** 결합 = Explicit Constraints(영구·파단·재결합 없음), 마찰 = Accurate Friction(SP 의 매 반복 마찰), 스택 안정화 = 질량 스케일링(Tonge/shock). 문서가 명시하는 규칙 — **"반복 수는 쌓이는 높이에 맞춰라, 대략 더미 지름의 두 배"** (#35 의 경로 길이 규칙 그대로), **"최대 강성 ≈ 서브스텝 × 반복"**, "반복이 모자라면 제약을 덜 지킨 채 넘어간다" | 오프라인. `strain` 감쇠 = 우리에게 없는 **연화 가지**의 제작 도구판(Matter DPSoft 와 같은 자리). 아치·터널 검증 없음 |
| **NVIDIA PhysX 5 PBD Particle System** | GPU 전용 PBD. 유체 · **granular** · 천 · 팽창체 · 강체를 한 입자계로. `PxPBDMaterial`: friction · adhesion · cohesion · viscosity… 이웃 상한 96 | Flex(C1)의 후속이자 **게임 엔진에 실제로 붙는 유일한 GPU PBD 알갱이.** 3-4 통과선의 "남들은 얼마나" 비교 대상 | 점착이 `cohesion` 스칼라 — 결합 그물 · 파단 거리 없음. 우리 반복 120 짜리 그물은 여기도 없다 |
| Blender Molecular 애드온 | 입자 간 **링크(결합)** 생성·파단 | 우리 영구 결합 목록과 구조가 같다 (링크 = 우리 결합) | CPU. 느림 |
| Taichi (MPM/PBD 예제) | 연구용 GPU 커널 언어 | 프로토타입 검증용 | 엔진 밖 |

### 연구용 DEM — 젖은 모래의 물리를 **이미 구현한** 코드

| 소프트웨어 | 무엇 | 우리와 겹치는 것 |
|---|---|---|
| **MercuryDPM** (오픈소스) | DEM. **모세관 다리 모델 내장 — Willett 근사 + Bagheri 근사** (arXiv 2411.02042, 2024) | 우리 §2-6 ②④ 의 근거(Willett 2000 · Lian 1993)를 **코드로 갖고 있는 곳.** 형성·파단 거리 · 힘 곡선의 참조 구현 |
| **YADE** (오픈소스, Python) | DEM. `capillaryLaplaceYoung` — 모세관 압력과 구 기하에서 다리 힘·부피·범위를 계산 | 같은 자리. 삼축 시험(`CapillaryTriaxialTest`) 예제 = 젖은 모래 강도 교정 |
| **PFC** (Itasca, 상용) | **Bonded-Particle Model** — Potyondy & Cundall. 평행 결합이 통째로 끊어지는 파괴 | 우리 §2-6 ⑩ 이 인용한 결합 교정 관행의 **원산지.** "결합 = 슬롯 · 끊어지면 삭제 · 재결합 없음" 이 BPM 의 정의 그대로 |
| **LIGGGHTS** (오픈소스, LAMMPS 기반) | DEM. SJKR 점착 · Potyondy 결합 패키지 | Roessler/Katterfeld 교정 논문(dem-calibration.md)의 도구 |
| **Chrono::GPU / DEM-Engine** (오픈소스) | GPU DEM. Hertz + Mindlin 이력 마찰 + 구름 마찰 + 점착. **단일 GPU 로 마찰 2억 개** | "GPU 에서 DEM 이 얼마나 도나"의 상한. 반복 솔버가 아니라 명시적 적분(작은 dt)이라 비용 구조가 다르다 |
| Blaze-DEM (GPU) | 6천만 구 · 3,400만 다면체 (K40) | 같음 |
| **Matter** (papers C4 보충) | MPM. DPSoft 연화 | 이미 정리됨 |

### 여기서 읽을 것

- **"젖은 모래 = 접촉 + 끌림"은 업계 표준이고, "결합 = 영구 목록 + 파단 + 재결합 없음"은 지반공학(PFC BPM) 표준이다.** 그리고 **Houdini 는 둘 다 제품에 넣어 두었다**(Clumping 과 Explicit Constraints). 우리는 후자를 골랐고, 그 선택은 영화 파이프라인이 매일 쓰는 길이다.
- **Houdini 문서 한 줄이 #35 를 독립적으로 확인한다**: "반복 수는 쌓이는 높이에 맞춰라 — 대략 더미 지름의 두 배". 그리고 스택 안정화에 **질량 스케일링**(Mass-Shock Scaling)을 표준 파라미터로 둔다 — 우리 A′(Tonge)·C3 결론과 같은 자리. gather 가 결합에서 깨진 것(3단계)에 대한 업계의 답도 이것일 가능성이 크다: **반복을 높이에 맞추고, 위를 가볍게 한다.**
- **모세관 다리의 참조 구현이 두 개(MercuryDPM · YADE) 있다.** `breakStretch(W)` 를 구현할 때 손계산 대신 그 코드의 수식을 베끼면 된다 — 둘 다 오픈소스.
- 실시간 쪽에서 우리와 가장 가까운 실물은 **PhysX 5 PBD granular** 다. 그런데 거기도 결합 그물은 없다. 3단계에서 gather 가 결합에서 깨진 것이 "우리만의 문제"인 이유가 여기 있다 — 남들은 그 문제를 **안 풀었지, 푼 게 아니다.**
- Houdini 가 서브스텝 15 로 안정을 얻는다는 관행은 Müller 2020 계열(서브스텝↑ 반복 1)과 같고, 우리 #28 의 "서브스텝은 악화" 와 충돌한다 — 우리 브로드페이즈가 프레임당 1회라서다(#35). 다시 볼 값어치가 있는 축.

## 4. 논문 쪽 새 항목 → papers.md 에 넣을 것

**Chen, Ly, Wojtan (2025), "Numerical Homogenization of Sand from Grain-level Simulations", SIGGRAPH Asia / TOG, DOI 10.1145/3763344 — ISTA. 코드·데이터 공개.**
알갱이 **형태**를 알갱이 단위(DEM)로 시뮬레이션해 연속체 파라미터로 접는다. 형태별 거시 거동:
구(잘 구르고 미끄러짐 · 마찰 최소) → dolos(H 자, 마찰 약간↑) → hexapod(6발 · **마른 채로 응집된 더미** · 눌리면 되밀어냄) → dodecafang(12발 · 얽혀서 **충격에 강한 구조**).
**물 없이 형태만으로 "응집"이 나온다** — 마른 모래성 충격 시험까지 있다(젖은 점착은 안 다룸).
우리 #25·#34 의 "회전 없는 구는 기하 맞물림이 μ 위에 ~25° 를 얹는다 → μ 는 유효값" 이 정확히 이 논문의 축이고, 우리는 그 축을 μ 하나로 뭉갠 것이다. papers.md A-R 에 넣었다.

## 5. 결론 넷

1. **장르는 살아 있고 이미 실물이 있다.** 우리가 첫 번째가 아니다 — 두 번째가 첫 번째와 다른 점은 터널·오버행·덩어리 붕괴 하나다.
