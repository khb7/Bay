## 상태 (칸마다)

| 채널 | 뜻 | 형식 |
|---|---|---|
| `b` | 지형 높이 | float |
| `h` | 물 깊이 | float |
| `hu, hv` | 유량 (운동량) | float2 |
| `s` | 뜬 모래 농도 | float |

- KP07 은 칸 중심 `(h, hu, hv)` + 칸 경계(꼭짓점) 지형 `b`. 바닥 경사 항을 경계 지형에서 계산해 정지 수면이 유지된다 (well-balanced).
- 버퍼 = 풀드 구조 버퍼 두 벌 (핑퐁). 텍스처는 렌더 쪽 내보내기만.

## 패스 (한 서브스텝)

```
0. 도구 스탬프       b 에 파기 · 쌓기 (M2 스탬프와 같은 구조체) — T6
1. 파도 주입         바다 쪽 경계 = 리만 불변량 (나가는 R⁺ 안쪽 외삽 · 들어오는 R⁻ = 이봉 스펙트럼 32 성분 합, papers D-M3-5)
2. 재구성 + 유속     minmod 기울기 → 칸 경계 값, 마른 칸 u 특이점 제거 (KP07 식 2.17)
3. 경계 유량         central-upwind 유량 (x · y), 국소 파속 a = |u| ± √(gh)
4. 갱신              SSP-RK2 (두 단계) — Δt = 0.25·Δx / max a (CFL 1/4, KP07 정리 3.1)
5. 모래              Exner: (1−p)∂b/∂t = −∇·q,  q = A·|u|²u  (바닥 운반)
                     s: 침식 · 침강 (Kd > Ks → 침강 지연) · 반라그랑주 이류
6. 열침식            이웃 경사 > 안식각이면 아래로 (Jákó & Tóth 2011)
7. 내보내기          b, h → 렌더 텍스처 (WPO)
```
- CFL: 파속 최대 √(g·0.5m) + 3 m/s ≈ 5 m/s, 칸 5cm → Δt ≤ 2.5ms → **프레임당 서브스텝 6~7 번**. T5 에서 비용을 보고 칸 크기 · 영역을 정한다.

#### c4 설계 — 한 방향 nesting (사용자 결정 2026-10-29)
- **바깥 격자**: 같은 해변 단면을 Dean 으로 수심 3.3 m (Hm0/d < 0.3, H₀ 1 m) 까지 늘린 영역 ≈ 200 m. 칸 25 cm (x 800 칸 · y = 안쪽과 같은 L_y), 분산 켬, 주기 y. 처오름은 거칠지만 안쪽 경계에 들어가는 **들어오는 불변량 R⁻ 만** 쓰니 상관없다.
- **안쪽 격자**: 지금 5 cm 격자 그대로. 동쪽 리만 경계의 입사 (η, u_n, v) 를 바깥 격자의 경계 위치 값으로 (y 선형 · 시간 선형 보간 — 바깥은 프레임 먼저 진행, 앞 · 뒤 두 스냅샷). 바깥 상태의 R⁻ 는 해안 쪽으로 가는 파만 실으므로 안쪽에서 나간 파와 겹치지 않는다 (한 방향).
- **바깥 경계 입사**: 선형 성분 + 묶인 IG 쌍 합 (32 성분 → 496 쌍, CPU 가 미리 계산). 입사 유속 = 분산 위상속도 c = ω/k (분산 켤 때). 해안선 방향 유속 부호 바로잡음 (진행 +y 면 v > 0, 연속식).
- **묶인 IG 계수 D**: 문서 (XBeach) 식을 옮긴 것이 LHS 얕은 물 극한과 수백 배 어긋남 (옮김 · 부호 규약 확인 불가) → **LHS (1962) 복사 응력 평형 해를 방향으로 일반화**: η̂₃ = −K_iK_jŜ_ij/(ρ(ghK² − Ω²)), Ŝ_ij = ρg a₁a₂[n·(k̂₁⊗k̂₂ 대칭) + (n − ½)δ_ij] → D = −g[n(K·k̂₁)(K·k̂₂) + (n − ½)K²]/(ghK² − Ω²), K = k⃗₁ − k⃗₂, Ω = ω₁ − ω₂. 같은 방향이면 LHS 와 같다. 유속 u⃗₃ = η₃Ω K⃗/(hK²) (연속식).
- **분산 · 경계**: 열린 경계 쪽 몇 칸에서 d → 0 으로 줄임 (얕은 물 · 리만 경계와 맞게). 주기 y 는 y 줄 삼중대각을 Sherman–Morrison (PCR 두 우변) 으로.
- 검증: (1) 바깥 격자만 — 경계 근처 IG 수위 vs 파군 포락선 (음의 상관 · 크기 = D), 반사 몇 % (2) nesting — 안쪽 경계 수위가 바깥 같은 위치 수위와 맞음, 안쪽에서 나간 파가 다시 안 들어옴.

#### c6 지하수 · 침투 (사용자 결정 2026-10-30, papers D-M3-12) — M5 지하수를 앞당김
#13: 침투가 없어 물러난 뒤 막이 남고 그 위에서 처오름을 재 setup 과대. 간이 침투 대신 정식 (XBeach gwnonh=0 · Brakenhoff 2019 구조).
- **상태**: 칸마다 `Gw` = (η_gw 지하수면, δ 습윤 전선 깊이). 대수층 바닥 z_aq = 격자 최저 바닥 − 1 m (Raubenheimer 1999: 두께 영향 작음). 처음 η_gw = min(B, SeaLevel).
- **연결**: 칸이 젖어 있고 (h > HDry) η_gw ≥ B − ε → 연결. 수두 H = 연결이면 지표 수위 w, 아니면 η_gw. 포화 두께 h_gw = min(H, B) − z_aq.
- **패스 (서브스텝 끝, FixCS 뒤)**: ① `GwFluxCS` — 면 Darcy q = −K·h̄_gw·ΔH/Δ (면 평균 두께), 칸 순유입 Q (m/s) · ② `GwApplyCS` — 연결: w += Q·Δt (지표와 교환, η_gw = B 고정) · 연결 안 됨: n_e·Δη_gw = Q·Δt, 물 덮이면 침투 f = K(1 + (h+ψ)/δ) ≤ h/Δt, w −= fΔt, η_gw += fΔt/n_e, δ += fΔt/n_e (물 없으면 δ = 0) · η_gw > B 면 넘친 n_e·(η_gw − B) 를 지표로 (침출). 지표에서 물이 빠질 때 hu, hv 는 같은 비율로 (속도 유지).
- **파라미터 (입도 표준값, 측정에 안 맞춤)**: K 5e-4 m/s · ψ 0.05 m · n_e 0.3. 명시 안정 Δt 0.075 s ≫ 서브스텝. 바깥 nesting 격자엔 끔.
- **검증**: (1) 닫힌 상자 질량 보존 Σ(h + n_e·(η_gw − z_aq)) 변화 < 1e-4 상대 · (2) 지하수면 계단 (지표수 없음) → 선형 확산 D = K·h_gw/n_e 의 erf 해 ±5% · (3) 마른 모래 위 웅덩이 → Green–Ampt 누적 침투 F(t) (CPU 상미분) ±5% · (4) #13 재측정: 막 사라짐 (젖은 시간 < 100%), setup 문턱 민감도 줄고 Stockdon · Guza–Thornton 과 비교, swash 변화.

#### c7 구역 바닥 마찰 (papers D-M3-13/14, #15 진단 뒤)
#15: swash 부족은 쇄파대 마찰 (n 0.025 → c_f 0.006~0.008, 관측 0.0007~0.006 위 끝) 탓. swash 구역은 현장 c_f 0.03 과 맞는 0.025 유지.
- **쇄파대 n = Strickler 낟알 값** d50^⅙/21.1 (SI, = 0.047·d50^⅙). d50 0.3 mm (중간 모래 — c6 의 K 5e-4 m/s 와 같은 모래) → n 0.0123, c_f 0.0015~0.0025 (h 1~0.2 m). 쇄파 난류는 Boussinesq 쇄파 소산이 맡으므로 마찰에 더하지 않는다. `-d50=` (mm). 바깥 nesting 격자도 같은 n.
- **swash 구역 경계 = 되밀림 한계**: 최근 120 s 안에 한 번이라도 마른 칸 (h ≤ 1 mm) 이 있는 열 중 가장 바다 쪽 (#15 의 "젖음 비율 < 100%" 와 같은 정의). 120 s = 가장 긴 IG 주기 (~100 s) 보다 길게. CPU 가 다운로드한 수위로 0.1 s (측정) · 매 프레임 (화면) 갱신 → `SetFricX`. 시작값 = 처음 물가선 (setup 전).
- **검증**: #15 기본과 같은 조건 (900 s, -nest) — setup · S_inc · S_IG · R2% vs Stockdon, 경계 x 가 #15 의 4.5 m 근처인지. `-onefric` 은 구역 없이 한 값.

#### c8 쇄파 지속 (papers D-M3-17, #18 뒤)
#18: 안쪽 쇄파대 SS H_rms/h ≈ 0.9 (포화 0.42 의 2 배). Tonelli & Petti 원 정의는 시작 후 종료 기준까지 유지하는데 우리는 순간 칸 판정만.
- **칸별 쇄파 상태 `Brk`** (지속 버퍼): ε = |η − SeaLevel|/h. 꺼져 있으면 ε > 0.8 에서 켬, 켜져 있으면 ε < 0.3 에서 끔 (Bacigaluppi 2019 의 영역 기준 0.3 · 종료 범위 0.55~0.25 안). 켜진 칸은 d = 0 (NSW). 바깥 · 안쪽 격자 둘 다. `-breakstop=0` 이면 이전 방식.
- 하지 않음 (이번): 아래쪽 영역 확장 (2D 에서 파 진행 방향 필요) — 지속만으로 부족하면 다음.
- **검증**: f10row 와 같은 조건 — SS H_rms/h 단면 · setup · S_inc · S_IG · R2%.

- **검증**: 바깥 격자 → 안쪽 경계 Hs/h (#19 1.36), 안쪽 SS H_rms/h (0.9 → 0.42 쪽), setup · S_inc · S_IG · R2%. 좋으면 기본값으로.

#### c9 마무리 (사용자 결정 2026-11-03, m3-log #23~#29 · papers D-M3-20~22)
- **기본값**: FUNWAVE-TVD breaker.F 식 와점성 (나이 · 위쪽 이웃 번짐, ν = h·0.15√(gh), T_brk = 너울 주기) + **시작 γ 0.3** (MS92 덜 천수 보정 — 같은 MS92 의 Bacigaluppi 2019 값). roller 넓힘 (`-breakroller`) 은 효과 없어 끔.
- 결과 (f32): setup 1.01 · S_IG 0.92 · R2% 0.90 — Stockdon 오차 안. **S_inc 0.63** 은 남음.
- **남은 문제 (보류)**: 바깥 격자 소산 부족 → 안쪽 경계 입사 Hs/h 1.18 (문헌 기대 ~0.74, Raubenheimer 1996 회귀 계수 원문 미확인). 원인: MS92 덜 천수로 앞면이 충격파가 안 돼 TVD 수치 소산 몫이 없음, 정적 ν 만으로 부족. 다시 열 때 후보: (1) 하이브리드 전환 재시도 — FUNWAVE `masks.F` · `etauv_solver.F` 줄 대조 (FUNWAVE 기본, #20 · #21 2D 붕괴 원인부터) · (2) 완전비선형 (Wei 1995 / SGN) · (3) TKE 1 방정식 (Kazolea 2018, κ · σ 경우별).

#### p1 최적화 — 동기 대기 제거 (사용자 결정 2026-11-03, m3-log #30 · #31)
- 문제: 매 `Run` 이 `SubmitAndBlockUntilGPUIdle` + `FlushRenderingCommands` → CPU 가 격자마다 GPU 끝까지 대기 (~6 ms/프레임). 서브스텝 수의 최대 파속을 동기 `Download` 로만 받아, 게임 경로의 바깥 격자는 늘 최대 64 서브스텝 (읽지 않음).
- 근거 (논문 아닌 엔진 API): RDG 제출 뒤 기다리지 않음 · `FRHIGPUBufferReadback` 링 (3 개) 에 시간 버퍼 (16 B) 를 매 Run 끝에 복사, 다음 Run 시작에 `IsReady()` 인 것만 읽음 · 타임스탬프 쿼리도 링, `RHIGetRenderQueryResult(…, bWait=false)`.
- 영향: 서브스텝 수가 1~3 프레임 전 최대 파속으로 정해짐. 안정성은 그대로 (GPU 가 서브스텝마다 Δt 를 그 순간 CFL 로 자름). 파속이 갑자기 커지면 그 프레임 시뮬 시간이 조금 늦을 뿐 — 지금도 있는 동작.
- 검증: `-puretime` 프레임 시간 · 기본 900 s 통계 (setup · S_inc · S_IG · R2% · 경계 Hs/h) 가 #28 f32 와 같은지.
- 남김: 게임 `UpdateWaterMesh` 의 매 프레임 전체 `Download` (CPU 메시) — 렌더 경로를 GPU 로 옮길 때 (별도 단계).

#### p2 최적화 — 바다 쪽 입사파 캐시 (사용자 결정 2026-11-03, m3-log #31)
- 문제: 유령 칸 `Fetch` 마다 (면당 최대 6 번) `IncidentWave` 528 성분 cos · sin — 경계 열 스레드만 길어 FaceX 패스를 붙잡음 (FaceY 의 18 배).
- 방법 (GPU 관행: 반복 계산 꺼내기 · 작업 불균형 해소): FaceX 전 `IncCS` (줄마다 그룹 하나, 64 스레드가 성분을 나눠 합, 공유 메모리 줄임) → `Inc` 버퍼. 같은 식 · 같은 단계 시각 — 결과 같아야 함. 안쪽 (nesting) 은 `NestWave` 보간이라 그대로.
- 함께: 비동기 링이 차면 가장 오래된 readback 까지 대기 (CPU 가 GPU 보다 최대 3 프레임 앞섬) — p1 뒤 CPU 가 수백 프레임 앞서 임시 버퍼가 쌓여 E_OUTOFMEMORY.

## 하지 않는 것
- 입자 ↔ 격자 결합 (파도 하중 · 장애물 · 파괴 환원) — M4. 참고 문헌은 D-M3-1 (Chentanez & Müller 2010).
- `W` · 증발 · 표면 수분 — M5 (F · E 절). 지하수면 · 침투는 c6 에서 앞당김. 침투가 둔덕을 만드는 효과는 M5 (지형 결합).
- 쇄파의 말리는 모양 (plunging) · 물보라 — 얕은 물은 bore 로만 표현한다. 시각 효과는 M8.
- 쇄파 전 분산 (Boussinesq) — 필요하면 바깥 바다만 다른 방법으로.
