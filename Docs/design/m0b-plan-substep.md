# M0-b 서브스텝 계획 — "작은 스텝 여러 번 × 적은 반복"

> 2026-10-25. 근거: [papers.md C6](../research/papers.md) (Macklin 2019 Small Steps) · m0-log #44 (깊은 기둥이 안 멈춘다).
> 위에 얹는 것: A안 단계 2 (`-gpu2 -color8par -block=15`). A안 단계 3 판정(#43)은 이 계획 뒤로 미룬다.

## 0. 문제와 가설

- #44: 5만(37층)은 반복 120 에서도, 2만(27층)은 반복 60 에서 25초 내내 끓는다 (|v| 10~60, 쌍/입자 18 — 정지면 3). 2만 · 120 만 멈춘다.
- **가설 H1 (깊이-수렴)**: GS 의 오차 보정은 국소 전파라 층 깊이만큼 반복이 필요하다. 모자라면 아래층 침투가 남고, 다음 프레임 `Kc/h·gap` 이 그것을 분리 속도로 바꿔 튕긴다 → 끓음.
- C6 의 처방: 반복을 서브스텝으로 바꾼다. 서브스텝 하나에서 중력이 만드는 침투가 Δts² 로 줄어 매 서브스텝 풀어야 할 오차 자체가 작아진다.
- **대안 가설 H2 (버그)**: GPU 경로 고유 결함. 서브스텝과 별개로 CPU 대조(S0-c)로 가른다.

## 1. 우리 솔버에 옮길 때 — 무엇이 바뀌나

| 항목 | 지금 (서브스텝 1) | 서브스텝 n |
|---|---|---|
| 이웃 탐색 · 쌍 생성 · 블록 정렬 · 배치 나누기 | 프레임당 1 | **그대로 프레임당 1** (C6 Alg.1, 우리 #3.5) |
| 워밍 (접촉 λ → 임펄스) | 프레임 시작 1 (`PairScatterCS`) | 첫 서브스텝은 그대로, **2번째부터 `SubstepWarmCS`** — 같은 자리 λ 를 같은 규칙(닿은 쌍만 · 접평면 재투영 · 원뿔)으로 다시 |
| 결합 워밍 | `BondWarmCS` 1 | 서브스텝마다 (몸체 그대로, `StepDt` = Δts) |
| 예측 · 지면/벽 워밍 | `WarmPredictCS` 1 | 서브스텝마다 |
| 반복 (색 8 + 결합 + 지면) | 120 | 서브스텝마다 k (n·k = 총 횟수) |
| `StepDt` (접촉 `Kc/h` · 결합 α̃ · 지면) | Δtf | **Δts = Δtf / n** — 셰이더는 이미 매개변수로 받는다 |
| 결합 파단 · 통계 | 프레임 끝 1 | 그대로 |
| 속도 감쇠 | 프레임 1 | Δts 로 환산해 서브스텝마다 (감쇠율이 n 에 안 묶이게) |

- **λ 단위**: 우리 λ 는 서브스텝 하나의 임펄스다. 서브스텝 길이가 같으면 워밍 비율 1.0 그대로. 프레임 사이 n 이 바뀌면 `n_old / n_new` 를 곱한다 (도구 조작 중 n 을 바꾸지 않으면 무관).
- **CPU 경로는 이미 이 구조다** (`FSandSpike::Step`: 접촉 목록 프레임당, 서브스텝마다 워밍·예측·반복, λ 범위 = 서브스텝). 그래서 CPU 로 먼저 물리를 본다 — GPU 는 이 구조를 옮기는 일이다.

## 2. 위험

| 위험 | 내용 | 대응 |
|---|---|---|
| R1 튕김 | Δts 가 작을수록 `Kc/Δts · gap` 이 커져 침투가 큰 분리 속도가 된다 (C6 §4.3) | 끓음이 늘면 C6 식 10 — 서브스텝당 분리 속도 상한 v_max (`gap` 을 `min(gap, v_max·Δts)` 로). 스위치 `-vmax=` |
| R2 크리프 | 서브스텝마다 워밍·마찰 원뿔 재절단 → 마른 더미 크리프가 변할 수 있다 (#24 · #36) | 관문에 더미 크리프 포함 |
| R3 감쇠 감소 | 수치 감쇠가 줄어 정지가 늦어질 수 있다 (C6 §4.1) | 정지 시간을 같이 기록. 필요하면 감쇠 환산 확인 |
| R4 탐색 반경 | 접촉 집합 고정 → 프레임 중 새 접촉은 다음 프레임. 탐색 상한 2R (이미 미결) | 서브스텝과 무관하게 같다. 붓기 낙하는 기존과 같은 조건 |
| R5 비용 | 서브스텝당 고정 패스 ~4 개 (워밍 2 · 예측 · 결합 워밍) ≈ 40 µs | n ≤ 8 이면 ≤ 0.3 ms. 총 반복이 같으면 비용 거의 같다 — **이득은 총 반복을 줄일 수 있는 것** |
| R6 GS 순서 | 색 회전은 프레임 번호 기준 → 서브스텝마다 같은 순서 | 회전을 (프레임 · n + 서브스텝) 으로 |

## 3. 단계와 관문

### S0 — CPU 로 물리 확인 (코드 거의 없음, 반나절)

기존 CPU 경로 `-color8 -substeps=n` (단계 0 CPU 8색 GS 모사). 조합 = 총 120 을 나눈 것 + 총을 줄인 것:

```
(n × k)   1×120 (기준) · 2×60 · 4×30 · 8×15     · 4×10 · 8×5   (총 40)
```

- **S0-a 깊은 기둥**: `-perf` 에 `-substeps=` 를 받게 하고 (CPU, 1줄), 2만(27층) 1500프레임 `-window=100`. 지금 GPU 에서 1×60 이 끓는 장면이다. **관문: 4×30 · 8×15 가 정지 (쌍/입자 ≈ 3, |v| < 0.5) — 1×60 은 끓는 것을 CPU 에서도 재현.**
  - 1×60 이 CPU 에선 멈추면 → H2 (GPU 결함) 쪽. 서브스텝과 별개로 GPU 를 먼저 고친다.
- **S0-b 기존 관문 셋**: 터널 원형 30cm · 더미 시드 3 · 절토 60~90, 조합 {1×120, 4×30, 4×10}. 통과선은 단계 0 과 같다 (터널 < 5% · 크리프 ≤ 0.005 · 침하 0 · H_c 84~95).
- S0 결과로 **n · k 를 정한다** — 가장 적은 총 반복으로 S0-a · S0-b 를 다 통과하는 조합.

### S1 — GPU 구현 (1~1.5일)

1. `FSandGpuFrameParams::Substeps` · `-substeps=` 를 `-gpu2` 에 연결 (지금 `checkf(Substeps == 1)` 제거).
2. `FSandGpuSim::Step`: 프레임 앞(탐색·쌍·정렬·`ColorBatchCS`) 1회 → `for s < n { (s>0 ? SubstepWarmCS : -) · BondWarmCS · WarmPredictCS · AddSolverIterations(k) }` → 파단·통계 1회. `StepDt = Δts`.
3. `SubstepWarmCS` (SandFrame.usf): 정렬 자리 기준, `PairScatterCS` 의 워밍 몸체를 함수로 빼서 공유 (식이 둘로 갈라지지 않게).
4. 결합 α̃ (`BondAlphaTilde`) 와 감쇠를 Δts 로 — CPU 쪽 `StepGpuResident` 에서 계산.
5. 색 회전 인덱스 = 프레임 · n + s.
6. (R1 이 나오면) `-vmax=`.

### S2 — GPU 관문 (반나절 + 측정)

- S0-b 와 같은 셋을 `-gpu2 -color8par -substeps=n -iterations=k` 로. 수치가 CPU S0 과 같은 경향이어야 한다.
- 깊은 기둥 2만 · 5만 `-perf -window=100 -frames=1500` (마른 · 젖음). **관문: 5만이 멈춘다.**
- 동시 1개 (#41 TDR).

### S3 — 성능 판정 (#43 재개)

- 5만 정지 상태 · 다짐 중, 총 반복 {40, 60} 의 ms. 통과선 **활성 5만 · ≤ 16 ms** (2026-10-25).
- 예상: 반복당 ≈ 0.9 ms @5만 다짐 중 (#43) → 총 40 이면 ~36 ms, 정지 상태(쌍 1/6)면 그 0.4배 ≈ 15 ms. **정지 상태에선 닿을 수도, 다짐 중엔 못 닿는다 → C안(재우기)은 여전히 필요할 공산.**

## 4. 분기

- S0-a 에서 서브스텝도 끓는다 → H1 기각. 끓음의 원인을 따로 판다 (침투 → 분리 속도 경로 계측, v_max 시험).
- S0-a 에서 CPU 1×60 이 멈춘다 → H2. GPU 경로 버그부터 (같은 시드 CPU/GPU 첫 100프레임 대조).
- S0-b 에서 터널/절토가 서브스텝에서 무너진다 → 결합 α̃ 환산·파단 문턱 점검 (파단은 프레임 끝 늘어남 기준이라 n 과 무관해야 한다).
