# M0-b — GPU 이식: 같은 답이 나오는가 (초안 2026-09-14)

> 상위 순서는 [milestones.md](milestones.md), M0-a 의 결과는 [m0-a-result.md](m0-a-result.md),
> 문헌은 [papers.md §C5](../research/papers.md). 이 문서는 **"GPU 로 옮겨도 M0-a 의 다섯 답이 유지되는가, 그리고 예산 안에 드는가"** 만 다룬다.

---

## 0. 이 문서의 지위 — 성능 스파이크가 아니다

milestones 는 M0-b 를 "답이 예면 GPU 로 옮긴다 (RDG 첫 접촉)" 한 줄로 두었다. 그 한 줄이 숨기는 것:

**M0-a 의 모든 통과는 GPU 에 그대로 못 올라가는 솔버로 얻었다.** m0-log #9 에서 Jacobi 도 GS 도 실패했고,
#11 에서 Sequential Positions 로 바꿔서야 34° 가 닫혔는데, 지금 SP 는 **제약마다 즉시 적용하는 순차(GS) 순서**다
(`SolveContactsSP`). GPU 는 그 순서를 못 지킨다.

그래서 M0-b 의 첫 질문은 "GPU 가 빠른가" 가 아니라 **"병렬형에서 34°·터널·붕괴가 유지되는가"** 다.
성능은 그 다음이고, M0-a 와 달리 여기서는 **차단**이다 (m0-spike §4: 성능(M0-b) 못 넘으면 M1 착수 금지).

```
M0-a   물리가 맞는가         CPU 단일 스레드 · 순차 솔버
M0-b   같은 물리가 GPU 에서   병렬 솔버 · 예산 안에서          ← 이 문서
M1     보이는가
```

## 1. 무엇을 만드는가

```
GPU 코어 하나 (RDG 컴퓨트)
  FSandSpike 와 같은 인터페이스 — Init / Step / GetPositions / FormBonds / ReleaseWalls …
  정렬 기반 공간 해시 (system-design §4 의 4단계)
  SP 제약 셋 (접촉 · 결합 · 마찰) + 지면 · 벽, 전부 gather 형
  λ 워밍 (접촉 · 결합 · 지면 · 벽) — 쌍 ID 슬롯
  리드백: 위치 전량 (계측용. 출하 경로는 M1 의 36KB)
```

**배치 하네스는 새로 만들지 않는다.** `-pour` `-tunnel` `-ramp` `-cut` 이 그대로 CPU 대조군이고,
GPU 코어를 같은 인터페이스 뒤에 넣으면 **같은 명령에 `-gpu` 만 붙여** 돈다. M0-a 의 "배치와 실시간이 같은 코어" 원칙(§2-1) 그대로.

## 2. 공통 뼈대

### 2-1. 대조 규약 — 바이트 재현은 포기한다

m0-spike §2-3 의 "같은 입력 → 같은 CSV 바이트" 는 GPU 에서 성립하지 않는다 (원자 연산 · 리덕션 순서).
대신 **M0-a 가 이미 잰 산포를 허용 오차로 쓴다.**

| 양 | 허용 오차 | 근거 |
|---|---|---|
| 안식각 (프로파일 · 법선중앙) | **±1°** | 시드 산포 (#28) |
| 터널 판정 | **같은 판정** (원형 30 섬 · 사각 30 붕괴 · 대조군 붕괴) | #32 |
| 덩어리 붕괴 `ΔW` | **±0.01** | #33 0.012 vs #35 0.019 |
| 절토 `H_c` | **한 단(10cm) 이내** | #35 D |
| 크리프 · 하중비 · 불평형비 | 같은 자릿수 | #35 A |

> ⚠ **μ 재교정은 허용한다.** μ 는 예산 의존 유효값이다(#35). 병렬형이 μ 0.15 에서 33° 를 내면 그건 실패가 아니라 재교정 대상이고,
> **재교정한 μ 로 터널·붕괴·절토가 유지되는가** 가 판정이다. 각도만 맞추고 결합 시험이 깨지면 실패.

**같은 입력 두 번** — GPU 끼리도 위 오차 안에 들어야 한다. 안 들면 결정성 문제가 따로 있다 (3-3).

### 2-2. 자료구조 — 결정은 되어 있고 검증만 남았다

| | 결정 (system-design §4) | M0-b 가 확인할 것 |
|---|---|---|
| 레이아웃 | SoA. 정렬 후 입자 데이터 재배치 | 재배치가 λ 슬롯 · 결합 목록 · 고정 입자 마스크를 같이 옮기는가 |
| 이웃 | 셀 키 해시 → radix 정렬(20비트 5패스) → 셀 범위 → 27칸 | 정렬 1회/프레임, 반복 120 이 재사용. 셀 크기 = 지름 |
| 접촉 λ | **쌍 ID `(min,max)` 해시 슬롯** — 정렬이 인덱스를 바꾸므로 | 슬롯 충돌률 · 미스율. 미스 = 차가운 시작 = 크리프 |
| 결합 | 입자당 **12 슬롯** 고정 배열 (#29 넘침 0~1) | 영구 목록이 재배치를 견디는가 |
| 벽 · 지면 λ | 입자당 스칼라 (벽은 벽별 4개, #29) | — |
| 잠든 타일 | 정렬 입력에서 제외 | M0-b 에선 타일 하나. 제외 경로만 자리를 잡아 둔다 |
| 정밀도 | float. double 없음 | 60m 월드에서 입자 지름의 1/7000 — 문제 없음 |

### 2-3. CPU 기준선 — 이미 있다

```
60 ns / 입자·반복   (단일 코어, 3000개, 붓기+정지+유지 평균, #35 E)
20만 입자 × 반복 120 = 1.44 s / 프레임
```

**GPU 는 이 위에서 ≥ 90배**를 내야 16 ms 다. 여기가 3-4 의 통과선이 된다.

## 3. 검증 넷

### 3-1. ★ 병렬형 물리 동등성 — 차단

**갈래 A (Frâncu §7 gather) 부터.** 이유 셋: 지금 코드의 IJ 항(`PrevDLambda`)이 이미 있다 · 순서 무관이라 결정성이 공짜다 · 컬러링 패스가 없다.

> ⚠ **논문이 보여준 SP 는 전부 SP-GS 다** (Fig. 8·10 범례 "Sequential Positions using GS"). SP 를 gather 로 돌린 결과는 논문에 없다.
> 즉 갈래 A 는 논문의 두 조각(IJ 접촉 · SP-GS 마찰)을 **우리가 처음 합치는 것**이고, 그래서 GPU 전에 CPU 에서 먼저 돌린다.
> 논문의 힌트: 접촉 단독 IJ 도 "항상 GS 보다 낫진 않아 a=2 로 조정"했고, 반복이 아주 낮으면 "ω 와 b 를 더 낮춰라". `a` `b` `ω` 가 3-1 ① 의 재교정 축에 μ 와 함께 들어간다.

#### 배치

CPU 코드에 **gather 스위치**를 먼저 넣는다 (`bGatherApply`). GPU 를 짜기 전에 CPU 에서 "즉시 적용 → 모아서 적용" 만 바꿔 M0-a 를 다시 돈다.
이게 통과하면 GPU 이식은 **같은 알고리즘의 구현 문제**로 줄고, 실패하면 GPU 를 짜기 전에 갈래를 바꾼다.

**결정 — 제약 종류별 gather (type-sequential).** 한 반복 안에서 `접촉 → 결합 → 지면 → 벽` 순서는 지금과 같게 두고,
**각 종류 안에서만** "전부 계산 → 한 번 적용" 으로 바꾼다. 종류 사이에는 갱신된 v·x 를 본다.
- 논문의 두 패스(모든 제약 → 모든 입자)보다 지금 코드에 가깝고, GPU 에선 반복당 디스패치 4쌍 — 종류 안이 순서 무관이면 충분히 병렬이다.
- 이게 통과하면 그 다음에 "종류까지 합친 완전 Jacobi" 를 한 번 더 돌려 차이를 본다 (정보성). 실패하면 완전 Jacobi 는 안 본다.
- CPU 구현: 인접 리스트 없이 패스 1 에서 `Delta[i]` 에 누적, 패스 2 에서 적용 — 옛 Jacobi 경로의 배열을 그대로 쓴다. 결과는 인접 리스트 gather 와 같다.

**스윕은 단계로.** 축이 다섯(μ · ω · a · 워밍 비율 · 시드)이라 한 번에 돌리면 108 실행이다.
```
1단계   μ {0.15, 0.17} × SorOmega {0.5, 0.7, 1.0} · a 1 · 워밍 1.0 · 시드 3      18 실행 → 34° 가 나오는 (μ, ω) 가 있나
2단계   그 (μ, ω) 에서 워밍 {0.25, 0.5, 1.0} × a {1, 2} · 시드 3              18 실행 → 3-2 겸함
3단계   최종 조합으로 -tunnel · -ramp · -cut                                    결합 시험
```

```
① CPU gather   -pour 3000 · 시드 3 · 반복 120 · μ {0.15, 0.17}     → 34° 가 어느 μ 에서 나오나
               -tunnel 30 원형·사각 · -ramp · -cut               → 그 μ 로 유지되는가
② GPU gather   같은 명령 + -gpu                                   → ① 과 2-1 오차 안인가
```

#### 판정

2-1 의 표 그대로. **①이 실패하면 ②를 시작하지 않는다.**

#### 실패 분기

```
①에서 각도가 안 맞음 (μ 재교정으로도)   → A′ 질량 분할 (Tonge 2012) — 유효 질량만 접촉 수로 나눈다
①에서 각도는 맞는데 터널이 무너짐       → 반복 상향 시도 (120→180→240). 그래도 안 되면 먼저 **결합만 클러스터 컬러링**(접촉은 gather 유지, Ton-That 2023).
                                          그래도 안 되면 GS 수렴을 되찾는 두 카드 중 하나:
                                          A″ 블록 솔버 (블록 안 GS · 경계 Jacobi. 256입자 ≈ 30cm = 아치 경로) — 우리 문제 크기에 맞음. 구현 무거움
                                          B  컬러링 (Vivace) — 전역. 구현 가벼움. 결정성을 따로 사야 함
A″·B 도 안 됨                          → C 순서 (충격 전파) 를 그 위에 얹는다. ⚠ C3 의 벽 셋(아치가 근사의 실패 지점 · 무한 질량) — 마지막 카드
②가 ①과 다름                          → 구현 결함. 물리가 아니다 — 쌍 ID 미스율 · 정렬 재배치 누락부터
```

> ⚠ **B 로 가면 결정성(3-3)을 따로 사야 한다.** 무작위 컬러링은 시드를 고정해도 GPU 스케줄에 따라 배치가 달라질 수 있다.

> ★ **접촉과 결합을 다른 솔버로 가르는 길** (Ton-That 2023, papers C5 A″-b). 결합은 **정적 그래프**(영구 목록, `FormBonds` 때만 바뀜)라
> 클러스터 컬러링을 전처리로 한 번 하면 되고, 접촉은 매 프레임 바뀌니 gather 로 둔다. 반복 120 을 요구한 건 결합 그물이었으니(#35 B),
> 결합만 GS 급 수렴을 사고 접촉은 Jacobi 30 으로 두면 #35 의 "접촉/결합 예산 분리"와 같은 절단선이 솔버형에서도 성립한다.
> A 가 결합에서만 깨질 때의 **첫 분기**로 둔다 — A′·A″·B 보다 먼저.
> ⚠ **색 = 동기화 지점.** 색 6개 × 반복 120 = 프레임당 720 회 동기화. 디스패치로 하면 런치 오버헤드만 7~14 ms 라 불가 —
> **타일(워크그룹) 하나 안에서 groupshared + 배리어로** 색을 넘겨야 한다. 즉 A″-b 는 A″(블록) 위에서만 성립한다. 두 카드는 하나다.
> 결합은 끊어지기만 하므로(재결합 없음) **색은 `FormBonds` 때 한 번 계산하면 파단 뒤에도 유효** — 제약을 빼는 것은 컬러링을 깨지 않는다.

### 3-2. 워밍 스타트의 GPU 형태 — 차단

M0-a #24: 워밍 없으면 크리프 0.08 cm/s, 각도가 μ 가 아니라 반복 수를 따라간다. 선택이 아니다.
그런데 Frâncu §7 은 "Jacobi 에선 워밍이 GS 만큼 극적이지 않다" 고 한다. **둘 중 어느 쪽인지 여기서 갈린다.**

#### 배치

3-1 ① 의 CPU gather 에서 워밍 **비율 스윕 {0, 0.25, 0.5, 1.0}** (`WarmStart` 는 이미 비율이다). GPU 에선 쌍 ID 슬롯의 **미스율**을 같이 찍는다.
Frâncu §7 원문: Jacobi 에선 "직전 승수의 더 낮은 비율을 써야 했고, 떨림·불안정을 막으려 파라미터를 손봐야 했다" — **1.0 이 아니라 부분 워밍이 기본값일 수 있다.**

#### 판정

| 결과 | 뜻 |
|---|---|
| gather + 워밍 off 에서 크리프 재발 | #24 그대로. 쌍 ID 슬롯이 필수 — 미스율 < 1% 목표 |
| gather 에선 워밍 없어도 크리프 없음 | Frâncu 가 맞다. 슬롯을 빼도 된다 — 자료구조가 가벼워진다 |
| 1.0 에서 떨림, 0.25~0.5 에서 안정 | Frâncu §7 그대로. 부분 워밍이 기본값. 슬롯은 필요 |

### 3-3. 결정성 — 정보성 (B 갈래면 차단)

같은 입력 · 같은 시드로 GPU 두 번. 2-1 오차 안이면 통과. **바이트 일치는 요구하지 않는다.**
A 갈래는 원리상 순서 무관이라 통과가 기대값이고, 안 되면 리덕션(불평형비 · 하중 검산 계측)이 범인이다 — 물리가 아니라 계측.

### 3-4. ★ 성능 — 차단

#### 배치

입자 수 스윕 `{2만, 5만, 10만, 20만}` · 반복 120 · 정지 상태 100프레임 평균. **정렬 / 이웃 / 제약 / 리드백** 을 따로 잰다.
기준 GPU 를 문서에 적는다 (미결 — 개발기의 것으로 시작).

#### 판정

```
통과   20만 · 반복 120 · ≤ 16 ms          (성 10채 정의 유지)
조건부  20만이 16~33 ms                      → 접촉/결합 예산 분리 (#35 판정: 접촉 30 · 결합 120) 로 재측정
실패   분리 뒤에도 33 ms 초과               → 입자 예산 축소 = 성 채수 축소. milestones 의 "성 크기 제한" 분기
```

> 스케일링 지수가 1 을 크게 넘으면 성능이 아니라 **버그**다 (m0-spike §3-4 와 같은 규칙). #35 의 CPU 초선형(8.4→30.5 µs/입자)은 미해명 — GPU 에서 재현되면 해시 쪽부터.

#### 부수 산출물

- 정렬 : 이웃 : 제약 : 리드백 비율 → M1 이 위치 리드백을 어디에 끼울지
- 반복당 ms → 접촉/결합 분리의 이득 추정

## 4. 정족수와 진행 규칙

| 검증 | 등급 | 막는 것 | 실패 시 |
|---|---|---|---|
| 3-1 병렬형 동등성 | **차단** | 3-2 · 3-4 · GPU 구현 자체 | 갈래 A → A′ → (A″ 또는 B) → C |
| 3-2 워밍 GPU 형태 | **차단** | 3-4 | 쌍 ID 슬롯 설계 재검토 |
| 3-3 결정성 | 정보성 (B 면 차단) | — | 계측 리덕션 수정 |
| 3-4 성능 | **차단** | **M1 착수** | 접촉/결합 분리 → 성 채수 축소 |

**순서: 3-1 ① (CPU gather) → 3-2 (CPU) → 3-1 ② (GPU) → 3-3 → 3-4.**
GPU 코드를 한 줄 쓰기 전에 CPU 에서 두 관문을 넘는다 — M0-a 가 "GPU 작업 전에 설계를 고친다" 고 둔 이유와 같다.

## 5. 타임박스 — 미정

M0-a 와 같은 규칙: **구현이 아니라 튜닝에만 건다.** RDG 첫 접촉은 구현이라 타임박스 밖.

## 미결 — 이 문서가 답하지 않는 것

| 항목 | 내용 | 언제 |
