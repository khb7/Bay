# M0-b C안 — 멈춘 모래 재우기 계획

> 2026-10-25. 근거: [papers.md C9](../research/papers.md) (Servin & Wang 2015 적응 모델 축소) · C1 §4.5 (Flex 입자 슬리핑) · Box2D v3 `sleepThreshold`.
> 바탕: #48 새 기본값 `-gpu2 -color8par -block=15 -kv=1 -kc=0.2 -vmax=30 -iterations=60`.
> 왜: 5만 정지 13.6 ms(마른) · 16.2 ms(젖음) — 통과선 언저리. 반복(색 8 패스 × 60)이 비용의 대부분인데, 정지 모래도 똑같이 그 비용을 낸다.

## 0. 목표와 범위

- **목표**: "대부분 정지 + 일부를 도구로 건드리는" 장면에서 활성 영역만 반복을 돈다. 통과선 **활성 5만 · 16 ms** 를 정지 모래 위에서 확실히 지킨다.
- **범위 밖**: 다짐 중(전체가 움직이는) 비용 41~57 ms 는 재우기로 줄지 않는다 (C9: 잠들 게 없다). 이건 별도 문제로 남긴다.
- GPU(`-gpu2`) 경로만. CPU 경로는 건드리지 않는다.

## 1. 설계 — 입자가 잠들고, 블록은 풀이를 건너뛴다

C9 는 정지 덩어리를 강체 하나로 합친다. 우리는 **합치지 않는다** — 강체의 질량·관성 계산, 쪼갤 때의 재배치가 없다. 대신:

| 층 | 무엇 | 어떻게 |
|---|---|---|
| 입자 | 잠듦 = 고정 입자처럼 | 잠든 입자는 역질량 w = 0 (무한 질량). 예측(중력)·속도 0. **깨어 있는 이웃을 그대로 받친다** — 접촉 식은 이미 w 로 나눠 깬 쪽만 움직인다 |
| 블록 | 풀이 건너뛰기 | 블록 안 접촉 중 **깨어 있는 입자가 하나도 없으면** 그 블록의 배치 수 = 0 → `SolveBlocksParCS` 가 즉시 반환. 색 8 패스 × 60 반복의 실제 일이 사라진다 |
| 쌍 | **그대로 만든다** | 잠든 쌍도 쌍 목록에 남겨 λ 를 이어 간다 (워밍). 깰 때 차가운 시작(#36 · C7: 워밍이 핵심)을 피한다. 쌍 생성은 프레임당 고정비라 작다 |

- 잠든-잠든 접촉은 `WSum = 0` 이라 몸체가 이미 건너뛴다. 블록 단위 건너뛰기는 그 반복 비용(메모리 읽기)까지 없앤다.
- 결합: 양쪽이 잠들면 w 가 0 이라 보정이 없다. 파단 검사는 그대로 (안 움직이니 끊길 일이 없다).

### 1-1. 상태

- `SleepRW[p]` (uint): 하위 31비트 = 정지 프레임 수, 최상위 비트 = 원래 고정 입자 (바닥 — 영원히 잠든 것과 같다, 깨우지 않는다).
- 잠듦 판정: `count ≥ SleepFrames`. 잠들 때 `Pos.w = 0`, 깰 때 `Pos.w = 1`. `Download` 는 고정 비트로 w 를 되살려 CPU 에 넘긴다.

### 1-2. 잠들기 (프레임 끝, `StatsCS` 자리)

- 깨어 있는 자유 입자: `|v| < SleepVel` 이면 `count++`, 아니면 0.
- 값 (C9 표 2 · Box2D 를 우리 단위로):
  ```
  SleepVel     0.25 cm/s      (C9 2.5 mm/s. 우리 정지 크리프 0.002~0.005 의 50~100 배 위)
  SleepFrames  30 (0.5 s)     (Box2D timeToSleep 0.5 s 관례. 미확인 → 스윕)
  ```
- C9 는 상대 속도·상대 가속도를 본다. 우리는 바닥이 고정이라 **절대 속도**로 충분하다 (움직이는 바닥 없음). 가속도 조건은 뺀다 — 속도가 N 프레임 연속 낮은 것이 같은 일을 한다.

### 1-3. 깨우기

| 사건 | 규칙 | 근거 |
|---|---|---|
| 충격 | 잠든 입자와 깬 입자의 접촉에서 다가오는 법선 상대 속도 > `WakeVel` | C9 접촉 사건 split. `WakeVel` = 15 cm/s (C9 0.15 m/s) |
| 전파 | 이번 프레임에 깬 입자의 잠든 이웃을 한 번 더 깨운다 (깊이 2) | C9 `N_c-spl = 2` |
| 결합 파단 | 끊긴 결합의 두 입자 | 하중 경로가 바뀐다 |
| 도구 (v1) | `Upload` (도구 조작 · 입자 추가/제거) 때 **전부 깨운다** | C9 센서의 가장 단순한 형태. 조작 순간 비용은 감수 |
| 도구 (v2, 나중) | 조작 AABB 를 매개변수로 받아 그 안 + 여유만 | C9 센서 |

- 깨우기 패스는 쌍이 정해진 직후, 워밍 앞 (`PairScatterCS` 뒤). 접촉 쌍을 훑어 잠든 쪽을 깨운다. 전파는 같은 패스를 "방금 깬" 표시로 한 번 더.
- 분리 사건(멀어짐) 깨우기는 **쓰지 않는다** (C9: 조금만 바꿔도 무반응 ↔ 전체 연쇄).
- ⚠ 깨우지 않는 경우: 잠든 입자 아래의 받침이 사라지는 것 — 도구로 파내는 것뿐이고, 그건 v1 의 전부 깨우기가 덮는다.

### 1-4. 블록 깨어 있음

- `ColorBatchCS` 가 블록 접촉을 이미 훑는다 → 그때 "깬 입자를 가진 접촉이 있나" 를 같이 본다. 없으면 `BatchStart` 를 빈 구간으로 쓴다 (배치 0개).
- 통계: 깬 블록 수 · 깬 입자 수를 `BatchStats` 에 더한다 → 창마다 "깨어 있음 %" 로그.

## 2. 위험

| 위험 | 내용 | 대응 |
|---|---|---|
| R1 굳은 사면 | C9 약점 — 충격이 없으면 영원히 굳어, 마지막 작은 사태 · 느린 크리프를 잃는다 | 관문에서 잠 켬/끔의 안식각 · 높이 비교. 크리프는 잠들면 0 이 된다 — **지표가 아니라 결과로 본다** (각·높이 유지) |
| R2 깜빡임 | 문턱 근처 입자가 잠 ↔ 깸 반복 → 블록이 계속 깸 | 깨는 문턱(15)과 잠드는 문턱(0.25)이 60배 떨어져 있다. 깸/잠 횟수를 로그 |
| R3 잠든 받침 위 깬 덩어리 | 잠든 쪽은 무한 질량이라 받친다 — 정상. 하지만 잠든 쪽이 **밀려야** 할 때(위에서 무게가 늘 때)도 안 밀린다 | 무게 증가 = 위에 뭔가 떨어진 것 → 충격 깨우기가 잡는다. 천천히 쌓이는 경우는 시험 G3 로 본다 |
| R4 워밍 λ | 잠든 쌍의 λ 는 풀이를 안 하니 그대로 남는다 → 깰 때 그 λ 로 워밍 | 원하는 바다 (정지 하중). 단 잠든 동안 `PairScatterCS` 가 매 프레임 λ × WarmStart 를 하므로 1.0 유지 필요 (지금 1.0) |
| R5 통계 · 정지 판정 | 잠든 입자 속도 0 → `IsSettled` 가 일찍 참 | 관문 시험의 정지 판정이 잠 때문에 빨라지는지 확인. 필요하면 잠든 입자를 판정에서 뺀다 |
| R6 결정성 | 잠/깸이 부동소수 문턱이라 실행마다 다를 수 있다 | 지금도 비트 재현은 아니다 (2-1). 같은 경향이면 된다 |

## 3. 단계와 관문

### S1 — 구현 (1~1.5일)

1. `SleepRW` 상주 버퍼 · `FSandGpuFrameParams::{bSleep, SleepVel, SleepFrames, WakeVel}` · 커맨드릿 `-sleep -sleepv= -sleepframes= -wakev=`.
2. `StatsCS`: 잠들기 카운트 · 잠들면 `Pos.w = 0`, `V = 0`.
3. `WakeCS` (새, SandFrame.usf): 쌍을 훑어 충격 깨우기 → 두 번째 호출은 "방금 깬" 이웃 전파. 깨면 `Pos.w = 1`, `count = 0`.
4. `BreakBondsCS`: 끊기면 두 입자 깨우기.
5. `WarmPredictCS`: 잠든 입자는 예측 없음 (지금 `Wi > 0` 분기가 이미 막는다 — 확인만).
6. `ColorBatchCS`: 깬 접촉이 없는 블록은 배치 0.
7. `Upload`: `SleepRW` 를 0 으로 (전부 깸, 고정 비트만 유지). `Download`: w 복원.
8. `-perf -window` 로그에 깬 입자 % · 깬 블록 %.

### S2 — 관문 (반나절 + 측정, 동시 1개)

```
G1 동등성     더미 시드 3 · 1337 잠 켬/끔        안식각 ±1° · 높이 ±0.5cm (크리프는 기록만)
G2 결합       터널 원형 · 절토 (잠 켬)            #48 과 같은 판정 (터널 < 5% · H_c 84~95)
G3 깨우기     5만 정지 기둥 위에 2천 개 붓기       잠 켬/끔 최종 높이·각 비교 · 깬 영역이 붓는 자리에 국한되는지
G4 성능       5만 정지 (잠 켬)                    목표 ≤ 5 ms (반복이 거의 없다)
              5만 정지 + 2천 붓는 중               ≤ 16 ms
```

- G3 는 새 시험이다: `-perf` 에 `-dropat=f -dropcount=` (f 프레임에 위에서 N 개 추가) 를 붙인다. 추가는 `Upload` 라 v1 에선 전부 깬다 → **v1 의 G3 는 "전부 깬 뒤 다시 잠드는 시간"** 을 잰다. 국한 깨우기는 v2(센서)에서.

### S3 — 값 스윕 (필요 시)

- `SleepVel` {0.1, 0.25, 1.0} × `SleepFrames` {15, 30, 60} — G1 각 변화와 G4 시간의 교환.

## 4. 분기

- G1 에서 각이 1° 넘게 변한다 → R1. `SleepVel` 을 낮추고 `SleepFrames` 를 늘린다. 그래도면 블록 안 "모든 입자" 조건으로 강화.
- G3 에서 깨우기가 연쇄로 전체를 깨운다 → `WakeVel` 을 올리거나 전파 깊이 1.
- G4 가 목표에 못 미친다 → 프레임 고정비(정렬 · 쌍 생성 · 배치 나누기)가 남은 것. 잠든 입자의 이웃 탐색 건너뛰기 (잠든-잠든 쌍은 지난 목록에서 복사) 가 다음 단계.
