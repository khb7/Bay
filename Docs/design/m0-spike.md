## 0. 이 문서의 지위

M0의 목표는 게임을 만드는 것이 아니라 **질문에 답하는 것**이다.
여기서 만든 코드는 버려도 된다 — 단 배치 하네스만은 남는다(§6).

산출물은 화면이 아니라 이것들이다.

```
차단 판정 2개   터널이 서는가 · 덩어리로 무너지는가
정보성 값 3개   벽 최소 두께 · CPU 기준선 · ΔW 폭
확정 상수 4개   μ·substep·반복 / 결합 슬롯 실수요 / breakStretch / 곡선 과장 배율
```

**M0가 "아니오"를 내놓는 것은 실패가 아니라 성공이다.**
두 달 뒤가 아니라 지금 알아내려고 만드는 구간이다.

## 1. 무엇을 만드는가

```
FSandSpike       순수 C++. UE 타입 최소. Step(dt) 하나. 렌더링을 모른다
 ├─ ASpikeActor   실시간 1× 재생 + 디버그 드로우 구       ← ★ 눈으로 판정
 └─ FSpikeBatch   같은 코어를 최대 속도로 N회전, CSV 덤프  ← 스윕 · 실패 분기
```

같은 코어, **관측만 둘**이다.

- ★ 덩어리 붕괴는 결국 **보고 판단해야 하는 것**이라 실시간 뷰가 필요하다
- 나머지 넷은 전부 숫자 스윕이라 배치가 필요하다 (안식각 하나만 27 실행)

별도 프로세스로 나누지 않는다. **스윕에 필요한 건 별도 프로세스가 아니라 코어가 틱·렌더링에서
분리되어 있는 것**이고, 그러면 한 세션 안에서 설정 수십 개를 for 문으로 최대 속도로 돌릴 수 있다.

내용물은 이게 전부다.

```
XPBD 입자 시뮬 하나
  접촉 + 마찰 + 점착 제약
  정렬 기반 공간 해시
  손으로 배치한 입자 더미 (도구 없음)
  W는 전역 슬라이더 하나
  렌더링은 그냥 구
```

격자도 파도도 조석도 도구도 타일도 없다. **입자와 제약만.**

### 순서

```
M0-a   CPU 단일 스레드. 다섯 질문에 답한다        ← 이 문서
M0-b   답이 "예"면 GPU로 옮긴다 (RDG 첫 접촉)
```

XPBD 자체는 코드가 짧다. 시간이 드는 건 GPU 파이프라인(RDG·버퍼·정렬)이므로,
**M0-a에서 답이 "아니오"면 GPU 작업을 시작하기 전에 설계를 고친다.** 그게 이 순서의 목적.

## 2. 공통 뼈대

다섯 검증이 같은 뼈대를 쓴다. 안 그러면 결과를 서로 비교할 수 없다.

### 2-1. 솔버 상수 — 미리 박지 않는다

**`substep`·반복 수·`μ`를 상수표에 적어두지 않는다. 실험의 출력으로 뽑는다 — 단 출처가 다르다.**

안식각을 "전제"로 올린 이유가 이것이다. 34°는 검사받는 대상이 아니라 **뼈대를 교정하는 기준자**다.
`μ`와 최종 안식각은 1:1이 아니고(입자 배열·회전 없음·반복 수가 전부 끼어든다) 이론값으로 못 정한다.
그러니 3-0이 곧 솔버 교정 실험이 된다.

> ★ **단 `substep`·반복은 34°가 정하지 않는다.** 판정 기준이 솔버 **안**에 있는 값이라
> [수렴 연구](#2-1-a-수렴-연구--예산은-34를-안-보고-정한다)로 먼저 못박고, 그 다음 `μ`만 34°에 맞춘다.
> 셋을 한 스윕에 올리면 **미수렴을 물리 파라미터로 쓰게 된다** — 미수렴이 만드는 저항은 하중에 의존하므로
> 3-0에서 맞춘 조합이 터널·벽·붕괴에서 어긋난다.
> 근거: [terms/dem-calibration.md](../research/terms/dem-calibration.md) (DEM 캘리브레이션 문헌의 모호성 문제)

| 상수 | M0 시작값 | 확정 방법 |
|---|---|---|
| 입자 반경 `r` | **2.5** (UE cm 단위) | 고정 — `system-design.md` §2 확정값 |
| 중력 | **-980** | 고정 |
| 프레임 `dt` | 1/60 | 고정 |
| `substep` | 10 | ★ **수렴 연구** (2-1-a) |
| substep당 반복 | 2 | ★ **수렴 연구** (2-1-a) |
| 마찰 `μ` | 0.7 부근 | ★ 안식각 스윕 — **예산 고정 후** |
| 접촉 컴플라이언스 `α` | **0** (강체) | 고정 — `params.md` "거의 0" |
| 점착 컴플라이언스 `α` | `1 / cohesion(W)` | 2-4 |

> `system-design.md` §4는 "XPBD 15반복"으로 적혀 있고, 시작값은 substep 10 × 반복 2 = 20 투영이다.
> Macklin 2019(Small Steps)가 같은 예산이면 substep을 늘리는 쪽이 수렴이 낫다고 하니 거기서 시작하되,
> **그 주장은 수렴에 관한 것이지 안식각에 관한 것이 아니다** — 검증 대상은 2-1-a이지 3-0이 아니다.
> 어느 조합이 **수렴을 최소 비용으로 내는지**를 2-1-a가 답하고, 그 결과가 §4의 값을 갱신한다.

> **입자 반경 2.5cm** — 반경 2.5cm / 지름 5cm / 터널 30cm = 6입자 폭.
> `params.md` §2-8의 옛 값(반경 5mm)은 정정 완료.

#### 2-1-a. 수렴 연구 — 예산은 34°를 안 보고 정한다

수치해석의 격자 수렴 시험을 **시간 예산 축**에서 하는 것. `μ`를 안 건드린다.

```
1.  μ 를 아무 값에나 고정한다              (0.3 정도. 값은 중요하지 않다)
2.  (substep × 반복) 격자로 θr 을 잰다
3.  예산을 늘려도 θr 이 안 움직이는 지점을 찾는다    ← 이게 판정
4.  그 플래토의 가장 싼 조합으로 고정한다
5.  그 다음 μ 만 34° 에 맞춰 스윕한다
```

**3이 핵심이다. 잔차 임계값을 미리 정할 필요가 없다 — 플래토 자체가 기준이다.**
임계를 가정하면 그 가정이 또 하나의 미조정 파라미터가 된다.

```
예산 ↑ 했더니 θr 이 움직인다   →  지금 각의 일부는 미수렴이 만든 것. μ 로 볼 게 아니다
예산 ↑ 해도 θr 이 그대로       →  수렴했다. 그 위는 낭비
```

[A-R7](../research/papers.md)의 **불평형력 비**(제약 잔차 ÷ 접촉력)를 같이 찍으면 두 기준이 서로를 확인한다.

| 잔차 | `θr` 플래토 | 해석 |
|---|---|---|
| `< 10⁻³` | 도달 | ✅ 수렴. 여기서 고정 |
| `> 10⁻³` | 도달 | ⚠ 각이 잔차에 둔감한 것. 붕괴 시간 등 다른 관측으로 확인 |
| `< 10⁻³` | 미도달 | ⚠ **워밍 스타트가 상태를 끌고 다니거나 §2-2 정지 판정이 새고 있다** |

**비용은 오히려 준다** — 수렴 연구는 `μ` 하나에서만 하면 되기 때문이다.

```
3차원 격자   substep 4 × 반복 4 × μ 8   =  128 회
분리하면     (4 × 4) + 8                =   24 회
```

> ★ **예측 하나.** `014c604`에서 워밍 스타트를 넣자 `θr`이 닫혔다. 워밍은 유효 반복 수를 늘리는 장치이므로
> **수렴 개선 → 각 상승**이었다는 뜻이고, 그렇다면 반복을 더 늘리면 34°를 넘고 **μ = 0.15는 과대평가**다.
> 그 커밋은 무작위 바닥과 같이 들어가 둘을 분리할 수 없다. **이 절차가 분리한다.**

> ⚠ **① 워밍 스타트를 켠 채로 잰다.** 끄고 잰 예산은 운영과 다르다.
>
> ⚠ **② 정지한 더미의 예산은 흐르는 상황에 모자란다.** 워밍의 이득은 접촉이 유지될 때만 나오는데
> 3-2 붕괴는 접촉이 매 프레임 갈린다. **잔차를 3-2에서도 찍고 둘 중 큰 예산을 채택.**
>
> ⚠ **③ 플래토가 `μ`에 약간 의존한다.** 5에서 `μ`가 정해진 뒤 그 값으로 한 번만 재확인(1회 추가).

**실측 (2026-09-09, m0-log #28)** — μ = 0.3 격자: ss 1 은 반복 23 부터 플래토(44.7~45.6°, 불평형비 10⁻⁵),
서브스텝은 늘릴수록 나빠짐(ss 8: 불평형비 100배 · 크리프 10배 · −1~3°). 운영 μ(0.15) 재확인: 반복 23→360 에서 31.8→35.4°,
플래토 진입 90~180 — **낮은 μ 일수록 예산에 민감하다(③ 확인).** 시드 산포 ±1°.
→ **예산 확정: ss 1 × 반복 180.** 90 은 −0.7° 로 스윕용. 그 예산에서 μ 재스윕 → **μ = 0.13** (3-0-A).

**플래토가 안 나오면 그게 실패가 아니라 §1 M0-a의 답이다.** 감당 가능한 예산 안에서 `θr`이 계속
움직이면 이 설계로는 20만 입자에서 수렴을 못 한다는 뜻이고, *"M0-a에서 답이 아니오면 GPU 작업을
시작하기 전에 설계를 고친다"* 가 발동할 조건이다. **지금 구조로는 그 신호가 `μ` 튜닝에 흡수돼서 안 보인다.**

### 2-2. 정지 판정 — 하나의 정의를 넷이 공유한다

안식각·벽·터널·붕괴가 전부 "멈췄는가"를 물으므로 정의는 하나여야 한다.

```
평균 |v|  <  ε · √(g·d)   가  60프레임 연속 유지        ε = 0.002
```

`√(g·d)` = 입자가 **제 지름만큼 자유낙하했을 때의 속도** = √(980 × 5) = **70 cm/s**.
그 0.2%가 임계 **0.14 cm/s**.

입자 크기와 중력만으로 만들어지므로 **해상도를 바꿔도, 시간 조각을 바꿔도 같은 의미**다.

> **⚠ 이전 정의(`0.01 × r/dt`, 임계 1.5cm/s)에서 바뀌었다.** 두 가지가 문제였다.
>
> **① `dt` 가 식에 남아 있었다.** 반경으로는 정규화됐지만 시간으로는 안 됐다 —
> `dt` 를 절반으로 줄이면 같은 모래의 판정선이 두 배가 된다. 계산 방식이 물성을 바꾸는 꼴이고,
> **M0-b 에서 GPU 결과를 CPU와 대조할 때 자가 달라진다.**
>
> **② 100배 느슨했다.** 에너지로 환산하면 `E_k/(m·g·d) = 2.3×10⁻⁴` 로,
> DEM 통상(10⁻⁶~10⁻⁸)에서 한참 벗어나 있었다. 실행 #1의 "정지인데 최고점이 계속 내려간다"부터
> 실행 #13~#15의 크리프 오판까지 **전부 이 느슨함 위에서 벌어졌다.**
>
> **`ε` 을 정한 방법** — 관측 창에서 역산한다.
> "4초 붙잡는 동안 표류가 지름의 10%(0.5cm)를 넘으면 멈춘 게 아니다"
> → `ε < 0.5 / (70 × 4) ≈ 0.0018` → **0.002**.
> 에너지 환산 `2×10⁻⁶` 으로 DEM 통상 범위와 일치한다 — 독립적인 두 경로가 같은 자리를 가리킨다.

### 2-3. 재현성

- **고정 시드** — 초기 배치 jitter만 난수를 쓴다
- **순회 순서 무관** — 초기엔 Gauss-Seidel(즉시 반영)이라 순서에 의존했다.
  실행 #3에서 그 순서 의존이 곧 잔여 운동의 출처임이 드러나 **Jacobi + 입자별 평균**으로 교체했다.
  결정성이 시드가 아니라 **알고리즘 구조에서 나온다** (→ [m0-log.md](m0-log.md) 실행 #3)
- **같은 입력 → 같은 CSV 바이트.** 이것을 회귀 테스트로 쓴다

세 번째가 실무적으로 가장 중요하다. 실패 분기에서 상수를 바꿔가며 튜닝할 때
**바꾼 것만 결과가 달라졌다**는 보장이 없으면 원인을 짚을 수 없다.

**골든 스냅샷** — "같은 바이트"를 실제로 붙잡아 두는 방식은 정해 뒀다.

```
미니 시나리오   3프레임 · 입자 수 최소 · 단일 스레드(결정성)
동결           위치·속도 배열을 골든 파일로 저장, 저장소에 넣는다
회귀           매 실행마다 대조. 틀리면 실패
```

> 핵심은 **"알고리즘을 의도적으로 바꾸면 이 테스트가 깨지는 것이 정상"** 이라는 규약이다.
> 깨졌을 때 골든을 다시 뜨는 것은 **의도한 변경일 때만**이고, 그 재생성이 곧 변경 기록이 된다.
> (선례: Matter `test_regression.py` — [papers.md A 보충 "Matter 2025"](../research/papers.md))

### 2-4. `cohesion(W)` — 교체 가능한 구간 선형

M0는 이 곡선의 **모양 자체가 검증 대상**이라 해석식으로 굳히면 안 된다. 제어점 4개의 구간 선형으로 둔다.

```
cohesion
   ↑        ●━━━━━━━━●
   │       ╱          ╲
   │      ╱            ╲
   └──●━━●──────────────●──→  W (0~1 정규화)
     W_dry W_opt         W_sat
      절벽   고원         슬러리
```

| 제어점 | 시작값 | 근거 |
|---|---|---|
| `W_dry` | 0.05 | papers B1 — 왼쪽 절벽. **이 아래는 0** |
| `W_optStart` | 0.15 | B1 — 최적 (실제 수분 ~1%) |
| `W_optEnd` | 0.70 | Scheel 2008 — 넓은 고원 |
| `W_sat` | 0.90 | 골격이 뜸 → 슬러리 |

**"급작스러움" 검증이 조정하는 건 `W_dry`와 `W_optStart` 사이 간격 하나**다.
좁힐수록 절벽이 가파르고, 그 배율이 M0의 산출물 "곡선 과장 정도"가 된다.
제어점 방식이라 그 값이 **숫자 하나로 떨어진다.**

### 2-5. 계측 출력

**프레임별 CSV** — 배치 실행이 자동으로 뽑는다.

```
frame, simTime, W_global,
avgSpeed, maxSpeed,
bondsActive, bondsBrokenThisFrame, bondsBrokenTotal,
peakHeight, comHeight,
movedParticles,          ← 초기 위치 대비 변위 > 2r
stepMs
```

**정지 시점 스냅샷** — 입자 위치 전량(재생용) + 파편 분석.

```
fragments: [size, size, ...]      ← 이동 입자만, 점착 그래프 연결 요소 (Union-Find)
massWeightedMeanSize = Σs² / Σs   ← ★ 덩어리 붕괴 주 지표
finesRatio = (크기 ≤ 2인 파편의 입자 수) / 전체 이동 입자
```

`bondsActive`와 `bondsBrokenTotal`을 매 프레임 남기는 것이 중요하다.
**결합 슬롯 12개가 실제로 몇 개 쓰이는지**와 **연쇄 파단이 얼마나 빠른지**가 둘 다 여기서 나온다.

### 2-6. 점착 제약 — 설계와 문헌 근거 (2026-09-09 확정)

**3-1·3-2 와의 연결** — 3-1 실패 분기의 `breakStretch 1.3 → 1.5` 는 "파단 완화"가 아니라 **재료를 강하게 만드는 것**이다

⑦ 의 연화 없음과 접촉 `α=0` 이다 — SP 가 순차(GS)라 Jacobi 평균 우려는 해당 없다.

## 3. 검증 5개

전부 같은 4단 형식이다 — **배치 → 절차 → 판정 → 실패 분기.**

### 3-0. 안식각 — 전제

`W=0`인 마른 모래가 34° 근처에서 멈추는가.

> **★ 측정법이 두 번 바뀌었다.** 경위는 [m0-log.md](m0-log.md) 실행 #6·#16,
> 근거는 [papers.md §A-R](../research/papers.md).
>
> **계기·오차 예산은 [m0-ruler.md](m0-ruler.md)** — 자 교정 · 안정성 · 잡음 바닥 · 유지 시간 스윕,
> 그리고 "지금 값을 얼마나 믿을 수 있는가".

#### 먼저 — 각도가 하나가 아니다

```
멈춰 있는 더미를 기울인다 → θm 에서 무너지기 시작       최대안정각
사태가 흐르다 멈춘다      → 남은 표면이 θr              안식각
                            θm > θr,  보통 2~5° 차이   (A-R4, Jaeger 1989)
```

정지한 알갱이는 서로 홈에 박혀 있어 **위로 올라타야** 풀린다(Reynolds 팽창).
그 여분이 `θm − θr`이다. **정지마찰과 운동마찰이 다른 것의 알갱이 버전.**

> ⚠ **우리 `μ` 는 속도 무관 상수 하나다.** 연속체 쪽은 같은 이력을 **전단률 의존 마찰**로도 본다
> (µ(I): 준정적 `mu_1 ≈ 0.382`(21°) → 관성 극한 `mu_2 ≈ 0.644`(33°). Matter 기본값,
> [papers.md A 보충 "Matter 2025"](../research/papers.md) — rheology 계수라 `θr`/`θm` 과 같은 양은 아니고 **참조 범위**다).
> 우리 모델엔 그 축이 없으므로 **`θm − θr` 이 전부 맞물림·기하에서 나와야 한다.**
> 3-0-A(부어 쌓기 · 동적)와 3-0-B(경사판 · 준정적)가 같은 `μ` 로 다른 각을 못 내면,
> 원인 후보는 재료가 아니라 **모델에 축이 하나 없는 것**이다.

#### 우리가 재야 하는 것은 `θr` 이다

`params.md` 의 `talusDry` 34° 가 어느 쪽인지가 관건이고, **`θr` 로 확정한다.**

| 근거 | |
|---|---|
| 문헌 관행 | 표로 나오는 "모래 안식각 34°"는 **부어 쌓은 더미의 경사** |
| **격자 모델의 의미** | [열침식](../research/terms/thermal-erosion.md)은 `경사 > talus 면 아래로 옮긴다` — **옮기기를 멈추는 각**이 곧 `talusDry`. 정의상 "흐른 뒤 남는 각" = `θr` |

> **격자와 입자가 여기서 갈린다 — 결함이 아니라 입자 계층의 존재 이유다.**
> 격자는 각도가 하나뿐이라 `talus` 보다 가파른 경사를 **만들 수가 없다.**
> 입자는 `θr` 과 `θm` 사이에서 **불안정하지만 서 있는 상태**를 가진다.
> 그게 ★덩어리 붕괴(3-2)가 요구하는 "버티다 갑자기 무너진다"의 물리적 정체다.

```

따라오는 값  입자의 θm = 36~39°     재는 게 아니라 결과. 게임의 드라마
```

#### 3-0-A. 부어 쌓기 (fixed funnel) — `θr` 주 교정

[A-R1](../research/papers.md) 의 네 측정법 중 하나. **더미 꼭대기 위 일정 높이에서 입자를
조금씩 떨어뜨려, 저절로 자란 원뿔의 옆면 각**을 잰다. 문헌 표의 "모래 34°"가 이 방식의 값이다.

```
        ▼ ▼                 ▼ ▼                  ▼ ▼
         ·                  ·                     ·
                           ▒▒▒                  ▒▒▒▒▒
        ▒▒▒       →       ▒▒▒▒▒       →       ▒▒▒▒▒▒▒▒▒
   ─────────────      ─────────────        ─────────────────
                                                ↖ 이 각이 θr
```

**왜 이 방식인가 — 불안정 상태를 만들지 않는다**

```
원통   높은 기둥을 만들어놓고 지지를 뺀다   →  불안정 상태를 먼저 만든다
부어   더미를 한 알씩 키운다                →  불안정 상태가 존재한 적이 없다
```

입자 하나의 추가는 언제나 작은 교란이라 **준정적이 저절로 성립한다.**
계단·유지 시간·상한 같은 임의 상수가 통째로 사라지고, 남는 축은 **낙하 높이와 공급 속도** 둘뿐이다.

> 설계 초기에 이 방식을 "쏟는 속도·낙하 높이가 변수"라며 기각했었다. 그건 **실험실 논리**였다 —
> 시드를 고정한 시뮬은 재현되고, 그 두 변수는 무관성 검사로 확인하면 된다 ([m0-log.md](m0-log.md) #21).

**배치** (`FPourSetup`)

| | 값 | 근거 |
|---|---|---|
| 입자 | 1200 (측정) · 600/2400 (크기 무관성) | 퇴적 원뿔의 밑동 반경이 입자 40개 폭 이상이어야 각을 잴 수 있다 |
| 낙하 높이 | 더미 꼭대기 위 **1d** | 기준은 **축 근처의 정지한 입자**(|v| < 0.1√(gd)). 공중 입자를 포함하면 생성 높이가 폭주한다 (#23). 0.5d 이하는 자리를 못 찾아 정체 |
| 놓는 지점 | 축 주위 반경 **0.5d** (점 공급원) | 2.5d 로 넓히면 착지 발자국이 평탄한 꼭대기를 만든다 — 두 판독이 8° 어긋난다 (#23) |
| 공급 속도 | 2개 / 2프레임 | 놓기 전 직전 입자가 지름 이상 떨어졌는지 확인한다 — 겹쳐 놓으면 폭발한다 (#22) |
| 거친 바닥 | 예상 퇴적 반경 × 1.2, **격자 흔들림 0.3R** | 퇴적물보다 넓어야 한다 (#19). ★ 간격 D 정사각 격자는 거칠기가 아니라 **결정 템플릿**이다 — 단분산 구가 FCC 로 자라 45~55°에 선다 (#25) |
| **솔버** | **워밍 스타트 켬** (`WarmStart=1`, 접선 포함, gap ≤ 0.05cm) | 차가운 시작은 접선 잔차가 크리프(0.08 cm/s)로 굳어 더미가 30초에 7cm 주저앉고, 각도가 μ 아닌 반복 수를 따라간다 (#24) |

② 목표 개수까지 붓는다                 매 놓기가 작은 교란 — 별도 정지 대기 없음

법선 중앙값       표면 입자의 지역 법선 히스토그램

크게 벗어나면 결정적 사건이 있다는 뜻이다 (#22: 21배, **미해명**).

반복 90 기준 μ 단조(참고): 0.10→29.0° · 0.12→30.5° · 0.15→34.4° · 0.17→37.1° · 0.20→39.1°.
회전이 잠긴 구는 기하학적 맞물림이 마찰 위에 얹혀 μ 가 물리값보다 훨씬 작다 — `μ` 는 유효 파라미터다.
실행별 경위는 [m0-log.md](m0-log.md), 오차 예산은 [m0-ruler.md](m0-ruler.md).

#### 3-0-B. 경사판 (tilting box) — `θm` 측정

---

**상자에 채우고 서서히 기울여 사태가 시작되는 각을 잰다.** 퇴적물 모양을 해석할 필요가 없다 —
모양이 아니라 **시점**만 본다.

```
       ┌─────────────┐              ┌─────────────┐
       │▒▒▒▒▒▒▒▒▒▒▒▒▒│      →       │▒▒▒▒▒▒▒▒▒▒▒▒▒│  θ
       │▒▒▒▒▒▒▒▒▒▒▒▒▒│              │▒▒▒▒▒▒▒▒▒▒▒▒▒│ ╱
       ┗━━━━━━━━━━━━━┛              ┗━━━━━━━━━━━━━┛╱
       ■■■■■■■■■■■■■  ← 고정층      중력을 θ 만큼 돌린다
         (거친 바닥)                 (상자를 돌리는 것과 같다)
```

**배치**

| | 값 | 근거 |
|---|---|---|
| 입자 | 3000개, 6층 | Frâncu 2014 §8.1 의 3000개를 따름 |
| 고정층 | 바닥 1층 | 매끄러우면 내부 파괴 대신 **바닥에서 미끄러진다** — 그러면 바닥 마찰을 재게 된다 |
| 벽 | 네 면 다 막음 | 사면 방향을 열면 **내부 파괴 없이도 퍼져서** 그 퍼짐이 사태로 오인된다 |
| 관찰 구역 | 중앙 60% | 가장자리는 항상 조금씩 흘러내린다 |

**절차 — 각도마다 붙잡고 묻는다**

```
① 수평에서 다진다                     정지 판정(§2-2) 또는 1800프레임
② 그 상태를 스냅샷                    모든 시험이 같은 다진 상태를 공유한다
③ θ 까지 1초에 걸쳐 기울인다           관성 전이는 이 구간에서 끝낸다
④ 붙잡고 4초 관찰                     ★ 여기서 정지하면 "버틴다"
⑤ 이분 탐색 8회                       0 ~ 70° 를 0.3° 해상도로
```

**판정** — 유지 창의 **앞 절반과 뒤 절반의 평균 속력을 비교**한다(중앙 구역 입자만).
뒤가 작으면 움직임이 죽어가는 것 = **버팀**, 아니면 유지되는 것 = **무너짐**.
Pouliquen 1999 의 `θ_start` 정의(흐름이 지속되는가)와 같은 성질이고 임의 상수가 없다.

> 연속으로 기울이며 재는 문헌 방식은 **기울기 속도가 결과를 바꾼다** — 실측에서 1°/s와 4°/s가
> 11° 차이났다. 기울이는 동안엔 언제나 미세 재배치가 있어 속도 임계가 그것을 사태로 오인한다.
> 각도를 고정하고 물으면 그 변수가 사라진다.

> ⚠ **판정을 고르는 데 네 번 걸렸고 실패 방식이 매번 달랐다** ([m0-log.md](m0-log.md) 실행 #15).
> 새 판정을 시험할 때는 **유지 시간 스윕과 μ 단조성을 둘 다** 볼 것 — 하나만 보면 통과한다.
> 변위 기준은 유지 시간에 휘둘리고(크리프 누적), §2-2 의 "60프레임 연속"은 스파이크에 부러진다.

**재는 값은 `θm`** — 34° 와 직접 비교하면 안 된다. `θr`(3-0-A)보다 2~5° 높게 나오는 것이 정상이고,
그 **차이 자체가 이력 폭**이라 ★덩어리 붕괴(3-2)가 얼마나 극적일지를 예고한다.

#### ★ 부수 산출물 — 점착 측정의 기준선 `θ_m0`

`c[Pa]` 를 경사판으로 재려면 **젖은 `θm` 과 마른 `θm` 의 차분**이 필요하다 ([3-3-B](#-3-3-b-점착의-자-c-pa--별도-배치가-필요하다)).
**34° 를 기준으로 쓰면 안 된다** — 그건 `θr` 이고, 자가 다르면 그 2~5° 가 통째로 `c` 로 둔갑한다.

```
                   sin(θ_m − θ_m0)
  c = γ·z·cosθ_m · ───────────────          θ_m0 = 같은 배치의 마른 θm
                       cos θ_m0
```

같은 시드·같은 층수·같은 판정으로 두 번 돌린 차분이라 **계통 오차가 상쇄된다** —
바닥 거칠기든 벽 효과든 양쪽에 똑같이 들어가고 빠진다.
감도는 `z=27.5cm`·`θ_m0=38°` 기준 **각도 1° ≈ `c` 50 Pa** (자 해상도가 `c` 의 5% 안쪽).

**★ 그래서 확정 조합에서 층수를 바꿔 마른 `θm` 을 지금 남겨둔다.**

```
Layers ∈ {6, 9, 12}  ×  확정된 (μ, substep, 반복)  =  3 실행
```

층수를 스윕하는 이유는 3-3-B 의 **측정 상한** 때문이고(층이 얇으면 큰 `c` 를 못 잰다),
지금 안 뽑으면 나중에 마른 것부터 다시 돌려야 하는데 그때는 코드가 바뀌어 있어
**"같은 조건" 보장이 약해진다.** 3 실행이면 몇 분이다.

**⚠ 어디까지가 문헌이고 어디부터가 우리 것인가**

| 문헌 | 우리 것 (근거 없음, 조정 가능) |
|---|---|
| tilting box 를 고른 것 (A-R1) | 각도 고정 + 4초 유지 |
| 정적 안식각을 재는 것 (A-R1) | 이분 탐색 8회 |
| 거친 바닥의 필요성 (Zhou 2002) | 트리거 = 평균 변위 > 0.5r |
| μ 단조성 재현 목표 (C4 §8.1) | 관찰 구역 중앙 60% · 6층 · 램프 1초 |

**현재 관측** (Sequential Positions, 반복 90, 모멘텀 없음, 유지 4초)

```
μ = 0.2 / 0.3 / 0.4  →  7.25° / 13.26° / 17.64°      오차 −4.1 / −3.4 / −4.2°
```

**절편은 물리가 아니라 절차가 만든다** — 유지 시간 스윕이 그것을 보였다([m0-log.md](m0-log.md) #14).
크리프 누적이 가장 적은 조건(유지 1초)에서는 오차가 **−1.0 / −1.7°** 로 줄고,
이는 절차가 거의 개입하지 않는 단일 입자 시험의 −0.9~−2.5° 와 같은 크기다.

```
솔버의 마찰      1~2° 안에서 이미 정확
나머지 −2~3°     판정·유지 시간·벽 지지가 만든 것
```

→ **`μ` 확정은 절차의 계통 오차를 먼저 줄인 뒤에 한다.** `θ_stop` 전환이 후보([A-R5](../research/papers.md)).

**⚠ 안정성 선행 조건** — 측정 전에 **다지기만 하고 최종 높이를 확인**할 것.
6층이면 27.5cm 여야 하고, 그보다 크면 더미가 부푼 것이라 **그 위의 각도는 전부 무효**다.
반복 45 미만에서 이 조건이 깨진다 ([m0-log.md](m0-log.md) 실행 #12).

#### 3-0-C. 기둥 붕괴 — 3-2 관찰용

> 아래는 원래 안식각 측정 절차였다. **더 이상 각도 교정에 쓰지 않는다** —
> 문헌상 기둥 붕괴는 런아웃·최종높이를 종횡비의 함수로 보는 실험이고,
> 퇴적물 경사는 종횡비와 기둥반지름/입자지름 비에도 의존해 **재료의 안식각과 같지 않다**
> ([papers.md §A-R2](../research/papers.md)).
>
> 배치·정지 판정·계측은 그대로 유효하므로 **★덩어리 붕괴(3-2)를 눈으로 보는 장면**으로 남긴다.

#### 배치

**기둥 붕괴(column collapse).** 원기둥으로 격자 충전 + jitter, 가상 벽 안에서 정지시킨 뒤 **벽 제거**.

```
① 원기둥 통에 채운다        ② 벽을 끈다          ③ 무너져서 멈춘다

   ┃▒▒▒▒▒┃                    ▒▒▒▒▒
   ┃▒▒▒▒▒┃ H                  ▒▒▒▒▒               ▒▒▒▒▒
   ┃▒▒▒▒▒┃                    ▒▒▒▒▒          ▒▒▒▒▒▒▒▒▒▒▒▒▒
   ┗━━━━━┛                    ▒▒▒▒▒       ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒
      R                                   ─────────────────────
                                                ↖ 이 경사각
```

> **왜 기둥 붕괴인가** — 깔때기 쏟기는 쏟는 속도·낙하 높이·구멍 크기가 전부 변수라
> 같은 설정을 두 번 돌려도 다른 더미가 나온다. 회전 드럼은 **우리 XPBD에 입자 회전이 없어**
> 물리가 성립하지 않는다. 기둥 붕괴는 초기 배치가 격자 충전이라 완전히 결정적이고
> 시작 시점이 "벽 끔" 한 순간으로 명확하다 — 2-3을 만족하는 건 사실상 이것뿐이다.
>
> 덤으로 **터널 실험과 같은 코드를 쓴다.** 벽을 껐다가 무너뜨리는 것과
> 터널 입자를 지웠다가 무너뜨리는 것은 같은 조작이다.

**종횡비 `H/R ≈ 1`.** 기둥이 높으면 무너질 때 관성이 섞여 모래가 옆으로 튕겨 나가고,
최종 경사가 안식각보다 낮게 깔린다 — 안식각이 아니라 "얼마나 세게 무너졌나"를 재게 된다.
문헌(Lube 2004 / Lajeunesse 2004)의 경계가 대략 `H/R ≈ 1.7`이라 여유 있게 1로 잡는다.

```
5천 입자 → 벌크 0.51 m³ → R = H = 54.6 cm  (각 21.8 입자)
```

`W = 0`, **점착 제약 완전 비활성.** 마른 모래다.

#### 절차

충전 → 벽 제거 → 정지 판정(2-2) → 각 측정

#### 판정

밑동 반지름 대비 높이(`atan(H/R)`)는 **쓰지 않는다.** 바닥 마찰과 관성 확산에 오염된다.

```
① 표면 입자만 추출 (이웃 수 임계 이하 = 노출)
② 각 표면 입자의 지역 법선 → 지역 경사각
③ 바닥 3입자층 제외(바닥 마찰), 꼭대기 반경 3입자 제외(단일 입자 노이즈)
④ 히스토그램 최빈값 = 안식각
```

> `H/R`이 작으면 꼭대기가 안 무너지고 평평하게 남을 수 있다(안쪽 심이 버팀).
> 그래서 각은 **옆면 경사**에서 재지, 꼭대기에서 밑동까지 이은 선에서 재지 않는다.

**통과: 34° ± 3°** (`params.md` 온대 석영 `talusDry` 34°)

#### 실패 분기 — 타임박스 3일

스윕 축은 `μ` × `substep` × 반복. 3×3×3 = **27 실행**, 배치로 자동.

```
μ         0.7  ·  1.0  ·  1.3       ← 0.7은 실행 #1의 값 (앵커)
substep     5  ·   10  ·   20
반복        1  ·    2  ·    4
```

**앵커 셀** — `μ=0.7, substep=10, 반복=2`는 실시간 뷰에서 이미 26.5°가 나온 설정이다.
배치가 이 셀에서 같은 값을 재현하지 못하면 나머지 26개를 믿을 수 없다.
배치와 실시간이 같은 코어를 쓰는지 검사하는 것이고, **M0-b에서 GPU를 CPU와 대조하는 방식이 이것 그대로다.**

찾는 것은 값이 아니라 **반응의 모양**이다.

| μ축 | substep축 | 해석 |
|---|---|---|
| 비례해서 오름 | — | 공식은 맞다. 값만 맞추면 된다 |
| 포화 | — | 클램프가 하중을 못 받는다 |
| — | **올릴수록 각이 내려감** | `μ·침투량` 클램프의 `dt²` 누수 지문 → 공식 교체 |

| 증상 | 대응 |
|---|---|
| 낮다 (< 31°) | `μ` 상향 → 그래도면 반복·substep 부족 (수렴 전에 미끄러짐) |
| 높다 (> 37°) | `μ` 하향 → 또는 접촉이 과도하게 뻣뻣해 얽힘 |
| 안 잡히고 진동 | substep 부족 / 컴플라이언스 문제 |
| **3일 초과** | **마찰 클램프 공식 자체를 의심.** Macklin 2014 friction 절 원문으로 |

여기서 확정된 `μ`·substep·반복이 나머지 넷의 고정 상수가 되고,
`system-design.md` §4의 "15반복"을 갱신한다.

#### 3-0-D. 원통 들어올리기 (hollow cylinder) — 기각 (#20)

**원통에 채우고 계단식으로 들어올려** 흘러나온 원뿔의 각을 재는 절차였다.
"매 단계 완전히 멈추면 준정적이 정의상 보장된다"가 전제였는데, **전제가 틀렸다.**

```
계단 | 높이 | 정지프레임 | 최대속력 | 이동입자
   2 | 10cm |   3000★    |   299    |   322
   3 | 15cm |   3000★    |   650    |  1599     ← 바닥 15cm 를 푸는 순간 전체가 간다
```

계단식의 전제는 "조금 풀면 그만큼만 움직인다"인데, **높은 기둥은 밑동이 풀리면 위 전체가
지지를 잃는다 — 파괴가 국소적이지 않다.** 계단을 잘게 나눠도 임계 노출량에서 똑같이 간다.
결과는 원뿔이 아니라 **중심이 꺼진 둔덕**(격렬한 붕괴가 모래를 바깥으로 던졌다).

> **상충** — 높은 기둥(H/R 2.5)은 한 번에 붕괴하고, 낮은 기둥(H/R 1.0)은 평평한 꼭대기가 남는다.
> 원통으로는 이 상충을 못 벗어난다. → 3-0-A 부어 쌓기.

**남긴 것** — 거친 바닥 범위(#19) · 잡음 바닥 계기(#19) · 벽 SP 규약(#18) 은 전부 이 절차에서 나왔고
부어 쌓기에도 그대로 적용된다. 코드(`RunConeLift`)는 대조용으로 남긴다.

### 3-1. 터널 — 차단

입자를 지워 30cm 구멍을 뚫었을 때 천장이 버티는가.

#### 배치

**90 × 60 × 60 cm 블록**, 하단 중앙에 **지름 30cm 관통 터널**. 천장 두께 30cm(6 입자층).
약 **2,800 입자**.

단면 두 종류를 **둘 다** 잰다.

| 단면 | 성격 | 근거 |
|---|---|---|
| **원형(아치)** | 관대 — 전체가 압축 | papers: "같은 폭이면 아치가 훨씬 안정적" |
| **사각** | 가혹 — 천장이 인장 | 점착력이 꼭 필요한 경우 |

둘의 차이가 곧 **아치 이득의 정량값**이고, M6 터널 도구 설계로 넘어간다.

> **기대값을 먼저 계산해 둔다.** 천장을 양단 고정 보로 보면 `σ = γL²/2t ≈ 2.4 kPa`이고,
> 젖은 모래의 인장강도는 문헌상 **0.5~3 kPa** ([papers.md §B-S1](../research/papers.md)).
> → **사각은 아슬아슬, 아치는 여유**가 물리적으로 예상되는 답이다.
> **시뮬이 사각을 여유롭게 통과시키면 통과가 아니라 의심할 신호다** (§B-S5).

#### 절차

충전, `W = W_optStart`(0.15) → 결합 생성 → **터널 입자를 한 번에 제거** → 정지 판정

> 한 번에 제거는 의도적으로 가혹한 조건이다(순간 하중 재분배).
> 실제 플레이는 브러시로 점진적이므로, 한 번에서 서면 그냥 통과다.
> 안 서면 점진 제거로 재시도한다.

**★ 세 실행이 한 묶음이다.** 본 실행 하나로는 원인을 못 가른다.

| 실행 | 설정 | 기대 |
|---|---|---|
| 본 실행 | `W = 0.15`, 지름 30cm | 아치 통과 / 사각 경계 |
| **★ 대조군** | **점착 완전 비활성**, 나머지 동일 | **무너져야 한다** |
| **★ 지름 스윕** | `W = 0.15`, D ∈ {20, 30, 40, 60, 80} cm | 무너지는 지름 `D_crit` |

**대조군이 왜 필요한가** — D/d = 30/5 = **6**이고, 사일로에서 배출구/입자 비가 5 부근이면
**점착이 0이어도 아치가 저절로 생긴다** ([papers.md §B-S4](../research/papers.md)).
대조군이 서면 본 실행의 통과는 점착이 아니라 **기하학이 낸 답**이고, 그걸 모른 채 M0-b로 넘어가게 된다.

**스윕은 이진 판정을 곡선으로 바꾼다.** "30cm가 서는가"는 답이 하나뿐이라 원인을 못 가르지만,
`D_crit`은 해상도를 바꿔 비교할 수 있다. 무너지는 큰 구멍은 빨리 끝나므로 **비용이 거의 안 든다.**

#### 판정

**셋 다** 통과해야 한다.

```
천장 잔존    터널 상방 30cm 구간에서 변위 > 2r 인 입자 < 5%
관통 유지    터널 중심선 반경 10cm 안에 입자 없음
★ 대조군 붕괴  점착 0 실행이 같은 기준으로 무너진다   ← 서면 위 둘의 통과가 무효
```

둘째가 필요한 이유: 천장이 살짝 처져도 첫째는 통과하는데,
그 처짐이 구멍을 막으면 **게임적으로는 실패**다.

셋째가 필요한 이유: 위 둘은 **왜 섰는지**를 묻지 않는다. 대조군이 그 질문을 대신한다.

#### 실패 분기 — 타임박스 2.5cm 4일 + 1.25cm 진단 2일

```
아치는 서고 사각만 무너짐  → 정상. 통과로 친다. M6 터널 도구를 아치 단면으로

둘 다 무너짐 (4일 안)     → 먼저 3-3 의 c[Pa] 를 본다. 2.4 kPa 에 못 미치면 물리대로 무너진 것
                          → W를 고원 안에서 상향 (0.15 → 0.4)
                          → breakStretch 1.3 → 1.5
                          → 결합 슬롯 12 → 20  ※ bondsActive로 슬롯 부족 여부 먼저 확인

★ 대조군도 섬        → 통과 취소. 점착이 아니라 기하가 낸 답이다
                       → 지름 스윕을 1.25cm 에서 반복해 D_crit 을 비교 (아래)

4일 초과 → 1.25cm 스윕 (튜닝하지 않는다)
```

**해상도 사다리는 탈출구가 아니라 진단이다.** 한 칸 내려갈 때마다 8배다.
그래서 1.25cm 실행에서 보는 것은 **통과 여부가 아니라 `D_crit` 두 값의 관계**다.

```
D_crit(2.5cm) ≈ D_crit(1.25cm)   cm 로 수렴   → 물리를 풀고 있다. 5cm 채택
D_crit ∝ d    둘 다 6입자 근처              → 해상도가 답을 정한 것.
                                              30cm 결과는 의미 없다. ★ GPU 착수 금지
```

| 반경 | 터널 가로 | 성 한 채(2m³) | 예산 30만으로 |
|---|---|---|---|
| **2.5cm (확정)** | 6 | 2만 | **성 15채** |
| 1.25cm | 12 | 16만 | **성 1.9채** ← 누적이 죽는다 |
| 6.25mm | 24 | 128만 | 불가 |

"성이 여러 채 남아 각자 마르고 무너진다, 보러 가는 것 자체가 콘텐츠"가 게임 정의에 있다.
한 칸만 내려가도 그게 사라지므로, 1.25cm 실행의 목적은 통과가 아니라 **원인을 가르는 것**이다.

> ⚠ **★ 이 검증이 쉽게 통과하는 것 자체가 신호일 수 있다.**
> 전단대 두께는 입경의 8~16배 = **40~80cm** 라 터널 지름(30cm)보다 크다.
> 붕괴 메커니즘이 격자에 안 들어가고, **오차는 과대 안정 쪽으로만 생긴다**
> ([papers.md §B-S5](../research/papers.md)).
> 그래서 M0의 진짜 차단 위험은 3-1이 아니라 **3-2**다 — 과대 안정한 시뮬은 터널을 쉽게 통과시키고,
> 그 다음 **마른 성이 안 무너져서** 게임의 정체성을 죽인다.

### 3-2. 덩어리 붕괴 — 차단 ★

`W`를 서서히 낮출 때 버티다 갑자기, 덩어리로 무너지는가.
**이 게임의 정체성이다.** 부슬부슬 흩어지면 하이트필드와 다를 게 없어지고,
그러면 입자 계층을 도입한 이유가 사라진다.

#### 배치

**3-1의 블록을 그대로 이어받는다.** 터널이 선 상태에서 시작.

> 터널 뚫은 성이 말라서 무너지는 것은 게임에서 실제로 일어나는 일이고, 별도 씬을 만들 이유가 없다.
> 타임박스가 `+2일`뿐인 것도 이 때문이다.
>
> 대가: 3-1이 실패하면 3-2를 못 잰다. 독립 씬으로 떼면 +4일이 되므로 묶는 쪽을 택했다.

#### 절차

**눈금자를 먼저 만든다.** 결과를 이미 아는 두 실행으로 축을 세운다.

| | 설정 | 기대 |
|---|---|---|
| 하한 (부슬부슬) | 점착 완전 비활성 | `massWeightedMeanSize` ≈ **1** |
| 상한 (덩어리) | cohesion 고정 최대 + `breakStretch` 3.0 | ≈ **이동 입자 전체** |

> 이 둘은 답을 얻으려고 돌리는 게 아니라 **지표가 두 극단을 갈라내는지 확인하려고** 돌린다.
> 못 가르면 지표가 나쁜 것이고, 지표를 고친다.
> 이 절차 덕분에 합격선을 미리 지어낼 필요가 없어진다.

본 실행:

```
① W를 전역 선형 하강  W_optStart(0.15) → 0,  2분 상당 (배치는 최대 속도)
② 매 프레임 CSV
③ 완전 붕괴 또는 W=0 도달까지
```

> 선형·전역인 이유: `ΔW` 폭을 재려면 `W`가 균일하게 변해야 한다.
> 실제 건조는 표면부터 진행하지만 **그건 M5의 일**이다. 여기서 섞으면 지표가 무엇을 재는지 모르게 된다.

#### 판정

```
주   massWeightedMeanSize 가 하한에 붙지 않고 상한 쪽으로 뚜렷이 이동
     ← 구체적 선은 눈금자 측정 후 확정
부   finesRatio · ΔW 폭(붕괴 10%→90%) · 첫 파단 → 전면 붕괴 시간
눈   덩어리 / 애매 / 부슬부슬을 같이 기록
```

> ★ **지표와 눈이 어긋나면 눈을 믿고 지표를 고친다.**
> 이 게임의 요구사항은 숫자가 아니라 보이는 것이다.

주 지표를 이렇게 정의한 이유 — "최대 연결 요소 / 전체"는 성이 대부분 서 있고 모서리만 떨어지면
최대 요소가 **서 있는 본체**라 값이 크게 나온다. 그래서 **이동한 입자만** 골라 파편을 세고,
크기 분포를 질량가중 평균으로 접는다.

> ★ **여기서 재는 현상의 이름은 [순차 파단](../research/terms/progressive-failure.md)이다.**
> 결합이 각자 끊어지면 부슬부슬, 한 점에서 시작해 면을 따라 번지면 덩어리다.
> ⚠ 그런데 **Jacobi + 입자별 평균**(응력 집중을 뭉갠다)과 **접촉 α = 0**(탄성에너지를 저장 안 한다)이
> 둘 다 그 전파를 억제하는 방향이다. **부슬부슬로 나오면 원인 후보 1번은 점착 파라미터가 아니라 이 둘이다.**

```
떨어진 입자 500개일 때
  낱알로 흩어짐   500개짜리 파편 1개씩  →   1
  10덩어리        50개씩                →  50
  한 덩어리       500개 하나            → 500
```

> 큰 덩어리 하나 + 낱알 먼지가 섞이면 값이 큰 덩어리 쪽으로 쏠린다.
> 그래서 `finesRatio`를 같이 기록한다. 덩어리도 떨어지고 먼지도 나는 건 자연스러우니
> 실패로 치지 않되 값은 남긴다.

#### 실패 분기 — 타임박스 +2일

| 증상 | 대응 | 등급 |
|---|---|---|
| 파편이 잘다 (하한 근처) | `breakStretch` 상향 → 슬롯 수 상향 → 파단 조건에 이웃 파단 수 가중(연쇄 강화, **모델 변경**) | 차단 |
| ″ 위 셋으로도 안 되면 | **결합 연화 도입** — 파단 직전 강성을 깎아 응력을 이웃으로 넘긴다 (§2-6 ⑦ 이 지적한 없는 가지). 연속체 선례 Matter `DPSoft` = `exp(−ξ·ε_pl_dev)`. ⚠ **결합당 이력으로 번역이 필요 — 설계 미정** | 차단 |
| **2일 초과** | **점착 모델 재설계. GPU 착수 금지** | 차단 |
| `ΔW`가 넓다 (질질 끎) | `W_dry`~`W_optStart` 간격 축소 — **그 축소 배율이 곧 "곡선 과장 정도" 산출물** | 정보성 |

두 실패의 성질이 다르다. 첫째는 **구조 실패**라 설계가 바뀌고,
둘째는 **튜닝 실패**라 곡선만 과장하면 된다.

### 3-3. 벽 최소 두께 — 정보성

`W`를 올리면 수직 벽이 선다. **얼마나 얇게까지 되는가.**

#### 배치

높이 60cm · 길이 60cm 고정, 두께만 스윕.

```
t ∈ {5, 7.5, 10, 15, 20, 30} cm   =  1, 1.5, 2, 3, 4, 6 입자층
```

1입자층을 일부러 넣는다. **표현 한계를 실측하기 위해서다.**

#### 절차

`W = W_optStart`, 결합 생성 → 지지 벽 제거 → 정지 판정

#### 판정

**통과선 없다.** 산출하는 건 두 한계의 간격이다.

| | 정체 | 플레이어 경험 |
|---|---|---|
| **물리 한계** | 인장이 점착을 넘음 | 깎다가 **무너진다.** 정직하고 배울 수 있다 |
| **표현 한계** | 입자 반경. 1~2층 두께엔 내부 구조가 없다 | 이상한 거동. 모래가 아니라 구슬 한 줄 |

```
물리 한계 30cm ≫ 표현 한계 5cm   → 좋다. 플레이어는 물리만 만난다
물리 한계 7cm  ≈ 표현 한계 5cm   → 나쁘다. 정직하게 무너지기 전에 이상한 거동부터 만난다
                                   → 반경 재검토. 단 이건 M6에서 터진다
```

> **두께를 제한하는 코드는 어디에도 없다.** 깎다가 무너지는 것은 규칙이 아니라 결과다 —
> 얇아지면 단면이 줄고, 인장이 커지고, 점착을 넘으면 끊어진다.
> 이 숫자를 읽는 코드는 없다. 경고 UI도 붙이지 않는다.

#### ★ 3-3-B. 점착의 자 (`c` [Pa]) — 별도 배치가 필요하다

**마찰에는 34°라는 자가 있는데 점착에는 없다.** `α = 1/cohesion(W)` 는 솔버 내부 숫자라
그대로는 터널 결과를 문헌과 대조할 수 없다.

> ⚠ **위의 얇은 벽 스윕으로는 `c` 를 못 뽑는다.** 자립 박벽은 **좌굴·전도**로 무너지고
> (그게 Pakpour 의 `h ∝ R^(2/3)`), 절토면 파괴와는 다른 모드다. **배치를 따로 둔다.**

**배치** — 3-1 의 블록을 그대로 쓰되 **한 면만 지지 제거**(절토면), 높이를 스윕한다.

```
   ▒▒▒▒▒▒▒│        높이 h ∈ {30, 45, 60, 75, 90} cm
   ▒▒▒▒▒▒▒│  ←── 이 면의 지지만 제거. 뒤는 모래가 받친다
   ▒▒▒▒▒▒▒│        (박벽과 달리 좌굴이 안 생긴다)
   ━━━━━━━━
```

**판정·역산**
```
H_c = (4c/γ)·tan(45° + φ/2)        Terzaghi 임계 절토고 (papers.md J-5)
→ 무너지기 시작한 높이가 곧 H_c.  φ 는 3-0 이 준 값(34°)
→ c = H_c·γ / (4·tan(45°+φ/2))

γ = 15,700 N/m³ 기준   H_c 30cm → c ≈ 0.6 kPa
                       H_c 60cm → c ≈ 1.25 kPa
                       H_c 90cm → c ≈ 1.9 kPa
```
목표 1.5 kPa (§B-S2 의 결합력 2.5N ≈ 자기 무게 1.5배) · 터널 요구 2.4 kPa (§B-S1) 과 비교한다.

**교차검증 — 3-0 경사판을 `W>0` 로 한 번 더 돌린다 (거의 공짜)**
```
c = γ·z·cosθ_m·(sinθ_m − cosθ_m·tanφ)        무한사면 + 점착
                                              z 층 두께, θ_m 사태 개시각
```
장비·판정이 이미 서 있고, **문헌도 정확히 이 양을 준다**
(Albert et al. 1997, "Maximum angle of stability in wet and dry spherical granular media" → A-R4).
두 경로가 같은 `c` 를 내면 자를 믿을 수 있다.

> ⚠ **경사판에는 측정 상한이 있다.** 층이 얇으면 구동하는 무게가 작아서, `c` 가 크면
> 90°까지 기울여도 안 무너진다. `cosθ_m·sin(θ_m−θ_m0)` 의 최대가 `(1−sinθ_m0)/2` 인 데서
> ```
> c_max ≈ 0.24 · γ · z            (θ_m0 = 38° 기준)
> ```
> | 층 수 | `z` | 잴 수 있는 `c` 상한 |
> |---|---|---|
> | **6층 (현재 3-0-B 설정)** | 27.5 cm | **1.05 kPa** |
> | 9층 | 41 cm | 1.6 kPa |
> | 12층 | 55 cm | 2.1 kPa |
>
> **6층 그대로 젖은 실행을 하면 목표 1.5 kPa 를 못 잰다** — "안 무너짐"만 나온다
> (그래도 `c > 1.05 kPa` 라는 하한은 얻는다). 자로 쓰려면 **9층 이상.**
> **수직 절토에는 이 상한이 없어서** 주력이 그쪽이다 — 높이 스윕이 0.6~1.9 kPa 를 직접 덮는다.

> ⚠ **선행 조건 둘.**
> ```
> ① 점착 제약 구현      현재 코어는 WGlobal 을 필드로만 갖고 솔버가 읽지 않는다 (결합 배열 없음)
> ② μ·substep·반복 확정  안 굳으면 기준선 θ_m0 도 같이 움직여 차분이 무의미해진다
> ```
> **순서: 3-0 확정 → 점착 구현 → 3-0'(W>0) · 3-3-B → 3-1.**
> 3-0 과 동시에 돌릴 수 있는 것은 위의 "마른 `θm` 층수 3 실행"뿐이다.

**그래서 실행 순서는 3-1보다 이 실험이 먼저다.** 배치가 독립이라 가능하고,
`c[Pa]` 를 모르면 터널이 무너져도 **점착이 약한 건지 해상도 문제인지 못 가른다.**
(등급은 여전히 정보성 — 값이 안 나와도 진행은 막지 않는다.)

#### 전달

```
M1 검증   "얇은 벽이 부풀지 않는가" 의 대상 두께
M6 도구   깎기 브러시 크기의 하한
3-1 전제  c[Pa] — 터널 실패의 원인을 가르는 자
```

---

### 3-4. 성능 — 정보성

몇 개까지 도는가. **별도 실험을 거의 만들지 않는다** — 배치가 이미 `stepMs`를 남긴다.

#### 절차

입자 수 스윕 `{1천, 3천, 5천, 1만, 2만}`(성 한 채 예산 상한), 각 정지 상태 100프레임 평균.

#### 판정

**통과선 없다.**

```
① CPU 단일 스레드 기준선         → M0-b GPU 이득 측정용
② 스케일링 지수                  → 공간 해시가 제대로 도는지
③ 정렬 / 이웃 / 제약 투영 비율    → M0-b에서 무엇부터 GPU로 옮길지
```

> ⚠ ②가 O(n²)로 나오면 성능 문제가 아니라 **버그**다. 그건 고친다.

M0-a는 의도적으로 CPU 단일 스레드다. 여기 fps는 출하 성능에 대해 아무것도 말해주지 않는다.
**성능이 차단으로 승격되는 것은 M0-b다** (§4).

---

## 4. 정족수와 진행 규칙

> **차단** = 못 넘으면 **M0-b(GPU 이식)에 착수하지 않는다.** 설계로 돌아간다.
> **정보성** = 값을 기록해 다른 마일스톤의 예산·범위에 반영하되, 진행은 막지 않는다.

3계층이다.

| 검증 | 등급 | 무엇을 막는가 | 실패 시 |
|---|---|---|---|
| 안식각 | **전제** | 나머지 4개의 **실행 자체** | 반복·substep·`μ` 수정 후 재시도 |
| 터널 | **차단** | M0-b 착수 | 무점착 대조군 + `D_crit`(2.5/1.25cm) → 해상도 문제 / 모델 문제 |
| 덩어리 붕괴 | **차단** | M0-b 착수 | 점착 모델 재설계 |
| 벽 최소 두께 | 정보성 | — | M1·M6 제약으로 기록 |
| 성능 (M0-a) | 정보성 | — | M0-b GPU 이득의 기준선으로 기록 |
| 급작스러움 (`ΔW`) | 정보성 | — | `strengthCurve` 과장 배율 초기값으로 기록 |
| *성능 (M0-b)* | *차단* | *M1 착수* | *입자 예산 축소 → 성 크기 제한* |

**안식각이 나머지와 층이 다른 이유** — 게임이 34°를 필요로 해서 재는 게 아니다.
`μ` 마찰 클램프가 제대로 도는지 확인하는 유일한 방법이라서 잰다
(`system-design.md`: "안식각 34°가 파라미터가 아니라 결과로 나온다").
여기서 34°가 안 나오면 벽·터널·붕괴를 **고장난 저울로 재는 것**이 되어, 숫자가 나와도 못 믿는다.
그래서 순서상 제일 먼저, 단독으로 통과시킨다.

**벽 두께를 정보성으로 둔 이유** — 벽과 터널은 물리적으로 같은 축(지지 없는 스팬 대 두께)이고
**터널이 더 가혹하다**(천장은 인장, 벽은 압축). 터널이 통과하면 벽은 따라온다.
그리고 이 값이 먹여 살리는 건 M0-b가 아니라 M2·M6의 도구 설계다.
**단 실행 순서는 벽이 먼저다** — 벽에서 역산하는 `c[Pa]`가 터널 실패의 원인을 가르는 자이기 때문
(3-3 부수 산출물). 등급과 순서는 별개다.

## 5. 타임박스

**타임박스는 추정이 아니다.** 추정은 "얼마나 걸릴까"의 예측이고 틀려도 된다.
타임박스는 **"얼마나 쓰면 멈추고 설계를 의심할 것인가"의 결정 규칙**이다.

그리고 **구현이 아니라 튜닝에만 건다.** 구현은 안 되면 계속 해야 한다.
튜닝은 무한히 할 수 있고, 그게 M0가 존재하는 이유를 정확히 무효화한다.

### 추정 — 풀타임 환산 3~5주

| 구간 | 작업일 | 변동 요인 |
|---|---|---|
| UE5 C++ 모듈 뼈대 + 액터 + 디버그 드로우 | **2~5** | ★ 가장 안 보인다. 툴체인 운 |
| XPBD 코어 (접촉 + 마찰) | 2~3 | 코드는 짧다. 디버깅이 시간을 먹는다 |
| 점착 결합 목록 + 수명 | 1~2 | |
| 계측 + 배치 하네스 | 2 | |
| 실험 실행 + 튜닝 | 5~11 | 아래 상한 |
| | **12~23일** | |

### 상한 — 이것만이 약속

| 튜닝 구간 | 상한 | 넘으면 |
|---|---|---|
| 안식각이 34°에 안 맞음 | **3일** | 마찰 클램프 공식 자체 의심. Macklin 2014 원문으로 |
| 터널 — 2.5cm 튜닝 | **4일** | 1.25cm 진단으로 |
| 터널 — 1.25cm 진단 | **2일** | 튜닝하지 않는다. 1회 실행 후 판정 |
| 덩어리 붕괴 | **+2일** | 점착 모델 재설계 |
| | **총 11일** | |

이 상한을 넘는다는 건 "더 하면 될 것 같다"가 아니라
**"M0가 답을 줬다 — 아니오라고"** 라는 뜻이다.

### 3일차 캘리브레이션 체크포인트

처음 해보는 일이라 추정에 근거가 없다. 그러니 추정하지 말고 **일찍 한 번 실측한다.**

> **3일차: "안식각 실험이 어쨌든 도는가?"**
> 34°가 나오는지는 아직 묻지 않는다. **입자가 쏟아지고 멈추고 각도가 찍히는지만** 본다.

```
3일에 도달   → 위 추정이 대체로 맞다. 그대로 간다
5일 걸림     → 전체를 1.7배 하고 다시 쓴다
8일 초과     → UE5 C++ 자체가 병목이다. M0 계획이 아니라 그것을 먼저 해결한다
```

한 번 실측하면 나머지 추정이 갑자기 정확해진다. 그래서 가장 짧고 독립적인 항목(안식각)을
맨 앞에 두는 것이 순서상으로도 맞다 — 어차피 나머지 넷의 전제이기도 하다.

## 6. M0가 끝났을 때 남는 것

```
답 5개        차단 2개의 예/아니오 + 정보성 3개의 값

확정 상수     μ · substep · 반복      ← 3-0이 뽑음. system-design §4 "15반복"을 갱신
              결합 슬롯 실수요         ← bondsActive 분포. 12개가 충분한가
              breakStretch            ← 3-1 / 3-2가 뽑음
              곡선 과장 배율           ← 3-2가 뽑음. W_dry~W_optStart 간격 축소율

배치 하네스   ★ 버리지 않는다
```

마지막 줄이 중요하다. 이 문서는 "여기서 만든 코드는 버려도 된다"로 시작했지만 **하네스만은 남는다.**
GPU 이식에서 가장 무서운 것은 느린 게 아니라 **조용히 틀리는 것**이고,
같은 씬·같은 시드로 CPU 결과와 대조할 수 있는 것이 유일한 방어다.

`FSandSpike::Step()` 내부만 RDG로 갈아끼우면 나머지는 그대로 쓴다.
