## 실행 #1 — 메시 코어 첫 동작 (2026-10-26)

`Mesh/SandSurface.{h,cpp}` (`FSandSurfaceBuilder`): 이웃 격자 · 표면 입자(이웃 < 25) · 커널(등방 B-cubic / Yu & Turk 이방성 / Zhu & Bridson) · 표면 입자 주변 띠 격자 · 장 · Surface Nets · OBJ. 셀 2.5cm · h 5cm · r_i 10cm · λ 0.9 · k_r 4 · N_ε 25 · k_n 0.5 · IsoFrac 0.5.

- **부스러기**: 셀 = 반경이라 입자 하나를 판정할 해상도가 아니다. 1.25cm 이하로 다시.

- 방향 · 닫힘: 부피비가 0.9~1.1 로 나와 삼각형 방향은 일관된다.

## 실행 #2 — 지표 재정의 · 셀 1.25 · 얇은 벽 원인 · 뿌리기 (2026-10-26)

**바꾼 것**: ① 판 지표 = 메시 윗면 RMS ÷ **입력 위층 입자 높이 RMS** (같은 영역, 입력 0.174R) ② 장 계산을 입자별 지지 AABB **뿌리기**(원자 덧셈)로 — 판 등방 장 131 → 20 ms (셀 2.5) ③ 정점 번호 · 면 생성 층별 병렬 ④ 띠 기준(`BandNEps` 25)을 커널 N_ε 와 분리 — N_ε 를 낮추면 띠가 사라지던 문제 ⑤ 스위치 `-neps -kn -knramp -minsigma -isofrac -lambda -kr`.

**얇은 벽이 얇던 원인**: 2 층 벽은 입자 이웃이 10~20 개라 전부 N_ε(25) 이하 → Yu & Turk 의 "구 복귀" 커널 k_n = 0.5 (지지 = h = 5cm) 로 떨어져 벽이 얇아진다. N_ε 를 낮추면 이번엔 이방성 커널이 두께 방향으로 납작해져 역시 얇다 (0.50~0.64, λ · k_r · σ 하한 어느 것도 못 고침).
- **수정 (우리 추가, `KnRamp`)**: 구 복귀 크기를 이웃 수로 키운다 — k_n(N) = 0.5 + 0.5·min(1, N/8). 고립 입자는 작은 구(보이게), 이웃 8 개 이상은 등방 h 크기.

**스윕 (이방성, 셀 1.25)** — 판 = RMS비 · 벽 = 두께비 · 부스러기 = 구형도 1/3/7

## 실행 #3 — 효율 1차 (이웃 셀 · 띠 폭 · 뿌릴 입자 거르기) (2026-10-26)

## 실행 #4 — 효율 단계 A: 표면 입자 판정에 치우침 추가 (2026-10-26)

**문턱 측정 (`-devdump`, 셀 1.25)**

## 실행 #5 — 효율 단계 B: 부분 영역 뿌리기 (2026-10-26)

`Block`(기본 32, `-block=`, 0 = #3 원자 뿌리기): 격자점을 B³ 영역으로 나누고, 입자를 지지 AABB 가 겹치는 **띠 있는 영역** 목록에 넣는다 (counting sort). 영역마다 스레드 하나가 지역 배열에 뿌리고 자기 띠 점에만 써 넣는다 — 원자 없음. 영역 안에서는 줄마다 **띠 점 x 범위만** 계산, 줄 안 G·r 은 증분, |Gr|² < 4 로 먼저 거른다. 작업 스레드 10 · 논리 코어 12. 띠 7.5 · SurfDev 0.15 · 셀 1.25.

```
                    기둥 장 = 띠 · 등위값 · 거르기 · 뿌리기       기둥 메시   판 뿌리기
B = 0 (원자, #4)     118 = 15 · 13 · 17 · 73                       54          73
B = 16              91 = 17 · 15 · 13 · 46                        64          57
★ B = 32            79 = 23 · 13 · 13 · 31 (목록 2)               38          35
B = 64              115 = 19 · 13 · 10 · 74                       52          54
```
- **메시 동일**: 판은 B 0/16/32/64 모두 정점 72359 · 삼각형 144724 · 지표 같음. 기둥은 시뮬 재실행마다 표면 입자가 4140~4220 으로 달라 정점이 ±0.5% 흔들린다 (B 와 무관). 판 · 벽 · 부스러기 지표 변화 없음.
- B = 64 는 기둥에서 영역이 적어(125 개 중 활성 일부) 스레드 10 개가 고르게 못 나눈다 — 계획 §1 의 예상대로. **B = 32 채택.**
- 뿌리기 73 → 31 ms (2.4 배). 계산 수 24.8M (기둥) — 이상적이면 개당 ~2 ns × 24.8M / 10 스레드 ≈ 5 ms 라 아직 영역 간 부하 불균형 · 스칼라 비용이 남는다. 측정 잡음이 크다 (같은 설정에서 이웃 단계 23~32 ms).
- **통과선(장 + 메시 ≥ 5 배) 미달**: 172 → 117 ms (1.5 배). 기둥 합 210 → 155 ms.

**남은 시간이 어디 있나** — 이제 한 곳에 몰려 있지 않다:
```
기둥 155 ms = 이웃 31 · 커널 7 · 띠 표시 23 · 등위값 13 · 거르기 13 · 뿌리기 31 · 메시 38
```
- 띠 표시 · F 초기화 · 메시 셀 훑기가 **전역 조밀 격자 311만 점** 전체를 돈다 (띠 점은 77만, 정점 8.8만). splashsurf 는 영역 단위로 파이프라인 전체(장 + MC)를 돌린다 — 우리는 뿌리기만 영역화했다.
- 셀 1.25 의 띠 77만 점은 예산 기준(20만 셀)의 4 배. 계산 수 자체(24.8M)가 이상적 스칼라 5 ms · SIMD 8 폭이면 ~1 ms 수준.

## 실행 #7 — 효율 단계 C: 뿌리기 줄 루프 SIMD (2026-10-27)

`Simd`(기본 8, `-simd=0/4/8`): 부분 영역 뿌리기의 줄 루프를 SSE 4 폭 · AVX 8 폭으로 (런타임 CPU 확인, 레인 값은 GR0 + k·DG 로 직접, B-cubic 은 blend · 마스크, 꼬리는 좁은 폭으로). AVX 는 float 연산만 써서 AVX2 · FMA 불필요.

```
(B 32 · 띠 7.5 · 셀 1.25)   판 뿌리기   기둥 뿌리기   기둥 합
스칼라                      44          53            133
SSE 4                       31          34            110
AVX 8                       29 / (250)  35 / 38       113 / 112
```
- (250) 은 같은 설정 반복 중 한 번 튄 값 — PC 부하로 본다 (기둥은 같은 실행에서 38).
- **메시 동일**: 판 정점 72359 · 삼각형 144724 · 지표 전부 그대로 (레인 직접 계산이라 증분과 반올림이 달라도 결과 같음).
- **통과선(뿌리기 ≥ 2 배) 미달**: 스칼라 → SIMD 1.4~1.5 배, SSE 와 AVX 차이 없음. 계산 24.8M 을 10 스레드로 35 ms → **계산당 ~14 스레드·ns** — 산술(레인당 ~1 ns)이 병목이 아니다.
- 추정 원인 (미확인): ① 줄이 짧다 — 커널 AABB ∩ 띠 x 범위라 한 줄 몇~십여 점, 8 폭이 덜 찬다 ② 입자 · 줄마다 드는 고정 비용 (G·r0 · 띠 범위 검사 · 빈 줄) ③ **영역 간 부하 불균형** — 활성 영역이 기둥 표면에 몰려 일부 영역이 오래 걸린다.

**효율 계획 A~C 결산 (기둥 2만, 셀 1.25)**: 342 ms (#3 띠 전체) → 210 (A) → 102~118 (B) → 110~113 (C). 판 420 → 67~75. 메시 품질 그대로. 목표 2.5 ms 까지 **약 40 배**.

**다음 판단 자료**: 원인 ①~③ 중 무엇인지 재고 (영역별 시간 · 줄 길이 분포), CPU 로 몇 배가 더 남았는지 추정 → GPU 메시화(milestones 실패 분기) 여부를 사용자와 결정.

## 실행 #8 — 뿌리기가 느린 원인 측정 (2026-10-27)

영역별 시간(준비 = 줄 띠 범위 · 뿌리기 · 써 넣기) · 줄 수 · 상위 영역 시간을 잰다 (`FSplatProfile`, 로그 "뿌리기 원인"). 띠 7.5 · 셀 1.25, 스레드 10.

```
                  병렬 벽   스레드 합 (준비 뿌리기 써넣기)   상위 영역        줄 (계산 비율)   줄당 점   계산
기둥 B32 AVX      73        254 (22 219 13)                 27 25 22         560만 (55%)      8.2      25.0M
기둥 B32 스칼라   41        198 ( 9 181  8)                 15 14 12         561만 (54%)      8.2      24.8M
기둥 B16 AVX      30        204 (35 162  7)                 23 22  9         571만 (63%)      6.8      24.6M
판 B32 AVX        25        103 ( 8  88  7)                  8  4  2         337만 (71%)     10.0      23.9M
판 B32 스칼라     39        165 ( 8 150  7)                 16 15  3         337만 (71%)     10.0      23.9M
```

**판정**
- ① **줄이 짧다 — 확인.** 계산하는 줄의 평균 길이가 7~10 점. AVX 8 폭이면 줄마다 벡터 한 번 + 꼬리(SSE · 스칼라)라 레인이 반쯤 빈다. 기둥은 줄의 45% 가 띠 밖이라 검사만 하고 버린다.
- ② **줄당 고정 비용이 지배 — 확인.** 기둥 스레드 합 ~180~220 ms ÷ 줄 560만 ≈ **줄당 32~40 ns**. 줄마다 r0 · G·r0 (9 곱) · 상수 브로드캐스트 15 개 · 꼬리 처리. 계산 2500만 개를 레인당 ~1 ns 로 하면 스레드 합 ~25 ms 여야 한다 → 지금의 1/8.
- ③ **부하 불균형 — 있음.** 기둥 B32 는 가장 큰 영역 하나가 15~27 ms 로 벽시계(41~73)의 절반 이상. 이상적 벽시계(스레드 합 / 10 = 20~25 ms)의 2~3 배. B16 이면 영역이 537 개로 늘어 벽 30 ms 로 나아진다.
- 같은 설정에서 스레드 합이 198 ↔ 254 ms 로 흔들린다 — PC 부하가 섞인다. 수치는 ±30%.

**CPU 로 남은 여지 (추정)**
- 뿌리기: 줄 대신 커널 단위 · 영역 단위로 루프를 다시 짜 고정 비용을 걷어내면 스레드 합 ~25~50 ms → 벽 **3~5 ms**.
- 나머지 단계: 이웃 18~24 · 메시 31 · 띠 · 등위값 · 거르기 ~15 ms. 같은 식으로 다듬어도 합쳐서 **15~25 ms 근처가 CPU 하한**으로 보인다.
- 셀 1.25 의 계산량(띠 77만 점 · 계산 2500만)은 예산 기준(20만 셀)의 4 배. **목표 2.5 ms 는 CPU 로 닿지 않는다** — 더 다듬어도 6~10 배가 남는다.

**판단 재료 (사용자 결정)**: ⓐ GPU 메시화 (milestones 실패 분기 — 계산 2500만은 GPU 에서 1 ms 미만) ⓑ CPU 를 하한(~20 ms)까지 다듬고 매 프레임 대신 움직인 영역만 갱신 (잠든 영역 캐시) ⓒ 예산 · 셀 크기 재검토.

## 실행 #9 — 실제 장면 규모 (활성 타일 1~2 채) (2026-10-27)

- **설계 전제와 규모가 맞는다**: 3 천 입자에서 띠 22만 점 · 계산 650만 — 설계의 "20만 셀 · 600만 연산" 그대로. 즉 셀 1.25 를 써도 실제 장면(타일 1 채)은 예산 규모 안이다 (#8 의 "4 배" 는 기둥 2만 기준).

- 60 fps 한 프레임 16.7 ms 보다 길다. 비동기(작업 스레드)로 돌리면 메인 스레드는 안 막지만 메시가 1~2 프레임 늦는다 — 계획 §3 지연 "0 프레임" 과 충돌.

**판단 재료**: 실제 규모에서 CPU 26 ms. #8 의 CPU 하한 추정을 같은 비율로 줄이면 타일 1 채 **~5~8 ms** 까지가 다듬어서 갈 수 있는 곳 (추정). 예산 2.5 ms · 지연 0 을 지키려면 GPU 메시화, 지연 1~2 프레임을 받아들이면 CPU 비동기도 후보.

## 실행 #12 — GPU G1-3 · G1-4 · G1-5: 띠 · 장 · Surface Nets · 시간 · 결정성 → **G1 통과** (2026-10-27)

## 실행 #17 — 가중 라플라시안 평활화 (papers C13) (2026-10-27)

"반죽" 느낌의 남은 원인(입자 크기 혹)을 위해. 규칙 (splashsurf 와 같게, CPU · GPU 동일):
- 입자 wnn_i = Σ(1 − d²/r²), r = r_i 10cm (= splashsurf 의 지지 4R 와 같은 비) → 정점으로 셰퍼드 보간(커널 (1 − d²/r²)³) → x = clamp(wnn/13, 0, 1) → w = smoothstep(x).
- v ← v + w·(mean(이웃) − v), 이웃 = 면을 맞댄 셀 6 개의 정점 (Surface Nets 사각형 모서리와 같은 연결). 야코비(두 버퍼 번갈아). 법선은 평활화 전 장 기울기 그대로.
- CPU `FSandSurfaceParams::SmoothIters · SmoothNorm` · GPU 패스 WnnCS → VertWeightCS → SmoothCS × N → VertFinalCS(화면 버퍼로). 커맨드릿 `-smooth=N`, 화면 `-sandsmooth=N`. 컴포넌트 기본 25.

## 실행 #23 — 활성 영역 슬롯: 띠 · 장 · 셀 정점 메모리 (2026-10-27)

G3 의 고정 영역 격자는 조밀 배열이라 띠 · 장 · 셀 정점 세 버퍼가 격자 전체(부은 3천: 197×197×98 = 380만 점, ≈ 46MB)를 잡았다 — 타일이 여러 개면 감당이 안 된다.
- **슬롯**: 표면 입자 구를 두 번 돈다 — ① 영역(8³) 활성만 표시 → 접두합 → 영역 번호 순으로 슬롯 배정(결정적) → ② 슬롯 안에 띠 점. 점 P 의 자리 = 슬롯 × 512 + 영역 안 색인, 슬롯 없으면 "띠 아님 · 장 −1" (조밀 배열의 기본값과 같은 뜻). 장 · 셀 정점 · 면 · 법선의 모든 접근을 `SlotPt / BandAt / FieldAt` 로.
- 슬롯 용량 = min(전체 영역, max(1024, 입자 × 3/4)) — 활성 영역은 입자 수의 13~31%. 넘치면 그 영역을 버리고 계수(`Counters[5]`).
- 정점의 셀 좌표 부호(VertPt)는 격자 좌표 그대로 (배열 색인 아님).

```
(-gpumesh, 꽉 맞는 격자)   CPU = GPU 정점 · 삼각형 · 부피비 · 지표 전 장면 일치, 2 회 비트 같음. 띠 점 ±1 (줄 구간 반올림, 이전과 같음)
(-meshframe -scene=pour, 고정 영역)  활성 영역 1012~1015 / 슬롯 2466 / 전체 8125 · 넘침 0 · 같은 프레임 3/3 · GPU 시뮬 5.22 + 메시 1.47 ms
```
- 고정 영역에서 띠 · 장 · 셀 정점 메모리 ≈ 50 → 15 MB (3.3 배). 꽉 맞는 격자에선 슬롯 = 전체라 그대로.
- 대가: 접근마다 영역 → 슬롯 한 번 더 — 기둥 3천 메시 단계 0.34 → 0.47 ms. 띠 · 장은 그대로.

## 실행 #28 — 입자별 W (W1 시뮬 버퍼 · W2 정점 색) (2026-10-27)
