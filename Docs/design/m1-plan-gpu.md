# M1 GPU 메시화 계획 — 입자 → 메시를 컴퓨트 셰이더로, 간접 그리기로 화면에

> 2026-10-27. 상위: [milestones.md](milestones.md) M1 실패 분기 (3 단계 경로의 3 단계) · [system-design.md §6-2](system-design.md) · 근거 [papers.md C12 · C14 · C15](../research/papers.md).
> 출발점: [m1-log.md #9](m1-log.md) — 실제 규모(입자 3 천 · 띠 22만 · 계산 650만)에서 CPU 26~28 ms, 예산 2.5 ms 의 10 배. CPU 하한 추정 5~8 ms.
> **CPU 구현(`FSandSurfaceBuilder`)은 지우지 않는다** — GPU 결과를 비교할 정답이자 대조군.

## 0. 범위와 순서

| 단계 | 내용 | 판정 |
|---|---|---|
| **G1** | 메시 생성 컴퓨트 패스 (화면 없이). 결과를 내려받아 CPU 와 비교 | 숫자 — AI |
| **G2** | 화면에 그리기: 커스텀 SceneProxy + VertexFactory + 간접 그리기 | 화면이 뜨는가 · 그림자 — AI 1 차, 사용자 확인 |
| **G3** | 시뮬과 같은 프레임 RDG 로 이어 붙이기 · 지연 0 · 예산 | 숫자 |
| (이후) | 잠든 영역 메시 캐시 · 젖음 W 정점 색 · Lumen/RT 지원 범위 | — |

**G1 이 실패(예산 미달)하면 G2 를 시작하지 않는다** — 그때는 CPU 비동기 · 부분 갱신으로 돌아가 사용자와 다시 정한다.

## 1. G1 — 메시 생성 컴퓨트 패스

### 1-1. 코드 위치

- `Source/SandGpu/` 모듈에 `FSandGpuMesher` (`SandGpuMesher.h/.cpp`) · `Shaders/Private/SandMesh.usf`.
- 기존 SandGpu 의 도우미 재사용: `UploadBuffer` · `ScratchBuffer` · `AddDirectPass` · `AddIndirectPass` · 접두합(`ScanBlocks/Top/Add`) · 정렬.
- 매개변수는 `FSandSurfaceParams` 를 그대로 받는다 (CPU 와 같은 값으로 비교).

### 1-2. 파이프라인 (CPU 단계와 1:1)

```
CPU 단계                         GPU 패스                                              비고
① 이웃 격자 (셀 10cm)            셀 키 → 개수 → 접두합 → 채우기 (counting sort)         시뮬 격자(15cm 블록)는 반경이 달라 따로
   이웃 수 · 치우침 · x̄ · 공분산  입자당 스레드 1: 27 셀 훑기                            C14 SurfDev 0.15 그대로
③ 커널 (고유분해 · G · Ext)       입자당 스레드 1: 3×3 야코비 (CPU 의 Eigen3 그대로)     k_s 자동값 = 내부 σ1 평균 → 병렬 합
   등위값 (내부 φ 평균 × 0.25)    내부 입자 표본에서 φ 모으기 → 병렬 합                  CPU 와 같은 표본 규칙
④ 띠                            표면 입자 → 닿는 **영역(8³ 점)** 에 표시 → 활성 영역 압축  성긴 영역 구조 (C15 Akinci · Wu)
⑤ 장 φ                          활성 영역마다 스레드 그룹 1 (8³ = 512 스레드, 점당 1):    **모으기**: 원자 · 경합 없음, 결과 결정적
                                 영역에 닿는 커널 목록(영역·입자 쌍 정렬)을 그룹 공유      CPU #8 의 "짧은 줄 · 줄당 고정 비용" 이 사라진다
                                 메모리로 나눠 읽고 점마다 합
                                 영역 +1 점 테두리까지 계산 (9³) — 이웃 영역 안 읽게
⑥ Surface Nets                  활성 셀 판정 → 정점 수 접두합 → 정점 · 법선 기록         C15 Dyken 의 압축 + 확장
                                 → 모서리마다 사각형 → 삼각형 수 접두합 → 색인 기록
   간접 인자                     마지막 패스가 {색인 수, 1, 0, 0, 0} 기록                 G2 가 그대로 쓴다
```

- **정점 · 삼각형 순서**: 접두합으로 영역 순서대로 번호를 매긴다 (원자 추가 안 씀) → 결과가 실행마다 같다. 단, CPU 와는 순서가 달라 비교는 지표로 한다.
- **용량**: 활성 영역 · 정점 · 삼각형 최대치를 미리 잡고(입자 수 비례 + 여유), 넘치면 계수만 기록하고 잘라낸다 → 로그에 경고. 시작값: 입자 3 천당 정점 4만 · 삼각형 8만 (#9 의 1.7 배).
- **나눌 수 없는 것**: 등위값이 장 전체 계산 전에 필요 → 등위값 패스가 장 패스보다 먼저 (CPU 와 같음).

### 1-3. 시험 (`-mesh -gpu`)

- 같은 장면 · 같은 입자로 CPU 와 GPU 를 둘 다 돌려 나란히 기록. 장면: slab · wall · debris1/3/7 · column3000 · column6000 · column20000.
- GPU 시간은 M0-b 와 같은 타임스탬프(`RQT_AbsoluteTime`, C11)로 패스별. 내려받기 시간은 따로.
- **GPU 시험 규칙 그대로**: 한 번에 하나 · BelowNormal · 조용한 실행 죽이지 않기.

### 1-4. 통과선

| 항목 | 기준 |
|---|---|
| 판 RMS 비 · 벽 두께비 · 부스러기 구형도 | CPU 값 ± 0.02 (0.60 · 0.91 · 0.98/0.99/0.99) |
| 기둥 부피비 · 정점 수 | CPU 대비 ± 1% |
| 띠 점 · 표면 입자 수 | CPU 와 같음 (± 0.1% — 부동소수 경계) |
| **GPU 시간 (column3000 = 타일 1 채)** | **≤ 2.5 ms** (system-design 예산) |
| GPU 시간 (column20000) | 기록 (참고 — 타일 7 채 분량) |
| 결정성 | 같은 입력 두 번 → 같은 정점 · 삼각형 |

### 1-5. 단계별 구현 순서

대조 방식: **기본은 단계별 핵심값 몇 개만** CPU 와 비교하고, 어긋날 때만 그 단계의 입자별 · 점별 전체 값을 내려받아 비교한다 (`-meshdiff`). GPU 버그는 조용히 틀린 값을 내고, 최종 지표만으론 어느 단계인지 모르며 통과선 안에 숨을 수 있어서다.

```
단계   내용                                        핵심값 (기본 대조)
G1-1  이웃 격자 · 이웃 수 · 치우침 · 공분산          이웃 수 합 · 표면 입자 수 · 치우침 평균 · 공분산 대각 평균
G1-2  커널 · k_s · 등위값                            k_s · 내부 φ · Iso
G1-3  활성 영역 · 장 φ (모으기)                      띠 점 수 · φ 합 · 부호 양수 점 수
G1-4  Surface Nets · 간접 인자                       §1-4 지표 (정점 · 삼각형 수 · 부피 · 판 · 벽 · 부스러기)
G1-5  시간 측정 · 용량 · 결정성                      m1-log 기록, 통과 여부
```

## 2. G2 — 화면에 그리기 (엔진 견본: VirtualHeightfieldMesh · Niagara 리본, C15)

- `USandSurfaceComponent` (UPrimitiveComponent) + `FSandSurfaceSceneProxy` + `FSandSurfaceVertexFactory`.
- 정점 버퍼(위치 · 법선 [· W]) · 색인 버퍼 · 간접 인자 버퍼를 G1 이 쓴다. 프록시는 `FMeshBatchElement::IndirectArgsBuffer` 를 걸고 `NumPrimitives = 0` 으로 그린다.
- VertexFactory 는 엔진 `FLocalVertexFactory` 를 먼저 시도 (위치 · 탄젠트 SRV 를 우리 버퍼로) — 안 되면 VirtualHeightfieldMesh 식 커스텀 VF.
- 경계 상자: 입자 AABB + 커널 지지 (CPU 가 알고 있음 — 시뮬 영역).
- **통과**: 에디터 뷰포트에 기둥 메시가 뜬다 · 그림자를 드리운다 · 기본 머티리얼 적용 · CPU 메시(OBJ)와 겹쳐 보면 같다. 사용자 확인 (모양).
- 범위 밖으로 미룸: Lumen 표면 캐시 · 하드웨어 레이트레이싱 (Niagara 리본의 RT 별도 경로 참고) — 필요해지면.

## 3. G3 — 시뮬과 이어 붙이기

- 시뮬 마지막 패스 다음, 같은 `FRDGBuilder` 에서 메시 패스 → 같은 프레임 렌더에서 그린다 → **지연 0 프레임** (m1-plan §3).
- 입자 위치 버퍼를 복사 없이 SRV 로 (시뮬 버퍼 형식 그대로 읽게 셰이더 작성).
- **통과**: 시뮬 + 메시 GPU 시간 측정 (`-perf -stages` 에 메시 단계 추가), 입자 이동 → 같은 프레임 반영 확인.

## 4. 위험과 대응

| 위험 | 대응 |
|---|---|
| 그룹 공유 메모리에 커널 목록이 다 안 들어감 (조밀한 영역) | 목록을 조각으로 나눠 반복 로드 |
| 활성 영역 불균형 (#8 ③ 의 GPU 판) | 영역당 그룹 1 이라 GPU 는 그룹 수가 많아 자연 분산 — 측정으로 확인 |
| 용량 초과 | 계수 기록 · 경고 · 다음 프레임 용량 늘림 |
| TDR | 패스를 작게 · 디버그는 작은 장면부터 · GPU 시험 규칙 |
| VertexFactory 셰이더 바인딩 | LocalVF 먼저, 막히면 VirtualHeightfieldMesh 코드를 따라간다 |

## 근거가 약한 부분 (명시)

- GPU 재구성 논문의 구체 ms 를 원문에서 확보 못 했다 (C15) — 2.5 ms 가능성은 계산량(650만 커널 평가 · 띠 22만 점)에서 추정한 것.
- 영역 8³ · 모으기 방식은 GPU 일반 관행에서 고른 시작값 — G1-3 에서 4³/8³ · 뿌리기(공유 메모리 누적) 와 비교해 정한다.
- LocalVertexFactory 로 간접 그리기가 되는지는 미확인 — G2 첫 실험.
