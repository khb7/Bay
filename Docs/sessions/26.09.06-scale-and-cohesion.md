# 해상도와 점착 세션 — 위험 방향이 반대였다

> 2026-09-06, 한 세션. 코드는 한 줄도 안 고쳤다. **문헌과 실험 설계만 바뀌었다.**
> 결과는 [papers.md §B-S·B2·B3](../research/papers.md), 절차 변경은 [m0-spike.md](../design/m0-spike.md).
>
> 이 문서는 **세션이 어떤 모양으로 흘렀는가** — 하나의 질문이 어디까지 번졌는가를 담는다.

---

## 한 줄 요약

**"지름 5cm 입자로 30cm 터널이 서는가"를 물었더니, 그 질문이 두 개였고 위험 방향이 반대였다.**

```
문서에 적혀 있던 위험    터널이 안 선다  →  해상도를 낮춘다  →  성 15채가 1.9채로
실제로 큰 위험          터널이 무조건 선다  →  ★덩어리 붕괴가 안 나온다  →  하이트필드와 같아진다
```

M0 의 진짜 차단이 **3-1(터널)에서 3-2(덩어리 붕괴)로 옮겨갔다.**

---

## 1. 질문이 두 개였다

`milestones.md` 불확실 표의 첫 줄은 두 질문이 붙어 있었고, **위험은 두 번째에만 있었다.**

| | 질문 | 상태 |
|---|---|---|
| Q1 | **실물** 젖은 모래에서 30cm 터널이 서는가 | **손계산으로 끝.** `σ = γL²/2t ≈ 2.4 kPa` vs 문헌 0.5~3 kPa |
| Q2 | **6입자 폭**으로 그 결과를 재현하는가 | ★ 진짜 미검증 |

Q1 이 코드 없이 답이 나온다는 것 자체가 소득이었다 — **사각은 아슬아슬, 아치는 여유**가
물리적으로 예상되는 답이고, 그건 `m0-spike.md` 의 실패 분기가 이미 적어둔 것과 같다.
**시뮬이 사각을 여유롭게 통과시키면 통과가 아니라 의심할 신호다.**

## 2. 그리고 오차 방향이 한쪽으로만 생긴다

D/d = 30/5 = **6**. 이 숫자가 세 군데서 걸렸고 **전부 같은 방향**이었다.

```
사일로 막힘 (Zuriguel 2005)   배출구/입자 비 5 부근에서 막힘 확률 발산
                              → 점착 0 이어도 6입자 폭 구멍은 기하학적으로 막힌다

전단대 두께 (Mühlhaus 1987)   8~16 입경 = 40~80cm  >  터널 지름 30cm
                              → 붕괴 메커니즘이 격자에 안 들어간다

breakStretch = 1.3 (Lian 1993) V* ≈ 0.2 = "물이 꽤 많은 상태"의 값
                              → 마른 쪽에서 결합이 물리보다 오래 버틴다
```

**셋 다 과대 안정.** 그래서 "터널이 쉽게 통과하는 것"이 좋은 소식이 아니게 됐다.

→ 3-1 에 **무점착 대조군**(`W=0` 에서 같은 터널은 무너져야 한다)을 넣고,
이진 판정을 **`D_crit(d)` 스윕**으로 바꿨다. 두 해상도에서 `D_crit` 이 cm 로 수렴하면 물리,
입자 수로 고정되면 해상도가 답을 정한 것이다.

## 3. 모든 실타래가 같은 곳으로 모였다

문헌을 다섯 갈래로 팠는데 **전부 같은 결론에서 멈췄다.**

```
Rumpf 를 쓰려면        →  거시 σ_t 를 알아야 한다   →  c[Pa]
Radjaï 2009 를 쓰려면  →  c 를 알아야 비교된다      →  c[Pa]
터널 실패를 해석하려면  →  점착 부족인지 해상도인지  →  c[Pa]
breakStretch 를 정하려면 →  결과 강도를 봐야 한다     →  c[Pa]
```

**자가 없으면 어떤 문헌도 못 쓴다.** 마찰에는 34°라는 자가 있는데 점착에는 없었다.

이건 [전날 M0-a 세션의 교훈](26.09.05-m0a-implementation.md)("물리보다 측정이 어려웠다")이
**문헌 층위에서 그대로 반복된 것**이다. 그때는 각도를 못 쟀고, 이번엔 강도를 못 잰다.

## 4. ★정정 셋 — 전부 이 세션 안에서 뒤집혔다

**① Rumpf 계수를 틀렸다**
```
처음   F = σ_t·πd²·8/(9(1-ε)) ≈ 17 N   →  자기 무게의 10배
정정   F = σ_t·d²·ε/(1-ε)    ≈ 2.5 N   →  자기 무게의 1.5배
```
Lian 1993 의 실제 모세관력(11.4 mN)과 대조하다 드러났다 — 두 경로가 220배와 1500배로
안 맞았고, 계수가 7배 틀린 것이었다. **교차 검산이 아니었으면 그대로 갔다.**

**② `c[Pa]` 측정 방법을 틀렸다**
```
처음   3-3 얇은 벽 두께 스윕에서 H_c 역산
정정   자립 박벽은 좌굴·전도로 무너진다 (= Pakpour 의 h ∝ R^(2/3))
       → 절토면 파괴와 다른 모드. 3-3-B 로 배치를 따로 뗐다
```
**같은 "무너진다"라도 모드가 다르면 다른 값을 재는 것이다.** 26.09.05 세션의
"기둥 붕괴는 안식각 측정법이 아니다"와 정확히 같은 종류의 실수.

**③ "재결합 없음"이 오해를 부르는 표현이었다**
```
읽히는 뜻   다시는 안 붙는다
실제 규칙   붙기 검사를 매 프레임 안 돌린다 (도구 조작 시에만)
```
질문을 받고서야 드러났다 — **손으로 밀면 붙는 게 맞고, 설계상 붙는다.**
금지되는 건 아무도 안 건드렸는데 시뮬이 스스로 되붙이는 것뿐.

## 5. 코드를 보고 알게 된 것 둘

**① 점착이 아직 구현돼 있지 않다**
```
SandSpike.h:59   float WGlobal = 0.f;   // 필드만 있다. 솔버가 읽는 곳이 없다
```
그래서 `c[Pa]` 측정은 **3-0 과 병렬로 못 돌린다.** 일정 문제가 아니라 구현 선행이다.

**② 경사판 벽 조건이 문서와 코드에서 반대다** ← ⚠ 미해결
```
m0-spike 3-0-B    "벽 네 면 다 막음"
SpikeBatch.h      bOpenDownhill = true   (기본값 열림)
```
[m0-log 실행 #15](../design/m0-log.md) 를 보면 **둘 다 실패했던 조합**이고,
어느 쪽이 현재 설정인지 판단할 근거가 문서에 없다.
**이걸 정하기 전에는 `θ_m0` 기준선이 의미가 없다.**

### 실행 순서가 바뀌었다

```
이전   3-0 → 3-1(터널) → 3-2 → 3-3(벽)
```
