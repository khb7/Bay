## 출발점

조사 문서(research/) 4종을 앞에 두고, 첫 질문은 이것이었다.

> "어떤 객체들을 만들면 될지 설계를 짜보려고 해. 뭐 바람, 물, 해, 온도, 수면,
> 이런식으로 정하면 되려나?"

**첫 결론: 그 분해는 위험하다.**

조사 문서의 핵심이 "모든 것을 수분량 `W` 하나가 구동한다"인데, 바람·햇빛·온도는 각자
상태를 가진 액터가 아니라 **`W`의 증발 항에 들어가는 스칼라 계수**이고, 수면·물깊이·유량·탁도는
**같은 격자 텍스처의 채널들**이다. 각각을 액터로 쪼개면 매 프레임 서로를 참조하며
갱신 순서 지옥이 된다 — 문서의 패스 순서 7단계가 이미 단일 소유자를 전제로 쓰여 있다.

> **분해의 축은 자연 명사가 아니라 데이터 소유권 + 갱신 주기여야 한다.**

최종 설계에서 **바람·태양·조석·파도·지하수면은 하나도 객체가 되지 않았다.**
각각 float 하나, 벡터 하나, 셰이더 함수 한 줄로 내려앉았다.

## 결정 흐름

### 1. 장르 — 샌드박스

조사 문서의 미결 첫 줄이 "게임플레이가 무엇인가 — 이게 정해져야 나머지가 결정된다"였다.
샌드박스(a) / 유지 방어(b) / 목표 건축(c) 중 **샌드박스**.

→ 목표·점수·판정 객체가 전부 빠지고, **관찰 가능성**이 1급 요구사항이 되었다.

### 2. 터널·아치·덩어리 붕괴는 타협 불가

가장 큰 분기였다. 하이트필드만(가) / 하이브리드(나) / 나중에 얹기(다).

내 추천은 (다)였다 — 젖은 모래의 특유한 거동은 전부 `W`와 열침식에서 나오고
오버행에서 나오지 않으니, 고유한 재미는 (가) 범위 안에 이미 다 있다는 논지였다.

> "무조건 터널, 아치, 덩어리 붕괴가 되야 해. 위에서부터만 쓰러지면 이 게임의 의미가 없어"

→ **(나) 확정.** 설계 중심이 "격자↔입자 전환 브로커"로 옮겨갔고, 프로젝트 규모가 두 배가 됐다.
이후 모든 판단의 기준선이 이 한 줄이 된다 (쇄파 튜브를 포기한 근거도 여기서 나온다).

### 3. 스케일 — 실물 크기

성 2~3m, 터널 지름 25~40cm, 입자 지름 5cm, 자유 카메라.
입자 예산 계산이 여유롭다는 것을 확인 → **속까지 꽉 채워도 되고, 그래서 터널이 진짜가 된다.**

### 4. 확장성 — 입자는 "플레이어가 만든 것"만

> "나중에 모래사장 크기를 더 키운다던가... 파도가 더 안 치는 뒤에서 한다던가"

핵심 원칙이 여기서 나왔다.

```
입자는 플레이어가 만든 구조물만. 자연 지형은 전부 격자.
→ 해변 크기와 입자 예산이 완전히 분리된다
```

그리고 "뒤에서 짓기"는 이미 시스템에 내재된 선택지였다 — 지하수면 모델이 자동으로
"앞은 물이 공짜지만 파도가 먹고, 뒤는 안전하지만 물을 노동으로 조달해야 하고 게다가 마른다"를 만든다.

### 5. 누적 + 60m

성이 여러 채 남아 각자 마르고 무너진다. 30분 전에 지은 성을 보러 가는 것 자체가 콘텐츠.
→ 조석 주기가 자동으로 확정됐다(변화의 엔진이 필요하므로).

### 6. 도구 11종 + 연속 브러시

처음 7종으로 시작 → 물 붓기 논의 중 **분무** 추가 → 실제 모래 조각 도구 조사 후
**형틀 · 절단 · 불기 · 고정** 추가.

### 7. 기술 — 접근 3 (분업)

| 안 | 판정 |
|---|---|
| Niagara 올인 | **기각.** 상태가 리컴파일·스트리밍·컬링에서 날아감 → 누적 요구사항과 충돌. 중단점 없음 |
| 커스텀 컴퓨트 올인 | 기각. 첫 화면까지 RDG를 먼저 넘어야 함 |
| **분업** | **채택.** 격자는 휘발성이어도 되고 빨라야, 구조물은 영속적이고 정밀해야 한다 |

> 요구사항이 두 계층에 정반대 성질을 요구한다. 하나의 도구로 둘 다 하면 어느 쪽이든 손해다.

## ★ 도중에 뒤집은 것들

이 세션의 실질이 여기에 있다. 순서대로.

### 파도 세트 — 변조항 → 이봉 스펙트럼

내가 `SetPeriod`/`SetStrength` 저주파 변조항으로 "가끔 큰 파도"를 만들자고 제안했다.
그 직후 사용자가 params.md에 파랑 기후 프리셋 5종을 추가했다고 알려왔고, papers G-6b/6c를
읽고 **철회**했다.

```
세트는 만드는 게 아니라 주파수가 다른 성분들의 맥놀이에서 저절로 나온다.
문서: "랜덤을 만들 필요가 없다", "이벤트를 짤 필요가 없다"
```

`gamma`는 지역 상수가 아니고 너울은 JONSWAP으로 표현되지 않는다 → **이봉 스펙트럼**,
지역 파라미터는 `swellFraction`과 `swellTp` 둘뿐. 내 변조항은 물리를 흉내낸 가짜였다.

부수 소득: **2m 풍파보다 1m 너울이 두 배 멀리 온다**는 함정이 그대로 게임 메커니즘이 됐다.
파고가 아니라 주기를 읽어야 하는 게임.

### 자연화 — 기본 적용 → 선택 도구

손으로 그린 지형의 안식각 초과와 계단 자국을 미리 완화하자고 제안했다.

> "안식각 초과의 경우 시작하자마자 무너지는게 오히려 샌드박스에 맞다고 생각해.
> 계단 자국도 일부로 그렇게 만들어놓은게 시간에 따라 옅어지는걸 보는게 재미에 맞고."

→ **기본에서 뺐다.** 시작 전에 물리를 미리 적용하면 가장 볼만한 첫 30초를 빼앗는 것이다.
따라오는 정정: `bFollowEquilibrium` 토글 삭제, 경고 UI 삭제, Dean 평형식은 초기값 생성기로 격하,
**편집 모드와 플레이 모드의 구분이 사실상 사라짐**(편집 = 시간이 멈춘 플레이).

### 웅덩이 — 문제 → 기능, 그리고 우물

"물이 갇히는 웅덩이"를 자연화가 고쳐야 할 문제로 적었다. 부정확했다.
웅덩이는 하이트필드가 그냥 처리하고, **오히려 기능**이다 — 해자, 조수 웅덩이, 그리고

```
구덩이를 파서 지하수면 아래로 내려가면 물이 차오른다  ← 이미 있는 네 줄에서 나온다
```

**뒤쪽에서 성을 짓는 물 조달 문제가 지형으로 풀린다.** 뒤로 갈수록 깊이 파야 하고,
조석이 빠지면 우물도 마른다. 설계로 넣은 게 아니라 있던 물리에서 나온 트레이드오프.

### swash mark — 마크 기록 → 부유물 추적

"물이 도달하면 1.0 기록하고 감쇠"를 제안했다. **전형적인 연출이었고 원칙 위반이었다.**

물리적으로 swash mark는 거품·조개 부스러기가 걸러져 남은 것이다. `debris`를 실제 물질로
추적하면 — 물에 실려 이동하고, 침강 속도가 거의 0이라 물이 빠지면 표면에 남는다.

| | 마크 방식 (기각) | 부유물 방식 |
|---|---|---|
| 겹친 아치 | 감쇠로 흉내 | **저절로** |
| 지워짐 | 타이머 | **다음 파도가 실어감** |
| 성 주변 | 없음 | **성에 걸려 쌓임** ← 예상 못 한 것까지 |

### ripple / rill — 셰이더 → 시뮬 재검토

"셀보다 작으니 셰이더로"라고 판단했다. 그때 사용자가 프로젝트 정체성을 명확히 했다.

> "시뮬레이션처럼 해서 의도하지 않아도 실제와 비슷한 모습들이 최대한 나오게 하려는게 목표야.
> 최적화때문에 구현을 못하는게 아니라면 최대한 시뮬로 해결을 해보고 싶어"

→ **원칙 §0으로 명문화**하고 재검토했다.

- **ripple**: "모델에 없다"는 맞지만 "추가할 수 없다"는 아니었다. Nishimori & Ouchi 사구 모델은
  두 단계뿐이고 **우리는 이미 둘 다 갖고 있다**(saltation ≈ 이류, avalanche ≈ 열침식).
  빠진 건 **높이 의존성** 하나 — 코드 두 줄. 파장은 24~35cm로 커지지만 그건 메가리플이라는 실재 현상
- **rill**: 해상도만 보고 성급했다. 수력 침식이 만들 수 있는 종류이고, 우리는 seepage face까지 있다

셰이더가 정당한 것은 **시뮬 대상이 아닌 것들**뿐이다 — 알갱이 질감(0.5mm), 광학, 포말.

### 동결(Frozen) 상태 — 도입 → 제거

입자를 해제하고 정적 메시로 굽는 상태를 설계했다가, 계산해보니 **잠듦만으로 이미 시뮬 비용이 0**이라
동결이 추가로 주는 건 입자당 76바이트(성 10채 ≈ 2.3MB)뿐이었다.

그 2MB를 위해 메시화·복원 파이프라인·상태 전이를 하나 더 만들고, 복원 시 점착 목록 재구성이
"재결합 없음" 원칙과 부딪히는 문제까지 떠안을 이유가 없다. → **1차 범위에서 제외.**

### 고정 스프레이 — 동결 트리거 → 물리 효과

동결과 고정을 하나로 묶어서 혼란을 만들었다. **층이 다르다.**

```
동결        자원 관리. 시스템이 판단. 플레이어가 인식 안 함     → 제거됨
고정 스프레이  물리. cohesion을 W와 무관하게 유지. 파도가 막을 벗김 → 남음
```

분리하고 나니 **"파도가 껍질을 벗김 → 속은 이미 마름 → 즉시 와르르"** 라는 결과가 나왔다.
연출이 아니라 두 규칙이 만나서 나온 것.

### 장애물 마스크 — 빠뜨린 것

"파도가 칠 때마다 하이트필드가 변하나"라는 질문에 답하다가 발견했다.
**격자 물 흐름은 `b`만 보는데 성은 입자라 격자에 없다 → 물이 성을 통과해 지나간다.**

`FFieldBridge`에 항목을 추가하고, 만드는 방법(z축 비트마스크 + 바닥부터 연속 높이)까지 정했다.
넣으니 **세굴이 자동으로 나왔다** — 파도가 성을 직접 부수는 것 말고 발밑을 파내 쓰러뜨리는
두 번째 경로.

### 그 밖의 정정

| 항목 | 처음 | 고침 |
|---|---|---|
| 커서 위치 | `SampleAsync`로 격자 조회 | **깊이 버퍼 픽킹** (지형·입자·물을 구분할 필요조차 없음) |
| 도구 적용 | 리드백으로 높이를 알아야 | 불필요. 브러시는 좌표만 넘기고 GPU가 자기 셀에서 판단 |
| VHM | 대안으로 검토 | **불필요.** RVT는 캐시 기반이고 우리 지형은 매 프레임 바뀐다 |
| 입자 상태 | 36바이트 | **40바이트.** `surfaceWater` 누락(흘러내림을 확정해놓고 안 넣었음) |
| 점착 결합 | 언급 없음 | **별도 버퍼 9.6MB.** 입자 상태보다 크다 |
| 격자 해상도 | 512² 기본 | **1024².** 셀 5.9cm ≈ 입자 지름 → 전환 손실이 사라짐 |

## 기각하고 남긴 근거

| 기각한 것 | 근거 |
|---|---|
| **성 단위 소유권** | "3m 떨어지면 별개인가? 이으면 합쳐지나?" 전부 임의 임계값이고 매 프레임 연결 요소 분석이 필요. **4m 공간 타일**로 바꾸니 질문 자체가 사라짐 |
| **Niagara `Neighbor Grid3D`** | `MaxNeighborsPerCell` 초과가 조용히 잘림(모래는 최밀 충전) + 균일 격자라 빈 공간이 33MB. **정렬 기반 공간 해시**는 5MB에 오버플로 없음 |
| **화면공간 유체 렌더링** | **그림자를 못 드리움** → 증발 메커니즘이 죽음. 정지 상태가 많은 우리 구조에서 최대 장점도 무의미. 두께 기반 투과는 불투명한 모래에 쓸 데 없음 |
| **쇄파 튜브** | 3D 물 시뮬 = 290만~2300만 입자(모래성의 10배 이상) + 이동하는 경계 처리. 우리 파고에선 애초에 드묾. **터널은 핵심 요구사항이라 비용을 지불했고, 튜브는 장식이라 지불하지 않는다** |
| **온도** | 증발률은 즉석 계산으로 충분. 상태로 둬야 하는 건 열관성이 필요할 때뿐인데 붕괴를 지배하는 건 `W`다 |

## 설계하지 않았는데 나오는 것들

의도해서 넣은 게 아니라 규칙들이 만나서 나오는 결과. **원칙 §0이 실제로 작동한 증거.**

| 현상 | 어디서 나오나 |
|---|---|
| **해자** | 쌓기가 근처 지면에서 모래를 퍼오므로 주변이 파인다 |
| **덩어리 붕괴** | 점착 끊김의 연쇄 (한 층이 끊기면 하중이 아래로 몰림) |
| **세굴로 성이 주저앉음** | 장애물 마스크 → 유속 증가 → 침식 ∝\|v\|³ → 지지 상실 |
| **성이 자기 그림자로 발밑을 지킴** | 그림자 마스크 → 증발률 감소 |
| **부유물이 성 앞에 띠로 쌓임** | `debris`가 실제 물질이라 성에 걸린다 |
| **물 부은 직후가 가장 약함** | 과포화 → 배수 → `fieldCapacity` = 최적 강도 |
| **마른 모래엔 구덩이가 안 파임** | `talusDry` 34° vs `talusWet` 90° |
| **우물** | `depthToWater`가 음수가 되면 물이 차오른다 |
| **틀 안에서 다지면 더 단단** | 원통 제약이 옆을 막아 힘이 아래로 간다 |
| **틀 빼는 순간의 성패 판정** | `cohesion(W)`과 `μ(φ)`가 이미 답을 갖고 있다 |
| **고정한 성이 파도 한 방에 통째로** | 막 벗겨짐 + 마른 모래의 급격한 붕괴 |
| **양지쪽 벽이 먼저 무너짐** | 증발률의 `dot(n, sunDir)` 의존 |
